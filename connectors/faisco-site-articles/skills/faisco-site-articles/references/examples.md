# 典型使用场景

## 查询文章

客户：“查找标题中包含新品的文章。”

调用 `getNewsInfo`，参数如下：

```json
{"title": "新品"}
```

根据实际结果展示匹配文章；没有记录就说明没有匹配，不提供示例文章冒充结果。

## 查询分类

客户：“查看当前网站的文章分类。”

调用 `getNewsGroupList`，参数如下：

```json
{}
```

展示实际分类名称与 ID。未分类包含在接口能力范围内，其 ID 为 `0`。

## 准备新增文章

客户：“把这段介绍整理成网站文章，先给我看一下。”

先返回文章草稿，不调用 `addNews`。客户要求新增后，根据 @references/api-spec.md 核对全部字段及必要业务规则；分类通过查询匹配，提交最终确认的内容。

客户已提供最终内容、有效参数及明确新增指令时，无需重复征求相同授权。客户没有提供封面、自定义地址等当前必填信息时，只问缺少的部分，不编造内容补位。

## 修改指定文章的发布时间

客户：“把新品介绍的发布时间改成指定时间。”

先按标题查询，核对目标文章 ID。若出现多篇同名文章，让客户选择。确认目标、日期和接口所需格式后，调用 `updateNewsDate`，其中 `newsId` 使用实际整数 ID，`date` 使用依据正式规则确定的字符串。

本参考不提供可直接写入的示例 ID 或猜测日期格式。写入结果依据实际工具响应报告；不能将调整日期描述为已经完成定时发布设置。

## 新增调用超时

先查询标题并核对内容及其他可用信息，或请客户在后台检查。状态未确定前不重复新增；同名结果不足以证明首次请求成功。
