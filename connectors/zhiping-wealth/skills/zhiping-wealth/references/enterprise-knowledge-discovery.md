# 实时知识发现

## 原则

完整业务知识和数据库结构保存在 MCP 服务端。本 Skill 只保存查找路径，避免把表、字段、确认项和规则复制到 Host 后产生版本漂移。`0、治理总控/基础常识定期更新文档.md` 是现行基础常识与动态事实台账，已纳入默认知识检索；不要把其中的数字复制到 Skill。

## 选择入口

| 需要回答的问题 | MCP 入口 | 预期结果 |
|---|---|---|
| 当前支持哪些业务主题、字段、筛选和指标 | `zhiping_describe_data_contract` | 实时主题状态、工具、字段别名、枚举和指标键 |
| 某业务口径、基础常识、数据来源或导出规范是什么 | `zhiping_search_business_knowledge(query=..., source_scope="current")` | 默认检索现行 Markdown 文档（含基础常识定期更新文档），返回来源路径和行号；可按 `passage_id` 取完整片段 |
| 某张表有哪些字段 | `zhiping_describe_database(table=...)` | 表说明、字段类型、中文标签、备注和来源路径；字段多时按 `next_offset` 续页 |
| 某中文或英文字段出现在哪些表 | `zhiping_describe_database(field=...)` | 有界的跨表字段匹配；按需续页 |
| 不清楚表名，只有中英文表名片段 | `zhiping_describe_database(table_query=...)` | 表名候选、字段数及来源路径 |
| 数据库当前解析出多少张表 | `zhiping_describe_database()` | 仅返回表数量和检索提示 |

## 查找顺序

1. 首轮业务工具选择先按 Skill 正文的企业能力边界表；已知主题及参数时直接调用实际可见工具，不例行遍历数据契约、知识或表目录。
2. 用户只问可用业务能力，或字段/指标无法判定：按目标 `topic` 查数据契约，不需要列全库表或默认请求 `topic=all`。
3. 用户问业务口径、基础常识、数据来源或导出规范：用具体业务短语检索现行知识；涉及理财公司数量等动态事实时，读取基础常识定期更新文档的对应片段，并核对其数据截至日期。只有用户明确问历史变更、审计或脚本实现时才传 `source_scope="all"`。历史片段不得覆盖现行工具契约。
4. 用户给出明确表名或字段：直接调用数据库描述，不先加载完整目录。需要更多结果时使用 `next_offset`，不要重复取首页。
5. 构造查询时以数据契约中的参数字段为准；物理表存在不代表 MCP 已开放查询能力。
6. 知识库描述了数据但数据契约标记为 `not_implemented` 时，如实说明当前 MCP 尚不能执行，不能生成 SQL 或调用本地脚本补齐。

数据库总览中的“约 229 张表”属于业务字典口径；当前 SQLite 从现有解析目录导入 214 张表、5891 个字段。两者不可混写为同一实测统计；本次没有核验差异原因。

## 回答数据库结构问题

区分三层信息：

- 业务概念：来自业务知识检索。
- 物理结构：来自数据库描述工具。
- 当前可执行能力：来自数据契约和实时工具 Schema。

回答时说明依据属于哪一层。不要因为字典中存在表或字段，就声称当前 MCP 可以查询或导出它。
