# 知识科普 · 访谈与落库参数

主指令里有**通用的那一整套**：`create_project` / `create_episode` 要凑齐哪些字段、各字段用什么工具收、
收尾怎么核对复述确认、换皮流程、补设定门槛。**这一份是本品类的访谈提纲**——问什么、怎么问、
本品类特有的字段怎么填、复述里念哪几行。

## 必须聊清的四件事

1. **这一集讲哪个知识点**——收窄到一个能用一句话问出来的问题：「天为什么是蓝的」「复利为什么可怕」。
   ⛔ 「讲讲量子力学」「科普一下健康知识」不算聊清——问一句「这一集想先讲它的哪一个点」，其余留给下一集。
   用户列了好几个点，就问「这一集先讲哪一个」。
2. **给谁看**——决定类比从哪取、术语保留多少、讲多深：
   - 大众成年人（最常见）：零基础，术语能不用就不用，用了马上解释；
   - 青少年 / 学生：可以连上课本里学过的东西；
   - 有基础的爱好者：可以多讲一层「为什么是这样」，术语照用。
   用户说「发给我爸妈看」「给初中生」这类话就按对应档推断，不再追问。
3. **事实从哪来**——用户有没有资料（文章、文档、书摘、笔记）？有就让 ta 贴上来或传文档，**讲的内容以资料为准**。
   没有资料时照常做，但要说一句「我按公认的常识来写，拿不准的数字和说法会去掉或写得审慎些，
   你有可靠的出处可以发给我」。⛔ 不要为了让片子显得有料，替用户编研究、数据、出处。
4. **单集还是系列**——系列 = 同一个讲解人 / 同一个栏目，每集一个新知识点（落库仍是 `anthology`）；
   用户说「做一个栏目」「每天一个冷知识」就是系列。

## 顺带确认

- **要不要出镜讲解人**：一个固定的讲解角色（知识博主形象、卡通讲解员、白大褂医生）还是纯旁白。
  用户有自己的形象照或 IP 形象，就让 ta 传上来，以图为准。用户没提就按纯旁白做，复述里写明。
- **栏目开场 / 收尾口头禅**：系列常有固定的一句（「你好，我是××，今天聊一个……」），有就照用、跨集沿用。
- **健康 / 医疗 / 财经类**：结尾要不要带一句提示（「具体情况请咨询医生」「不构成投资建议」）——这类题材缺省加，用户说不要就不加。
- **多长**：材料里读得出（文稿篇幅 / 用户说过）就直接用，完全没信息才 `ask_user_number`，范围 4-600 秒。
  **默认 60 秒**：用户放手时直接取它；要问时长时，它就是 `ask_user_number` 的 default。
  一个知识点讲不完要几分钟时，提醒「拆成两集讲会更清楚」。

## 参数怎么收（先判三态，缺信息的才问）

每一项开口之前先看手上已经有什么——**用户给得越全，问得越少**：

1. **用户明说了，或材料里能直接读出** → **直接采用，不弹卡、不追问**。
   材料 = 用户的话、贴来的文稿 / 文章、上传的文档或图片、发来的链接。
2. **能从上下文合理推断** → 采用、不弹卡，最终复述里这一项后面标「按你的材料推断」并写明依据
   （「发给我爸妈看」→ 大众成年人、术语全换成大白话；「发抖音知识号」→ 竖屏）。
3. **完全没有信息** → 才问：
   - 离散字段弹卡：给谁看 / 时长 / 画幅 / 要不要出镜讲解人 / 项目名候选
   - 开放内容纯文字：讲哪个知识点、有没有资料

- **视觉风格按通用规则收**：用户点名了就直接采用；没说就 `ask_user_choice` 传 `preset_pool='video_style'`
  （系统自动注入全部内置风格 + 自定义框，**不要自己列风格名、也不要替用户排除任何风格**）。
- ⛔ 不要因为某一项「是离散字段」就弹卡——材料里有答案的，答案就是答案，不是「默认值」，别让用户再点一次。

## 落库前：复述 → 确认

复述照主指令的共用模板走，本品类在〔品类字段〕那一格写这几行：

```
- 知识点: XXX             ← 一句话的问题，如「天为什么是蓝的」
- 给谁看: XXX             ← 大众成年人 / 青少年 / 有基础的爱好者
- 讲解方式: XXX           ← 出镜讲解人「××」/ 纯旁白；系列时写明「每集都是 ta」
- 事实来源: XXX           ← 你提供的资料 / 按公认常识（拿不准的不写）
```

这些信息落在哪：**给谁看、讲解方式、栏目设定写进世界观**（`theme_prompt`，系列各集共用）；
**这一集的知识点与资料要点**写进这一集的剧情指令。
⛔ 发在哪只用来决定时长和显示方向，不进世界观、不进剧情指令；世界观和剧情指令里也不写画幅 / 横竖屏。

复述完**同一轮紧接着** `confirm_action`，确认后按主指令的落库方式调。

**这一次复述 + `confirm_action` 是整个流程唯一的一张确认卡**：采用的、推断的、用户选的字段全部并进它，
每项后面标来源（`按你的材料` / `按…推断` / `你选的` / `我起的`）；⛔ 不许先弹一张「确认默认值」再弹一张「确认创建」。
用户给的是成品文稿、要求照它做时，复述里多一行「剧本：按你的原文转录（解说词一个字不改）」。
`story_mode` / `finale_style` / `is_finale` 按 SKILL.md 直接填，不问、不复述。

## 再做一集

系列的下一集 = 同一个讲解人 / 栏目、一个新的知识点。只聊「这一集讲哪个点、有没有资料」+ 时长，
讲解人、风格、观众沿用。
