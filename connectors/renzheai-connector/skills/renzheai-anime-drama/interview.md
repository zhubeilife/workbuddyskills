# 漫剧 · 访谈与落库参数

主指令里有**通用的那一整套**：`create_project` / `create_episode` 要凑齐哪些字段、各字段用什么工具收、
收尾怎么核对复述确认、换皮流程、补设定门槛。**这一份是本品类的访谈提纲**——问什么、怎么问、
本品类特有的字段怎么填、复述里念哪几行。

## 必须聊清的四件事

1. **讲什么故事**——题材（重生 / 穿越 / 修仙 / 系统 / 霸总 / 甜宠 / 逆袭……）+ 主角是谁、要爽在哪。
   用户甩来一段小说原文，故事就定了，不用再问；只确认一句「照原文改编（保留关键台词与情节），还是一个字不改照原文来」。
   用户没说时按「照原文改编」走——小说是写给人读的，直接搬进视频多半太长、太散。
2. **谁来讲**——漫剧大多靠旁白带着走：
   - 第一人称旁白（「我重生回到了十八岁那年」）——主角自己讲，最常见；
   - 第三人称旁白（「这一年，林家大小姐被退了婚」）——说书人讲；
   - 旁白很少、主要靠对白。
   原文是第一人称就用第一人称，是第三人称就用第三人称，不用问；材料完全看不出来才问一句。
3. **这一集讲到哪**——原文很长时，问「这一集讲到哪一段为止」，或者由你按时长切、在复述里写明切在哪。
   每一集要停在一个钩子上（一句狠话、一个身份即将揭晓、一个危机刚冒头）。
4. **结局风格与大结局**——照下方「结局风格与大结局」一节收。

## 顺带确认

- **有没有角色设定图**：用户有现成的角色立绘 / 漫画截图就让 ta 传上来，以图为准，跨集都按它画。
- **多长**——4-600 秒。材料里读得出（用户说过 / 原文那一段的篇幅明显对得上）就直接用，完全没信息才 `ask_user_number`。
  **默认 90 秒**：用户放手时直接取它；要问时长时，它就是 `ask_user_number` 的 default。
- **一次建几集**：用户给了整章原文、说「先做前三集」，就按原文切成三集，每集一条剧情指令。

## 结局风格与大结局

- **剧集模式不问**：缺省各集连着走（`serial`）；用户明说「每集一个独立故事 / 单元剧」才换。
- **结局风格**：用户已经明说怎么收尾（「最后要大团圆」「结尾留个悬念」、或原文自带结局）就直接采用；
  其余情况弹一张 `ask_user_choice` 2 选不带自定义，措辞按剧集模式写：
  - 连续剧：问「将来大结局那一集怎么收？」→「完整收束：伏笔全部交代清楚，给个明确的结局」/
    「开放式：留个悬念收尾，让观众自己想」。
  - 单元剧：问「每一集的结尾怎么收？」→「收干净：每集自成闭环，结尾点题」/「留白：每集结尾留个开放的余味」。
- **哪一集是大结局**：只有连续剧问，一批里最多标一集；原文自带收尾就照它判，拿不准再问一张卡。单元剧不问、恒否。
- **用户放手时**（「别问了」「你定」）：结局风格按「完整收束」定，不弹卡；复述里标「（我替你定的，要换说一声）」。

## 参数怎么收（先判三态，缺信息的才问）

每一项开口之前先看手上已经有什么——**用户给得越全，问得越少**：

1. **用户明说了，或材料里能直接读出** → **直接采用，不弹卡、不追问**。
   材料 = 用户的话、贴来的小说原文 / 梗概、上传的角色图或文档。
2. **能从上下文合理推断** → 采用、不弹卡，最终复述里这一项后面标「按你的材料推断」并写明依据
   （原文是「我」在讲 → 第一人称旁白；「发抖音连载」→ 竖屏）。
3. **完全没有信息** → 才问：
   - 离散字段弹卡：时长 / 画幅 / 结局风格 / 项目名候选
   - 开放内容纯文字：讲什么故事、这一集讲到哪

- **视觉风格按通用规则收**：用户点名了就直接采用；没说就 `ask_user_choice` 传 `preset_pool='video_style'`
  （系统自动注入全部内置风格 + 自定义框，**不要自己列风格名、也不要替用户排除任何风格**）。
  本品类推荐动漫 / 漫画类风格，可以在 question 文字里这样说，但不要替用户删选项。
- ⛔ 不要因为某一项「是离散字段」就弹卡——材料里有答案的，答案就是答案，不是「默认值」，别让用户再点一次。

## 落库前：复述 → 确认

复述照主指令的共用模板走，本品类在〔品类字段〕那一格写这几行：

```
- 题材: XXX               ← 重生 / 穿越 / 修仙 / 霸总 / 甜宠……
- 讲述: XXX               ← 第一人称旁白 / 第三人称旁白 / 少旁白、以对白为主
- 剧集: 各集剧情连着走     ← 单元剧写「每集一个独立故事」
```

逐集清单里，连续剧每集后面标 `非大结局` 或 `**大结局**`（是大结局的那一集要加粗，它会锁死项目）；单元剧整格省略。

这些信息落在哪：**题材、主角设定、讲述视角写进世界观**（`theme_prompt`，各集共用）；
**这一集讲到哪、停在哪个钩子上**写进这一集的剧情指令；改编自原文时，这一集对应的那段原文整段放进剧情指令。
⛔ 发在哪只用来决定时长和显示方向，不进世界观、不进剧情指令；世界观和剧情指令里也不写画幅 / 横竖屏。

复述完**同一轮紧接着** `confirm_action`，确认后按主指令的落库方式调。

**这一次复述 + `confirm_action` 是整个流程唯一的一张确认卡**：采用的、推断的、用户选的字段全部并进它，
每项后面标来源（`按你的材料` / `按…推断` / `你选的` / `我起的`）；⛔ 不许先弹一张「确认默认值」再弹一张「确认创建」。
改编自原文时复述里多一行「剧本：按你的原文改编（保留关键台词与情节）」；
用户要求一字不改时写「剧本：按你的原文转录（一个字不改）」。

## 再做一集

连续剧的下一集 = 接着上一集的钩子往下讲。只聊「这一集讲到哪」+ 时长（用户接着贴下一段原文，那一段就是这一集），
题材、风格、讲述视角沿用。
