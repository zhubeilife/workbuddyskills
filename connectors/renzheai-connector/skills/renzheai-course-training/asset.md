# 课程培训 · 素材细则

主指令（素材师 skeleton）里只有平台机制。**每类素材怎么写在这里**；建哪些素材以剧本师的素材清单为准。

## 每类素材怎么写

| 类型 | 怎么写 |
| --- | --- |
| `character` | **核心素材**；讲师造型一次定好，一门课各节都按它生成 |
| `scene` | 整洁、标准，就是「该有的样子」 |
| `prop` | 写清操作时看得到的部位 |
| `special` | 卡上的字按材料原文，不改一个字 |
| `audio` | 讲师清晰、平稳、中等语速，像在上课而不是在播广告 |

## 讲师素材

- **一个让学员信得过的样子**：年龄段、着装（工装 / 商务 / 行业制服）、一个记忆点写清楚；系列课每一节都按它生成，造型不能漂。
- 用户传了真人讲师照片，**以图为准**，不要自行想象外观；没传就按学员与行业起一个，⛔ 不写姓名与头衔，除非用户提供了。

## 演示场景与设备

- **场景要标准**：演示的是「正确做法」的环境，地面、走线、标识、物品摆放都写成合规整齐的样子；
  错误示范需要的乱象（地上的杂物、堵住的通道）只按剧本清单的变体条写，不改主场景。
- **设备、工具写清被操作的部位**：开关在哪、按钮几个、把手朝哪——特写会拍到它。用户传了真实设备照片，照图写。
- 同一件东西的正常 / 出错状态（关好的阀门 / 没关的阀门）各列一条变体，`variant_of` 回链主条。

## 界面截图：以用户上传的为准

软件、系统、设备面板上的字和布局，视频模型画不出来、也不该编。

- 用户传了截图 → 以截图为准，描述照着截图写，⛔ 不改界面上的任何字。
- 没有截图 → 照常干活，在 summary 里写一句「软件界面需要真实截图，没有的话画面只能拍操作动作，
  学员照着对不上界面，建议上传每个关键步骤的截图」，由调用方转告用户。
