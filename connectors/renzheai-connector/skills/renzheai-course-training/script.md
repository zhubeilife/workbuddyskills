# 课程培训 · 编剧细则

剧本师主指令里已有**平台机制 + 通用编剧手艺**：工具怎么调、产出形态、块 id 纪律、
台词法则（信息前置 / 动作可视化）、人设与配角格式、换皮重制、自检与合规、画面文字的四问。
**这一份只有教学视频特有的东西** —— 别在这里找台词怎么写、人物怎么立。

## 骨架：目标 → 讲解 → 示范 → 小结

| 段落 | 占比 | 要做到 |
| --- | --- | --- |
| **开场点题** | 前 10% | 讲师一句话说清「这一节学完你能做到什么」。⛔ 不寒暄、不讲「培训的重要性」 |
| **讲解与示范** | 70% | 要点逐条讲，每一条都配一段能看见的示范：步骤演示、情景演示、正误对比 |
| **常见错误** | 10% | 学员最容易做错的一两处，点名说清（材料里没有就省掉这一段，不编） |
| **小结** | 最后 10% | 讲师把这一节的要点按顺序再说一遍，收在一句行动提示上（「下次遇到退货，就按这三步来」） |

短的一节（一个技巧、一条规定）压成「点题 → 一段示范 → 小结」。
`serial` 的课开头可以用一句话接上一节学过的东西（「上一节我们学会了登录，这一节来建第一张单」），⛔ 不复述上一节全部内容。

## 忠于材料，这一条比什么都重要

用户给了讲义 / 制度原文 / PPT / 操作手册时：

- **要点与步骤一条不漏、顺序不改**：材料写了五步就是五步，不合并、不跳步、不调换。
- **专业术语、制度条文里的关键词逐字照用**：「动火作业审批」不改成「用火要申请」，系统里的按钮名、菜单名原样照写。
  解说词可以在术语后面补一句白话解释，但术语本身不动。
- **数字一个都不改**：时限、距离、温度、金额、比例，照材料原样进解说词。
- ⛔ 材料没写的规定、步骤、数值**不要自己补**；觉得材料有缺口，在 summary 里列出来，由调用方去问用户。
- 材料装不下这一节的时长：按材料顺序讲完能讲完的那一段，在 summary 里写明「从第 X 条起留给下一节」，⛔ 不为了塞进时长而删要点或压成一句带过。

## 讲解词怎么写

- **一句只讲一个动作或一个要点**：「先点右上角的新建，再选退货单」拆成两句，跟着画面走。
- **步骤由解说词带出序号**：「第一步……第二步……」，学员边看边能数得清。
- **讲为什么，但只讲一句**：每条规定后面跟半句理由（「因为冷链断了就不能再上架」），学员记得更牢；不展开成科普。
- **用学员自己的场景举例**：门店的就举门店里的事、车间的就举车间里的事，别用跟学员不相干的例子。

## 正误对比：制度、安全、服务话术类的核心手法

- **先演错的、再演对的**：同一个场景、同一个人，错误做法出了什么后果，正确做法怎么做——两段尽量对称，学员一眼看出差别在哪。
- **错误要典型，不要夸张**：演的是学员真会犯的错（忘了戴手套、先办手续再道歉），不是闹剧式的离谱操作。
- **后果点到为止**：安全类可以演出隐患和险情，⛔ 不写血腥伤亡的画面；用讲师的一句话说清后果比画面渲染更有效。
- 错误示范结束要明确收回来（讲师一句「这样做是不对的」），⛔ 不能让错误做法看起来更轻松、更好玩。

## 这类片子常撞上的「画面上的字」

教学视频最容易觉得「每一步都该打一行字」，这几种都照通用细则「画面文字」的四问走（以下是例子，不是清单）：

- **步骤说明、要点句** → 是解说词，由讲师念出来，序号也由解说词带出；⛔ 不为每一步做一张步骤卡，不写「屏幕上打出第一步」。
- **小结要点** → 讲师在结尾念一遍；学员需要截图留存、或用户明确要一张要点清单的，做**一张**小结卡当文字素材，
  `reason` 里按材料原文逐条写清卡上的字，不改字、不改顺序。
- **关键数字 / 红线条款**（「离地两米以上必须系安全带」）→ 进解说词；确实要定格看清的，最多一张写着那一条的静态卡。
- **软件界面、设备面板上的字** → 现实里真实存在，走第 4 问：用用户上传的界面截图 / 设备照片当素材，以截图为准；
  没有截图时只写操作的动作（「点开右上角的菜单」），⛔ 不描述界面上印着什么字，并在 summary 里提醒用户上传截图。
- 一节里的文字素材通常 0~2 张，数到第 3 张就回头查——多半是把该讲的话做成了卡。

## 素材清单列什么

- **讲师是核心**：一门课各节**跨集复用**同一条，不每节重建；演示里的学员、顾客、同事列一两个就够。
- **演示场景 1~3 个**：学员真实工作的地方（门店收银台、车间工位、办公桌、客服坐席）。
- **演示用到的设备、工具、单据必列**（灭火器、扫码枪、退货单、防护手套）；软件教程列每个关键步骤的界面截图。
- **讲师与有台词的演示角色各列一条音色。**
- ⛔ 不列：只在讲解词里提到、画面上不出现的东西；用户没提供、也推不出来的真实系统界面——宁可只拍操作动作，也不要编一个界面。

## 什么不该做

- 不要一节里讲两个学习目标；
- 不要把培训写成剧情片——情景演示是为了示范，人物不需要弧线和反转；
- 不要在结尾留悬念或「下节更精彩」——每一节收在小结上；
- 不要在小结里出现正文没讲过的新要点。
