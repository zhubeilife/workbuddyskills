# 短剧 · 访谈与落库参数

主指令里有**通用的那一整套**：`create_project` / `create_episode` 要凑齐哪些字段、各字段用什么工具收、
收尾怎么核对复述确认、换皮重制流程、补设定的门槛与两工具连调。**那些对所有品类都一样，这里不重复。**

这一份只有**短剧特有的三个字段**（剧集模式 / 结局风格 / 是否大结局）与**本品类的问法**。
⚠️ 读到本文件说明当前品类是短剧——下面这三项别拿去套别的品类，它们在别处压根不问。

# 本品类特有的项目级字段

主指令「创建新项目」清单里那条「当前品类 skill 要求的其余项目级字段」，在短剧这里是下面三项。

## 剧集模式 story_mode（必问，除非用户已明说）

serial 连续剧（各集剧情连贯、后一集承接前一集）/ anthology 单元剧（每集是一个独立完整的故事，互不相关）。
这一项决定整个项目会不会积累剧情记忆、集与集怎么衔接，**不许静默按缺省落**：

- 用户已明说 → 直接传，不用再问：「每集一个独立故事」「单元剧」「各集互不相关」「一集讲一个寓言 / 一个案子」「像《世界奇妙物语》那样」→ anthology；「连续剧」「剧情连着走」「下一集接上一集」→ serial
- 其余情况 → **必须用 ask_user_choice 问一张卡**。两个选项写成人话，别甩英文字段名：
  「各集剧情连着走，后一集接前一集」/「每集一个独立完整的故事，互不相关」

选了 anthology 之后：本项目**不会**积累剧情记忆，各集不承接上集、也不留跨集悬念；**也不问、不设大结局**（每集的 `is_finale` 恒 false）；
用户想改回来可以在项目详情里切。这一项定了就在复述里念一句（见本文末「共用复述模板里，本品类要填什么」）。

## 结局风格 finale_style

`closed` 完整收束 / `open` 开放式留白。**用户已经明说怎么收尾（「最后要大团圆」「结尾留个悬念」、或给的剧本自带结局）就直接传；
其余情况必须弹一张 ask_user_choice——这一项不许推断、不许静默按缺省落**（用户放手时例外，见下方「用户放手时」）。
措辞按剧集模式写（所以要先心里定下剧集模式——世界观聊完就能判）：

- 连续剧：问「将来大结局那一集怎么收？」→ 选项「完整收束：伏笔全部交代清楚，给个明确的结局」/
  「开放式：留个悬念收尾，让观众自己想」。这一项现在定好存着，中间各集照常写、不受影响。
- 单元剧：问「每一集的结尾怎么收？」→ 选项「收干净：每集自成闭环，结尾点题」/
  「留白：每集结尾留个开放的余味」。这一项是**每一集**的收尾方式。

## 哪一集是大结局 is_finale

**只有连续剧问这一项**，且**一批里最多一集能标**（标两集工具会拒收）。

只建一集时就是问「这一集是不是即大结局（单集短篇）」；建多集时通常是最后一集，用户的剧本
自带收尾就照它判、拿不准再问一张卡。单元剧不问、恒否：选单元剧就是要持续做一集接一集的
独立故事，而大结局会把项目锁死、之后一集都建不了。

## 用户放手时（「别问了」「你定」「其它按推荐来」）

主指令的「用户放手时」优先于本文里的「必须弹卡」：剧集模式、结局风格这两项由你定，不弹卡，取你本来会推荐的那一项——

- 故事在这一集里讲完了 → 每集一个独立故事 + 收干净；
- 故事停在钩子上、或用户提过「系列 / 后面还要做 / 第一集」→ 各集连着走 + 完整收束（大结局那一集才用得上，先存着）；
- 只建一集、又判不出来 → 按每集一个独立故事 + 收干净。

**时长默认 150 秒**：用户放手时直接取它；完全没信息、要问时长时，它就是 `ask_user_number` 的 default。 你替用户定的这几项，复述里逐项标「（我替你定的，要换说一声）」并带半句理由。

## 这三项各用什么工具收

这三项决定内容怎么组织、怎么收尾，只有两态：**用户明说了（或给的剧本里写明了）→ 直接采用；没说 → 弹卡**。
不做推断——推断错了整个项目返工。其余通用字段（时长 / 显示方向 / 平台…）照主指令的「字段三态」判，
材料里读得出、推断得出的一律不问，全部并进最后那一张复述确认卡。

- **剧集模式** ask_user_choice 2 选不带自定义（用户已明说就不问）
- **结局风格** ask_user_choice 2 选不带自定义，措辞按剧集模式写（用户已明说就不问）
- **哪一集是大结局**（仅连续剧）ask_user_choice 2 选。早点定，它决定那一集剧情怎么收。
  单元剧**跳过这一问**，各集 `is_finale` 一律 false

# 补设定时这两项怎么收（归属空项目的会话）

主指令的「归属空项目的会话」那节讲了门槛与流程（动态补只补缺的、复述与确认只有一次、
update_project → create_episode 同一轮连调、两次调用之间不再问）。
本品类在那套流程里还要补齐下面两项——其余各项（世界观 / 视觉风格 / 显示方向）照主指令那节收，
本品类无特殊要求：

- **剧集模式**：**照上方「剧集模式 story_mode」那套判**——用户已明说直接传；其余情况必问一张卡
   （民间故事 / 成语故事 / 睡前寓言 / 单元案件这类天然一集一个故事的题材尤其要问）。
   传了 anthology 就在复述里念一句。
- **结局风格**：ask_user_choice 2 选不带自定义，措辞按剧集模式写（见上方「结局风格 finale_style」）。
   **用户没明说就必须用户点**——它决定剧本怎么收尾，连续剧是将来大结局的收法、单元剧是每一集的收法。

# 共用复述模板里，本品类要填什么

主指令的「落库前的复述与确认」是**所有品类共用的一套**（逐集清单格式、真实序号纪律、
上传素材行、来源标注、confirm_action 的 title 写法、批量上限；**全流程只有那一张确认卡**）。本品类在那套模板里这样填：

- **字段齐全的硬闸口**加一项：`是否大结局`（**仅连续剧**；单元剧没有这回事，不核也不问）
- **〔品类字段〕那一格**写大结局标记：
  - 连续剧 → `非大结局` 或 `**大结局**`（是大结局的那一集要加粗，它会锁死项目）
  - 单元剧 → **整格省略**（连分隔符 `｜` 一起去掉）

```
- **第 12 集**《雪夜寻仇》｜45 秒｜非大结局
  > (完整剧情指令原文)
- **第 13 集**《血债血偿》｜60 秒｜**大结局**
  > (完整剧情指令原文)
```
