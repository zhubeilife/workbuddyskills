# 祝福视频 · 访谈与落库参数

主指令里有**通用的那一整套**：`create_project` / `create_episode` 要凑齐哪些字段、各字段用什么工具收、
收尾怎么核对复述确认、换皮流程、补设定门槛。**这一份是本品类的访谈提纲**——问什么、怎么问、
本品类特有的字段怎么填、复述里念哪几行。

## 必须聊清的四件事

1. **送给谁**——名字（或称呼）、和送祝福的人是什么关系（妈妈、老婆、闺蜜、带过的学生、全体员工、合作多年的客户）。
   用户写了「送给我老婆小雅」就已经齐了，不用再问。被祝福的是一群人（全体员工、各位客户）时，问清怎么称呼这群人。
2. **什么场合**——生日、春节、中秋、婚礼、结婚十周年、毕业、开业、升职、年会……
   场合决定调性的大方向（拜年喜庆、纪念日温馨、毕业带点不舍），也决定画面里会出现什么（蛋糕、红灯笼、婚纱、学士帽）。
3. **谁送的、以谁的口吻**——送祝福的人自己说、几个人一起说（「全家」「整个部门」）、
   还是让一个可爱的形象 / 吉祥物代为送上。这决定主角是谁、旁白用谁的声音。
4. **一两件具体的事**——一段共同的回忆、对方的一个特点或习惯、这一年 ta 做成的一件事。
   这是整条片子的分量所在：**用户没说就一定要问一句**（「有没有一件你们之间的小事、或者 ta 的一个特点，想放进去？」）。
   用户说「没有 / 你看着写」就不再追，剧本按场合写，但不编造具体经历。

## 顺带确认

- **有没有照片**：主角是被祝福的人（或送祝福的人）时，请用户把照片传上来——人物以照片为准，不凭描述想象长相。
  没有照片也能做：换一个可爱的形象代为送祝福，或者只拍场景与物件、人只出现背影 / 手。
- **祝福语有没有现成的**：有就**一字不改**照用；没有就问一句「祝福语我来写，还是你有想说的话」。
- **名字要不要出现在画面上**：要的话名字和那句祝福语会做成画面上的字卡（视频里写不出准确的字）；
  也可以只念出来、不上画面。用户没提就按念出来处理，复述里说一句「名字只念、不上画面」，用户想要再加。
- **多长**：4-600 秒。材料里读得出（用户说过 / 要发的地方有明确限制）就直接用，完全没信息才 `ask_user_number`。
  **默认 30 秒**：用户放手时直接取它；要问时长时，它就是 `ask_user_number` 的 default。

## 参数怎么收（先判三态，缺信息的才问）

每一项开口之前先看手上已经有什么——**用户给得越全，问得越少**：

1. **用户明说了，或材料里能直接读出** → **直接采用，不弹卡、不追问**。
   材料 = 用户的话、贴来的祝福语 / 想说的话、上传的照片或文档。
2. **能从上下文合理推断** → 采用、不弹卡，最终复述里这一项后面标「按你的材料推断」并写明依据
   （「给我妈过六十大寿」→ 生日、子女口吻、温馨；「发朋友圈 / 微信群」→ 竖屏）。
3. **完全没有信息** → 才问：
   - 离散字段弹卡：场合 / 口吻 / 时长 / 画幅 / 项目名候选
   - 开放内容纯文字：送给谁、那一两件具体的事、想说的话

- **视觉风格按通用规则收**：用户点名了就直接采用；没说就 `ask_user_choice` 传 `preset_pool='video_style'`
  （系统自动注入全部内置风格 + 自定义框，**不要自己列风格名、也不要替用户排除任何风格**）。
- ⛔ 不要因为某一项「是离散字段」就弹卡——材料里有答案的，答案就是答案，不是「默认值」，别让用户再点一次。

## 落库前：复述 → 确认

复述照主指令的共用模板走，本品类在〔品类字段〕那一格写这几行：

```
- 送给: XXX              ← 名字 / 称呼 + 关系（一群人时写怎么称呼这群人）
- 场合: XXX
- 谁送的: XXX            ← 本人 / 全家 / 某部门 / 由某个形象代为送上
- 想放进去的事: XXX      ← 没有就写「按场合写，不编具体经历」
- 祝福语: XXX            ← 用户给的原文照抄并标「一字不改」；没给写「我来写」
```

这些信息落在哪：**场合、谁送的、调性写进世界观**（`theme_prompt`，同项目各集共用）；
**送给谁、那一两件事、祝福语原文**写进这一集的剧情指令。
⛔ 发在哪只用来决定时长和显示方向，不进世界观、不进剧情指令；世界观和剧情指令里也不写画幅 / 横竖屏。

复述完**同一轮紧接着** `confirm_action`，确认后按主指令的落库方式调。

**这一次复述 + `confirm_action` 是整个流程唯一的一张确认卡**：采用的、推断的、用户选的字段全部并进它，
每项后面标来源（`按你的材料` / `按…推断` / `你选的` / `我起的`）；⛔ 不许先弹一张「确认默认值」再弹一张「确认创建」。
用户给的是成品台词 / 祝福文案、要求照它做时，复述里多一行「剧本：按你的原文转录（一个字不改）」。
`story_mode` / `finale_style` / `is_finale` 按 SKILL.md 直接填，不问、不复述。

## 再做一集

同项目下的下一集 = 同一个场合、换一个被祝福的人（下一位员工、下一位客户）。
只聊「这一条送给谁 + 那一两件事 + 祝福语」+ 时长，场合、风格、送祝福的人沿用；
用户一次给了一串名单，就按主指令的多集方式一次建齐，每一集的剧情指令各写各的人和事。
