# 项目衔接：asset_intent 素材意图清单

（本集怎么承接上一集、怎么收尾，属于品类方法论，在本次任务给定品类的那份 `script.md` 里；
这里只讲**产出形态**：给下游素材师的那份清单该长什么样。）

## asset_intent：建条清单（列了就建）

### 为什么需要

`asset_intent` 是素材师的**建条权威清单**：素材师只照清单建条，不自己从剧本里再提取。
清单收口两件事——**不漏建**（画面里要认出来的实体都得有参考图，没有参考图的实体交给
视频模型自由发挥，跨镜形象稳不住），也**不多建**（不在清单里的实体素材师不建）。

### 列举规则

- **剧本正文点名的角色 / 场景 / 道具 / 特效 → 各列一行**。凡是观众要在画面里认出来的
  实体都必须有参考图——正文写到了金牌徽章，就列金牌徽章
- **有台词的单人具名角色一律列（铁律）**：台词块（`type='dialogue'`）里出现过的每个
  单人说话者，哪怕只有 1 句过场台词也必须列——实测说话角色不出参考图，
  视频里形象会乱（换镜变脸）
- **群演 / 路人 / 群体说话者（"众村民""围观群众""学徒们"这类批量人物）不逐个列**：
  汇总成**一条 `type='prop'` 的群像素材**（如「本集群演群像」，全集所有群体合一条），
  reason/描述里列清包含哪些群体及各自服饰身份——实测群演不出图，
  模型画出来的路人全长一样；一张多人群像图作道具引入，分镜按需引用。
  **无台词的一闪而过路人同样并入这条群像**，不单列
- **画面上要出现的字 → 列一行 `type='special'` 的文字素材**：时间卡 / 片名 / slogan /
  联系方式卡 / 企业名墙 / logo。视频模型写不出可读的字，画面上的字只能来自
  一张素材图——清单里没有这一行，下游就没有图可引用，这段字就上不了画面。写法见下方「文字素材」
- **正文没写的环境陈设**（桌椅摆设、街景背景这类）不进清单——那是分镜 video_prompt
  用文字描述的事，不立素材

### 输出形态

每行 `{ name, type, reason, variant_of? }`——**没有 intent 字段**：列进清单 = 建，
不出图的改判只属于用户（在前端操作），你不用管。

```json
[
  { "name": "张万雀", "type": "character", "reason": "主角，本集核心" },
  { "name": "老周",   "type": "character", "reason": "本集核心配角，全集 5 秒戏" },
  { "name": "本集群演群像", "type": "prop", "reason": "含围观群众×3、店小二；市井粗布短打" },
  { "name": "VIP休息室", "type": "scene",  "reason": "本集唯一场景" },
  { "name": "金牌徽章", "type": "prop",    "reason": "老周胸前佩戴，多镜可见" },
  { "name": "圣旨",    "type": "prop",     "reason": "本集关键道具，需要多场出现" },
  { "name": "转场时间卡", "type": "special", "reason": "第二场开头的时间跳跃。图上的字：「三天后」，黑底白字居中" },
  { "name": "张万雀-音色", "type": "audio", "reason": "在场主角，本集大量台词" },
  { "name": "老周-音色",   "type": "audio", "reason": "在场核心配角，有台词" },
  { "name": "画外解说员（大气磅礴）", "type": "audio", "reason": "开场画外解说，独立声源" }
]
```

### type 5 类（严格）

| type | 含义 | 例子 |
|------|------|------|
| `character` | 有名字的人物 | 张万雀 / 老周 |
| `scene` | 地点 | VIP休息室 / 草料场 |
| `prop` | 重要道具 | 圣旨 / 长枪 / 智能手机 |
| `special` | 特殊视觉元素 / 文字素材 | 闪回画面 / CG 特效 / 时间卡 / 片名 / 联系方式卡 |
| `audio` | 具名说话人的音色 / 画外声源（群体不立） | 张万雀-音色 / 画外解说员 |

### 文字素材：画面上的字各列一条 special，原文写进 reason

正文里每一处走到「画面文字」四问的第 3 问、判为「静止且必须被看见」的字，各列一行 `type='special'`：

- **`name` 按用途起，⛔ 不把图上的字写进名字**：「转场时间卡」「片名」「片尾 slogan」「联系方式卡」「合作企业名墙」「公司 logo」。
  名字是下游对账的键（素材按名字匹配、分镜按名字引用），而图上的字是会改的——字写进名字，用户一改字，三处名字就对不上、
  还会重复建条。字只写在 `reason` 里。同一张图多处出现只列一条；一集里有两张时间卡就按位置区分（「转场时间卡·第二场前」「转场时间卡·第三场前」）。
- **`reason` 里把要上图的原文一字不差写出来**，再带一句版式线索（底色 / 字色 / 位置 / 质感）。
  版式线索里 ⛔ 不要「小字」「一行小字备注」「角落水印大小」——这张图会被缩小放进视频画面，字小了视频模型看不清就会自己重画一遍。要上图的字一律按大字、少字写。
  下游照这句话做图，这里概括成「三家合作企业名称」，图上就没有那三个名字：
  - ✅ `"图上的字：「伯恩光学」「努比亚」「光峰科技」，三行竖排；前台背景墙上的发光字"`
  - ❌ `"前台背景墙展示合作客户"`（没有原文，做不出图）
- ⛔ **长在场景上的字不单列文字素材**：店铺招牌、门头、墙上的大幅标语、球场边的横幅——它们是场景的一部分，会画在场景图里。
  单列成一张字卡，就得让视频模型把字卡「贴」到画面里的招牌位置上，那一步最容易出错。
  做法：把要出现的字写进**那个场景行**的 `reason`（「门头灯箱招牌：桂花乌龙」）；剧情里店名没定就在这里定一个。
  真实门店的招牌同理，写在场景行上并注明「真实门店，需用户上传门头照片」。
- ⛔ **长在道具 / 产品上的字同理**：瓶身标签上的牌子、包装盒上的品名、工牌、车身喷字——它们是那件东西的一部分，会画在那件道具的素材图里。
  写进**那个道具行**的 `reason`（「瓶身印品牌名『…』与头像标识；真实信息，需用户上传图片」），⛔ 不再为上面的牌子 / 图标各单列一行文字素材——
  同一块字出两张图，下游不知道该信哪一张。
  ⛔ 尤其不要「道具留白 + 另做一张字卡贴上去」——道具在画面里会动、会转、会变远近，视频模型没法把一张平面字卡贴准在它身上：
  - ❌ `prop | 外卖保温箱 | 黄色保温箱，箱体正面为店名留白（字用「箱体店名」素材图）` + `special | 箱体店名 | 图上的字：「阿香米线」`
  - ✅ `prop | 外卖保温箱 | 黄色保温箱，箱体正面印大字「阿香米线」（只出现这四个字）；多镜出现`
  品牌 logo 也按这个判：它**单独出现在画面里**（片尾黑底落版一个 logo）才列一条文字素材；只是印在车厢、瓶身、工装上的，跟着那件东西走，不另列。
  片尾想让这行字「占满画面」也一样：正文写「△ 箱体正面占满画面」，引用的仍是这件道具的图，不另做卡。
- 正文的 `action` 块与这一行**用同一个叫法**（正文写「联系方式卡从画面下方升起」，清单 `name` 就叫「联系方式卡」）——
  下游按名字把画面和素材图对上。

### 现实里真实存在的东西：照写照列，reason 注明需用户上传

判据：**这个东西在现实里真实存在，观众会拿它跟现实对照吗？**——拨这个电话、扫这个码、认这张脸、
买这个产品。是 → 它只能用真图，生成的图再像也是假的。常见的：联系方式 / 二维码 / logo /
企业与客户名称 / 资质证书 / 老板或个人 IP 的真人形象 / 真实产品 / 真实门店。

- **先看项目素材里有没有**（开局 `get_project_materials` 已读）：用户已经传了对应的图 → 按下方
  「用户上传素材」的规则用，`name` 照抄那张素材的 title，不另列一条。
- **没有 → 照样写进正文、照样列进清单**，类型按它是什么定（真人 → `character`、产品 → `prop`、
  联系方式卡 / logo / 企业名墙 → `special`），`reason` 末尾加一句「真实信息，需用户上传图片」。
  用户随时可以在素材页给这一条上传真图；图没到不是不写这个画面的理由。
- **summary 末尾点名**：「以下素材是真实信息，建议上传真图：联系方式卡、公司 logo」——由调用方转告用户。
- **二维码**：视频模型会把它重画一遍，成片里的码扫不出来。含二维码的那一行 `reason` 里加一句「二维码仅作示意，成片里扫不出来」，
  summary 里也点一句，由调用方告诉用户怎么处理。

```json
[
  { "name": "联系方式卡", "type": "special", "reason": "片尾定格画面。图上的字：电话、微信、二维码三个信息位；深蓝底白字。真实信息，需用户上传图片" },
  { "name": "陈总", "type": "character", "reason": "企业创始人出镜讲述。真实人物，需用户上传图片" }
]
```

### audio 类型：具名说话人（含形态变体）各列一条，群体不列

音色的存在前提是**这个声音由一个人发出**。台词块（`type='dialogue'`）的说话人按此分三档：

- **在场且有台词的角色/形态** → 各一条，`name` = `<说话人名>-音色`（「张万雀-音色」「老韩-音色」「老韩（皇帝）-音色」）。**形态变体说话也单列**——共不共声线只写在 `reason` 里（如「共用班主任声线」），条目数不减：每个形态有自己的音色行，用户才能给某个形态单独换音色而不影响其它形态。
- **画外声源**（画外解说员 / 画外播音员 / 旁白等）→ 各一条独立 audio，`name` 自定且可含语气（如「画外解说员（大气磅礴）」「画外播音员」「旁白」）。**一集可有多个画外音，互不合并**。它没有画面形象，只有声音。
- ⛔ **群体说话人**（看客群 / 众人 / 围观百姓 / 满城百姓）→ **不列 audio，也不列 character**，只并进「本集群演群像」那条 prop。群体不是一个人，一条音色念不了「齐声起哄」；那条 prop 群像图的作用是让视频模型别把群众画成一排双胞胎，跟声音无关。群体那几句台词照常写进 dialogue 块（台词内容有表演价值，不要降级成 action 描述），声音由视频模型按台词自己演。

具体音色选择由素材师做（共声线的变体条目素材师会直接复用 base 的音色，不重新挑）。

台词块里画外音那句的 `speaker` 用画外声源的名字（如「画外解说员」），跟对应 audio 条目的 `name` 语义一致——两边名字要互含，配音链路靠它接音色；在场角色那句的 `speaker` 用角色名（张万雀）或变体全名（老韩（皇帝）），与「<说话人名>-音色」一一对应——工具会校验**每个列了 character 条目的 speaker** 都有对应音色条目，缺报 `SPEAKER_AUDIO_MISSING` 拒收。群体 speaker 没有 character 条目，不在校验范围。

### 形态变体：同角色/场景多形态各列一条（variant_of 回链）

角色 / 场景在剧本时间线里发生**跨镜持续、影响画面识别**的形态变化时，每个形态是**独立素材**，asset_intent 里**各列一条**：

- **算形态变化**（按剧本动态判断，不是穷举）：年龄段跨越（小孩→少年→老年）、身份/服装体系变化（跳槽换公司工服、入伍着军装、穿越着龙袍）、重大造型变化（长发削发为僧）、场景改造（宅院烧毁前后）。判定核心：这个形态**跨多个分镜持续存在**，且观众一眼能看出「跟之前不一样了」。
- **不算**：单镜/单场的瞬时状态（淋湿、受伤挂彩、一场戏的睡衣）——这由分镜的 video_prompt 文字表达，不立素材。
- **穿戴 vs 持握**：**穿在身上、改变角色外观辨识的**（服装 / 制服 / 马甲 / 盔甲 / 龙袍）→ 属于形态变化，立**变体**，衣着由变体的定妆图承担；**手持 / 骑乘 / 独立物件**（外卖箱、电动车、武器、拂尘）→ 立 **prop**。⛔ 禁止把「黄马甲」这类穿着塞进 prop 条目指望模型把它「穿」到人身上——跨镜穿戴合成不稳定。
- **变体条目必带 `variant_of` = base 形态的人类可读名**；base 条目不带。`name` 必须**包含 base 名**且带形态限定——后缀式（「小明（少年）」「林澈（外卖服）」）或前缀式（「童年小明」）均可，与 base 可区分即行；⛔ 禁止不含 base 名的别名（「小灯」）——配音按名字互含匹配，断链。
- 回忆 / 闪回里出现旧形态 → 旧形态也照列一条（通常项目里已有素材，素材师会复用不重建）。

#### 变体音色条目示例（每说话形态各一条）

```json
[
  { "name": "小明",        "type": "character", "reason": "主角童年形态，前半集主线" },
  { "name": "小明（少年）", "type": "character", "reason": "十年后主线形态，跨镜持续", "variant_of": "小明" },
  { "name": "小明-音色",        "type": "audio", "reason": "童年段有台词" },
  { "name": "小明（少年）-音色", "type": "audio", "reason": "少年段有台词，声线随年龄变，重新选音色" },
  { "name": "老韩",        "type": "character", "reason": "班主任形态，已有素材复用" },
  { "name": "老韩（皇帝）", "type": "character", "reason": "穿越龙袍形态，跨镜持续", "variant_of": "老韩" },
  { "name": "老韩-音色",        "type": "audio", "reason": "班主任段有台词" },
  { "name": "老韩（皇帝）-音色", "type": "audio", "reason": "皇帝段有台词，纯换装共用班主任声线" }
]
```

#### speaker 全名纪律（说话形态是变体就写全名）

台词块的 `speaker` 写**说这句话的形态的条目全名**：只要这句台词是某个**变体形态**在说——不管本集有没有其它形态并存——speaker 就写变体全名（皇帝的台词写「老韩（皇帝）」不写「老韩」；回忆段写「小明」，现时段写「小明（少年）」）。**禁止对变体形态写短名**——下游按 speaker 名定位形态素材与分镜说话人，短名会指错形态。base 形态说话照常写角色名。工具会校验每个 speaker 都有**自己对应**的「<说话人名>-音色」条目，缺报 `SPEAKER_AUDIO_MISSING` 拒收。

### 「用户上传素材」铁律：硬要求只有两档

调 `get_project_materials` 开局必读，逐条看 `source='user_uploaded'` 的素材，按三档判。
判据是两个字段：`must_appear_in_script` 与 `inherited_from_episode_id`。

#### 第一档｜硬要求：`must_appear_in_script=true` 且 `inherited_from_episode_id` 为 null

用户在创建这一集时亲手传进表单的图，明示「我要这个出现在这一集」。
**本集至少出现一次**——不一定是主戏，但 `content` 块里要真的写到、要有镜头，
`asset_intent` 里列上那条。写不进去 = 这一集写砸了，不允许提交。

#### 第二档｜硬要求：本次任务描述里点名的素材

本次任务描述里写「本集剧本必须写到 <素材 title>」时，那张素材**等同第一档**，
不看它的 `must_appear_in_script` 是几、也不看是不是本集首发。
⚠️ `asset_intent` 那条的 `name` **照抄任务描述给的 title 原文**，一个字都不许改写——
素材条目按 `name` 匹配，改字下游素材师就对不上，会重复建出第二条同一实物的素材。

#### 第三档｜其余全部：剧情需要就用，不需要就跳过

包括 `must_appear_in_script=false` 的（用户自己在素材 tab 传的图、对话里拖进来的图）和
`inherited_from_episode_id` 非 null 的（首发在别的集、跨集继承过来的）。
判据跟普通素材**完全一样**：本集剧情真的用得上就写进正文、列进 `asset_intent`；用不上就当它不存在。
⛔ 不许为了「让用户上传的图出现」硬塞戏份——凑出来的戏是注水，比不出现更糟。
用户想让哪张进剧本会自己说，调用方把它写进任务描述走第二档。

## summary 字段：80 字以内本集一句话

`update_episode_script` 的 `summary` 字段：
- 给调用方 / 后续环节快速回顾本集用
- 不超过 80 字，一句话
- 必须包含「**主角名 + 核心事件 + 本集结果**」

| ❌ 反例 | ✅ 正例 |
|--------|--------|
| 「本集讲述了主角的复仇之路」（无信息量） | 「张万雀被户部侍郎老周认出是失踪皇帝，记忆觉醒后决定回宫复位」（35 字，主角+事件+结果） |
| 「林冲在草料场遇到陆谦」（缺事件、缺结果） | 「林冲山神庙偶遇陆谦密谋火烧草料场，怒杀仇敌雪夜上梁山」（27 字，主角+事件+结果） |
