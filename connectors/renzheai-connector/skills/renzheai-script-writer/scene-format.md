# 场次格式 + AI 视频经济硬约束

## 「场次」是什么

「**场（场次）**」是剧本的**最小空间单元**，对应电影术语里的"同地点同时间的一段连续戏"。

在本项目（AI 视频生成）的语境里要清楚一个**真实代价**：短集（≤15 秒）的多个场次会被分镜师**合并进同一条视频生成**——场景切换发生在视频模型内部，模型做跨空间硬切的能力差、没有运动衔接，切一次突兀一次。**换景是全剧本最贵的动作**，每一次换景都必须有充分理由。

### ⛔ 场景预算（硬约束）

按本集 `duration_sec` 给场景数预算：

| 集时长 | 场景数 |
|---|---|
| ≤15 秒 | **默认 1 场演到底**；确有戏剧需要最多 2 场 |
| 16-30 秒 | ≤3 场 |
| 每 +15 秒 | 预算 +1 |

一个地点演到底不是缺陷，是短视频的常态——15 秒内观众根本不需要换地方。

### ⛔ 换景白名单（连续两场之间必须满足其一）

1. **衔接动作**（空间相邻 + 运动连续）：上一场末尾的 `action` 块写角色的离场运动，下一场开头的 `action` 块用**同一运动**入画。
   ```
   △ 小林转身朝广场方向狂奔，冲出画面。      ← action 块（上一场末块）

   【蟠桃宴广场 · 日 · 外】                ← scene_heading 块

   △ 小林狂奔冲入广场，一头撞翻仙鹤。        ← action 块
   ```
2. **叙事跳切**（闪回 / 回忆 / 梦境 / 想象）：`scene_heading` 块的 text 加第 4 段标记。观众对这类硬切有心理预期，且下游会用色调 / 画风变化区分。
   ```
   【老宅院 · 日 · 外 · 闪回】
   ```
3. **时间跳跃**：用时间卡过渡（「三天后」）。下一场开头的 `action` 块写这张卡怎么出现，时间卡本身列进 `asset_intent` 当一条文字素材（写法见「画面文字」章节）。
   ```
   【出租屋 · 夜 · 内】                    ← scene_heading 块

   △ 时间卡「三天后」在黑场中央淡入，停留片刻后淡出。   ← action 块
   ```

❌ **禁止无理由硬切**：上一场角色还在 A 地点，下一场凭空出现在 300 米外的 B 地点，中间没有任何衔接动作 / 叙事标记——这是观感突兀的头号来源。

## 剧本正文 = 块数组（唯一产出形态）

**你的剧本正文只有一种产出形态：`content` 块数组**（`update_episode_script` 的 `content` 参数，直接传 JSON 数组）。没有「markdown 正文」这回事——不产 `###` 标题、不产整段文本，**一块就是一个 JSON 对象**（落库后每块带服务端 mint 的 id，`get_episode_script` 读回来长这样）：

```json
{ "id": "e5f6a7b8", "type": "action", "text": "△ 王总把方案摔在桌上，纸页散落。" }
```

四种 `type`：`scene_heading`（场次标题）/ `action`（动作画面）/ `dialogue`（台词，另带 speaker / emotion 两字段）/ `narration`（无声源叙述，少用，见下方字段表）。一场 = **1 个 `scene_heading` 块打头 + 若干 `action` / `dialogue` 块**，块在数组里的顺序就是剧情时间线。

每块自带稳定 id（8 位 nanoid）：**首次写全部不带 id**（服务端 mint）；修订时按下方「修订纪律」沿用旧 id。分镜师拆镜时把覆盖本镜的块 id 填进 `script_block_ids`（引用，不抄原文）——**块是分镜引用剧本的最小单位**，所以「一个动作一个块、一句台词一个块」，不要把几件事挤进同一块。

> **示例速记约定**：本 prompt 后文示例为了可读，用「一行 = 一个块」的速记展示块序列——`【地点 · 时间 · 内外】` 一行 = `scene_heading` 块；`△ …` 一行 = `action` 块；`人名（情绪）：台词` 一行 = `dialogue` 块（速记里的人名 / 括号情绪 / 冒号只是展示，落块时拆进 speaker / emotion 字段，**text 只放台词原文**）。看到速记示例，脑内都要还原成 JSON 块数组。

**关键背景**：分镜师拆分本剧本时，`validate_storyboard_coverage` 做**块 id 集合对账**——剧本每个块都必须被某个分镜的 `script_block_ids` 引用到，漏块（最典型 = 被漏掉的 `action` 动作块）会被硬拦。

这意味着：
- 你写的每一个块（含 `scene_heading` 场次标题块），都会被分镜师覆盖到某个 shot 里
- **严禁**在 `content` 里掺杂「人物表 / 世界观 / 调性」这类非剧本块——只放场次 / 画面 / 台词

### 两类内容块（核心区分）

一场戏的内容块主要是**两类**（外加场次标题的 `scene_heading` 块）：

| 块类型 | 载体 | 含义 | 下游怎么处理 |
|------|------|------|-------------|
| **`dialogue` 台词块** | speaker=人名、emotion=情绪、text=台词原文 | 人物说出口的话 | **TTS 配音念出来 + 出字幕**——AI 视频最强信息载体 |
| **`action` 动作块** | text 以 `△` 开头的画面句 | 画面动作描述（告诉演员要演什么） | AI 视频模型按此生成画面动作；**不 TTS 配音、不出字幕**——作为台词的伴随表演 |

⛔ **绝对不要**把台词写进 `action` 块 / 给 `dialogue` 的 text 加 `△`——人物说的话一律进 `dialogue` 块（speaker / emotion / text 分开），混进 `△` 动作块会让 AI 视频模型 / TTS 困惑（「这句是要演还是要念？」字幕系统也会出错）。

### 台词总量：按本集时长的节奏来

台词写多少由这场戏的需要决定，没有字数公式、也没有句数指标。唯一要对的是**时间**：
把全集台词按各自的选档语速（见「台词语速」章节）在心里默念一遍，**台词估时 + 必要的动作与留白时间，
和本集 `duration_sec` 对得上**就行。

⭐ **按本集时长把内容规划到位**：30 秒的集就按 30 秒的容量写——写太少会拍出大段没有信息的画面，
写到明显念不完则要么删内容、要么就是这一集本该更长（那是用户调设定的事，不是你硬压台词的理由）。

**明显念不完时按这个顺序处理**：

1. **首选：砍冗余字**——去掉「就是说」「然后」「我觉得」等口语填充词，砍重复信息
2. **次选：砍节拍**——节拍数超预算说明内容贪多，删一个次要节拍
3. ⛔ **不要靠改用更快的语速档硬塞**——那是拿念得快换内容多，观众听到的就是急促失真

每句台词都要服务内容——既不要冗余水台词（"今天天气真好"这种），也不要为了「少而准」把该有的对话砍光。

✅ **正例：按戏剧需要决定句数**（15 秒，1 场演到底；速记展示，一行 = 一个块）

```
【会议室 · 日 · 内】

△ 王总把方案摔在桌上，纸页散落。

王总（怒摔文件）：就你这方案？公司养你干什么吃的！

林默（低头）：王总，我重做……

王总（打断）：滚！明天不用来了！

△ 林默拳头攥得指节发白，眼眶通红，一字一句。

林默（决然）：从今天起，我要让所有人跪着求我。

系统提示音（VO）：检测到强烈逆袭意愿，商业觉醒系统已激活。
```

这一场落成 `content` 块数组（首次撰写，**全部不带 id**——服务端 mint）就是：

```json
[
  { "type": "scene_heading", "text": "【会议室 · 日 · 内】" },
  { "type": "action", "text": "△ 王总把方案摔在桌上，纸页散落。" },
  { "type": "dialogue", "speaker": "王总", "emotion": "怒摔文件", "text": "就你这方案？公司养你干什么吃的！" },
  { "type": "dialogue", "speaker": "林默", "emotion": "低头", "text": "王总，我重做……" },
  { "type": "dialogue", "speaker": "王总", "emotion": "打断", "text": "滚！明天不用来了！" },
  { "type": "action", "text": "△ 林默拳头攥得指节发白，眼眶通红，一字一句。" },
  { "type": "dialogue", "speaker": "林默", "emotion": "决然", "text": "从今天起，我要让所有人跪着求我。" },
  { "type": "dialogue", "speaker": "系统提示音", "emotion": "VO", "text": "检测到强烈逆袭意愿，商业觉醒系统已激活。" }
]
```

注意逐块对照：`scene_heading` 的 text **没有 `###` 前缀**；台词的人名进 `speaker`、括号情绪进 `emotion`、`text` 只剩台词原文（无人名 / 无括号 / 无冒号）；「系统提示音」这类**具名画外声源**照样是 `dialogue` 块（speaker=声源名、emotion 标 VO）——要配音念出来的句子一律 dialogue 块。

冲突（解雇 → 求情 → 二次羞辱）→ 反应 → 起钩，全部在**同一个会议室**内完成，没有一次换景。这是「按戏剧需要决定」且尊重场景预算的样子。

**说话不影响做动作**——两者可以同时发生。dialogue 块和 action 块交错排列，台词主导剧情，action 块描述说话时的表情/手势/对方反应。

### 一场的块序列（**台词优先，块按时间顺序排**）

一场戏 = 1 个 `scene_heading` 块打头，后面跟若干 `action` / `dialogue` 块，按剧情时间顺序排（速记示意，右侧注明块型）：

```
【地点 · 时间 · 内外】               ← scene_heading 块

△ [简短场景/人物入画，1 句]          ← action 块

[人名]（[情绪/动作]）：[台词内容]     ← dialogue 块（speaker / emotion / text 分开）

△ [说话时的画面动作 / 对方反应]       ← action 块

[人名2]（[反应]）：[台词内容]         ← dialogue 块

△ [收尾画面细节，可选]               ← action 块
```

**为什么这个顺序**：台词承担剧情驱动，`action` 块描述「说话时配套的画面动作 / 对方反应」，每个 `action` 块都在为台词服务。

**每块独立**：每个 `scene_heading` / `action` / `dialogue` 都是 `content` 里**单独一个块**，不要把动作和台词塞进同一个块、不要把两个动作合进一个 `action` 块——块是分镜师引用的最小单位，切镜边界只能落在块与块之间。块的先后就是剧情时间线。

### 各块字段说明

| 块 | 字段规范 | 例子 |
|------|------|------|
| `scene_heading` | text = `【地点 · 时间 · 内外】`，全角方括号包住；「·」分隔三段全必填；地点名与素材库场景资产对应；⛔ **不带 `###` 等任何 markdown 前缀** | text=`【咖啡厅 · 夜 · 内】` |
| `scene_heading` 第 4 段（可选） | `闪回` / `回忆` / `梦境` / `想象` 之一——叙事跳切场必标 | text=`【老宅院 · 日 · 外 · 闪回】` |
| `action` | text 以全角三角符 `△` 开头，**一个动作一个块** | text=`△ 张三猛地推开门，眼神带怒` |
| `dialogue` | speaker=说话人全名（只写名字，⛔ 不放身份描述——配角硬格式只用于该角色首次出场的 `action` 块；画外声源用声源名，如 `画外解说员` / `系统提示音`）、emotion=情绪/动作（可空串；os / VO 标记写在这里）、text=台词原文（**不含人名 / 情绪 / 冒号 / 引号**） | speaker=`张三`、emotion=`冷笑`、text=`你最好祈祷我没听清` |
| `narration` | **无声源、不进配音**的叙述性文字（不指定谁念）。极少用——**凡是要被配音念出来的句子一律写 dialogue 块**（画外解说 / 旁白给它起声源名当 speaker），否则该句进不了台词清单、配不上音色 | text=`那一夜之后，一切都变了。` |

`scene_heading` 的 text 里**不写**编号、秒数、景别——场的顺序由块顺序决定；时长由分镜师按内容估算；景别 / 运镜是分镜师的职责。

### 严禁

- ❌ **任何场次 0 台词**（哪怕只有 1 句 os / 旁白台词块都行，但不能全 `action`）——用户明确不要人声时除外（见「画面文字」章节）
- ❌ **把要说的信息写成画面上的字**（「△ 字幕打出：…」「△ 画面浮现说明文字：…」「△ 转场字幕：…」）—— 信息一律进 `dialogue` 块，规则见「画面文字」章节
- ❌ `action` 块 text 用 `▲` `▼` `*` `-` 等非 `△` 符号
- ❌ 把台词写进 `action` 块 / 给 `dialogue` 的 text 加 `△` —— 人物说的话一律进 `dialogue` 块
- ❌ `dialogue` 块 text 里塞「人名：台词」「人名（情绪）：台词」—— 人名进 speaker、情绪进 emotion、text 只留台词原文
- ❌ 任何块的 text 带 markdown 符号（`###` / `**` / `-` 列表符）—— 块型已经表达了结构，text 是纯文本
- ❌ `scene_heading` 写成「场景一」「第一场」「Scene 1」「场 1」—— 必须 `【地点 · 时间 · 内外】`
- ❌ `scene_heading` text 里写秒数 / 景别 / 编号 —— 只写地点三元组（+ 可选叙事标记）
- ❌ `action` 块写景别或镜头手法（「特写：…」「慢镜…」「镜头推近…」「快切到…」）—— 写观众要看清的内容，怎么拍归分镜师（见下方「铁律 4」）；人物「对着镜头说」这类直面观众的表演可以写
- ❌ 缺地点 / 缺时间 / 缺内外 —— 三段全必填
- ❌ **超出场景预算 / 无白名单理由的换景**（见文件开头）

### ⛔ 画面文字：视频模型不写字

视频模型画不出可读的字——让它在画面里写一行中文，出来的多半是乱码，这一条视频整条作废。所以剧本里**没有「让画面自己长出字」这种写法**。
正文里每一处「画面上有字」，都拿下面四问**从上往下走，走到哪一问有了答案就停**：

**第 1 问：观众需要读懂这些字吗？**

不需要 → 它只是道具或背景。照常写它在那、亮着、被翻动，⛔ 不写上面的字。
`△ 邻座电脑弹出一封邮件，鼠标点开了附件。` / `△ 他把一叠文件摔在桌上。` / 街景里的店招、墙上的海报，都属于这一类。

**第 2 问：需要读懂——这些字能不能由人念出来？**

能 → 写成 `dialogue` 块，`action` 块只写对应的画面与人物反应。谁念都行：角色自己念、对方念、内心 os、画外解说员。
凡是「在复述或代替一句话」的字都走这里——字幕、说明文字、卖点句、要点清单、转场字幕、手机消息、来电人、合同条款、诊断结论、余额数字、片尾钩子。
台词的字幕由后期剪辑统一配，剧本里不出现「字幕」二字。

| ❌ 写成画面上的字 | ✅ 让人念出来 + 画面 |
|---|---|
| `△ 字幕一行行打出：客户数据、研发图纸、财务人事，都需要保护。` | `画外解说员（VO）：客户数据、研发图纸、财务人事，都需要保护。` + `△ 档案室里，文件柜一格格合上、落锁。` |
| `△ 手机屏幕显示老公发来的微信：「我们离婚吧。」` | `△ 手机在桌上震了一下，林晚拿起来，脸色一点点白下去。` + `林晚（声音发抖，念出声）：……我们离婚吧？` |
| `△ 屏幕上显示余额：3.20 元。` | `阿杰（盯着手机，苦笑）：三块二。` |
| `△ 画面打出「未完待续」。` | 用一句台词或一个动作留钩子：`△ 门外忽然响起敲门声，她猛地回头。` |
| `△ 画面下方浮出两行说明文字，复述刚才那句旁白。` | 删掉——那句旁白已经在 `dialogue` 块里 |

**第 3 问：念不出来，或者念了也不够——它必须被看见。它是静止的吗？**

静止 → 规划成**文字素材**：一张带字的素材图，视频里出现的是这张图，不是模型现写的字。片名、时间卡（「三天后」）、slogan、logo、
规格参数卡、联系方式卡、要被看清的那块倒计时牌 / 那一页鉴定报告 / 那张奖状，都是这一类——它们有自己的字体、颜色、版式，是画面里的一个「东西」。
⛔ 长在场景上的字（店铺招牌、门头、墙上标语、场边横幅）、长在道具 / 产品上的字（瓶身标签、包装品名、工牌、车身喷字）不走这里——
它们画在那张场景图 / 道具图里，写法见「asset_intent」章节的「文字素材」。
正文 `action` 块只写它**怎么出现**（在画面哪里、什么时候、怎么进怎么出），同时在 `asset_intent` 里列一行 `type='special'`（写法见「asset_intent」章节的「文字素材」）。

```
△ 片尾，联系方式卡从画面下方升起，停在前台背景墙前。      ← action 块：只写怎么出现
```

会动、会变 → 视频模型做不了，一张静态图也表达不了「变化」。把变化交给台词和画面动作，画面上最多留**终态**的那一张静态卡：

| ❌ 让字动起来 | ✅ 变化交给台词与画面 |
|---|---|
| `△ 大屏上员工数从 50 一路滚动涨到 2000。` | `画外解说员（VO）：十年，从五十人到两千人。` + `△ 空荡的小办公室；同一个地方，整层楼坐满了人。`（需要的话再加一张写着「2000 人」的数据卡素材） |
| `△ 他在电脑上一个字一个字敲出辞职信。` | `△ 他的手指在键盘上停了很久，终于敲下回车。` + `周然（os）：这封信，我写了三年。` |
| `△ 直播间弹幕疯狂刷屏「666」。` | `主播（盯着屏幕笑出声）：弹幕都刷疯了！` |

逐字出现的歌词、滚动新闻条、关键词花字放大、滚动片尾同理——不写进剧本。

⚠️ **「常驻」的字也属于这一类**——一直挂在角落的价签 / 台标 / 店名角标、一直贴在画面下沿的信息条、进度条。
每一镜都是视频模型单独画的，同一块字要它每镜在同一位置重画一遍，镜与镜之间大小位置对不齐。⛔ 不写「缩到右下角常驻」「始终显示在画面下沿」：

- 要这块字 → 让它**完整亮相一两次**（开头占满画面、片尾再定格一次），其余的戏不带它。
- 体裁需要它一直在场（演播室背景大屏上的头条标题）→ 它是场景的一部分，写进场景行 `reason`、画在场景图里，正文不单独提它。
- ⛔ 不写「画面下方预留新闻条位置（由后期叠加）」这类**给后期留位置的块**：剧本的每一块都会被分镜拆成画面，
  「预留位置」拍不出来，只会让下游在那个位置摆一块东西。交给后期的内容只进 summary，正文一个字不提。
- 任务描述点名要「全程挂着」→ 照上面两条安排，summary 里说明「全程常驻的角标 / 信息条未写入剧本，成片导出后用剪辑软件加」，由调用方转告。

⚠️ **画面里设备自带的、会变的数字也是「会动的字」**——计分牌、进度条、时钟、秒表、仪表读数、排队叫号屏。
别因为它长在道具上就当成道具的一部分写「数字从 X 一路跳到 Y」：视频模型画不出一串连续变化的可读数字。写法是——
拍**光、声音和人的反应**（屏幕的光一下下闪、提示音越来越急、他盯着屏幕喉结滚动），
**变化由人报出来**（`裁判（吼）：最后十秒！` / `她（盯着屏幕，喃喃）：百分之九十九……卡住了。`），
只有剧情需要观众**定格看清**的那一个数（终场比分、最后停住的读数）才做一张静态的文字素材。

| ❌ | ✅ |
|---|---|
| `△ 计分牌上的比分从 88:90 一路交替跳到 95:94。` | `解说（VO，越喊越快）：追上来了！反超！` + `△ 计分牌的红光在球员脸上一闪一闪。` + `△ 终场哨响，全场静了一瞬。`（终场比分「95:94」做一张计分牌素材，定格时出现） |

**第 4 问：它在现实里真实存在吗？**

是 → 只能用真图，写法见「asset_intent」章节的「现实里真实存在的东西」。**二维码单独记一句**：视频模型会把它重画一遍，
成片里的码扫不出来——联系方式卡照列，`reason` 里注明「二维码仅作示意，成片里扫不出来」，由调用方告诉用户。

走四问时别走偏的几处：

- **「这种片子本来就该有字」不是理由**：宣传片的数据字幕、口播的关键词花字、探店 vlog 的弹出吐槽、新闻的滚动条、
  剧情片的「未完待续」——都是体裁惯例，照样从第 1 问走下来。
- **字是动作的一部分时，写动作，别删戏**：老师在黑板上写下「坚持」、书法家挥毫写「福」、她把信读给奶奶听——这些戏照常写。
  要被看清的成品（写好字的黑板、那幅字）走第 3 问做一张素材；逐笔书写的过程拍运笔和神情，不要求字一笔笔长出来；读信本来就是台词。
- **用户明确不要人声**（纯音乐氛围片 / 默片风格）：尊重，不硬塞解说词，也不改用一排文字卡讲故事——让画面自己讲，
  信息装不下就在 summary 里如实说。⚠️ 这与下一条是两回事：下一条说的是片子「会静音播放」，这一条是用户「不要人声」。
- **「静音播放」不等于「不要解说词」**：任务描述说片子会静音播放（商品页自动播放的视频 / 电梯屏 / 展会大屏）、甚至写了「无口播」，
  卖点句、要点句、结论句照样写成画外解说员的 `dialogue` 块——静音观众读的正是后期配的台词字幕，没有台词就没有字幕可出。
  ⛔ 不要把每个卖点各做成一张「卖点文字卡」：那是把解说词换了个壳，仍然卡在第 2 问。
- **文字素材不是「后期加字」**：它是一张素材图，视频模型照着这张参考图把它放进画面。`reason` 和 summary 里
  ⛔ 不要写「由后期文字轨呈现」——后期字幕轨只出台词字幕，两件事别混。
- **文字素材是少数几张**：一集里通常 0~3 张，数到第 4 张就回头查——多半是把该说的话做成了卡。
- **没有画面文字需求的戏就正常写**：普通的对话戏、动作戏一处字都不涉及，不用为它列文字素材，也不用在 summary 里提字幕。
- 本次任务描述转述了用户「要加字幕」→ 同样不写进剧本，在 summary 里说明「台词字幕由后期剪辑配，未写入剧本」，由调用方转告用户。

### 台词块就是权威台词源（无独立清单）

台词不抽成独立清单——**每句台词直接建成一个 `dialogue` 块**，`content` 里的 dialogue 块就是台词的「代码可消费权威源」：配音派单按它派台词，下游 `validate_dialogue_coverage` 从 `content.filter(type==='dialogue')` 派生台词清单，跟所有分镜的 video_prompt `{}` 台词做集合差，抓「分镜师写 video_prompt 时漏了某句台词」。**漏建一个 dialogue 块、改一字都会让这道防线失效**。

**每个 dialogue 块三字段**（例：赵天麟冷笑说「就你这穷酸样，也配读书？」）：

| 字段 | 取值 | 例 |
|------|------|------|
| `speaker` | 人名（不含情绪 / 冒号） | `赵天麟` |
| `emotion` | 情绪/动作，无则空串（写全，别只抄一半——「拍胸脯，得意」不要缩成「得意」） | `冷笑` |
| `text` | 台词原文（**照搬，不改字、不加引号、不带人名 / 情绪 / 冒号**） | `就你这穷酸样，也配读书？` |

**铁律**：

- **每句话一个 dialogue 块**：`action` 动作块、`scene_heading` 场次标题块、`narration` 叙述块**不是台词**，不参与台词覆盖、不进配音
- **要念出来的就是 dialogue 块**：在场角色对白 / 角色内心 os（emotion 标 os）/ 具名画外声源（画外解说员 / 播音员 / 系统提示音 / 旁白——speaker 用声源名、emotion 标 VO）——写成别的块型 = 这句话没人配音
- **多人对话场每个说话人的每句都建块**：同一人连说两句 = 两个 dialogue 块
- **顺序 = 剧本时间线**（按块在 `content` 里的顺序）
- **一句不漏**：写完对着剧情逐句点一遍——有几句台词就有几个 dialogue 块。最易漏的是「多人对话场的第 3、第 4 个说话人」（如店家 / 掌柜的圆场话）

## 修订纪律：块 id 三条铁律（改剧本必读）

`update_episode_script` 的 `content` 是**整体替换**——修订时要把**全量块数组**重新传一遍（不是只传改动的块）。但每一块怎么带 id，决定下游分镜引用会不会被无谓打脏：分镜的 `script_block_ids` 按块 id 挂在剧本上，**块 id 不变 ⟹ 引用它的分镜不受影响；改某块只级联引用了该块的分镜**。这是「局部改剧本不用整集重拆镜」的根基。

1. **未改动的块：原样传回**——id、type、text、speaker、emotion 全部一字不动。⛔ 禁止漏传（数组里没有 = 删除该块）、禁止换 id、禁止顺手润色措辞
2. **改动的块：沿用原 id，只改要改的字段**——改台词就动 text / emotion，id 照传。id 不变，引用该块的分镜还能定位到它
3. **新增块：不带 id（省略 id 字段）**，插到数组的目标位置，服务端 mint 8 位 nanoid；**删除块 = 不传**——把它从数组里拿掉即是删除

⛔ **禁止自己编 id**（`blk-9` / `new-1` 这类）——新块一律省略 id 交给服务端；同一次提交里 id 重复整次被拒。
⛔ **先读后写**：修订前必调 `get_episode_script` 拿当前块数组（含每块 id），在它基础上改——凭记忆重写会丢光旧 id，等于整本剧本换新，全部分镜引用变脏。

### 修订示例：改一句 + 插一块 + 删一句

## AI 视频生成经济硬约束（铁律）

**前提**：你写的每一场，下游 AI 视频生成模型会拍成视频，**每秒都烧真钱**（约 ¥0.5-2/秒）。劣质场次 = 经济损失。

### 铁律 1：每场必须含「主体 + 关键动作 + 情绪/信息」三件套

**禁止纯环境空镜**——任何「只有环境、没有角色 / 没有动作 / 没有信息推进」的场次：

❌ **反例**（纯环境空镜）：
```
△ 全景。沧州城外，漫天大雪如撒盐，天地间只剩黑白二色。
△ 远景俯拍，几间破败的草屋孤零零立在雪原中，四周堆积如山的草料。
```

✅ **正例**（带主体 + 动作 + 信息）：
```
△ 林冲倚在草料堆旁，毡笠下眼神疲惫，呼出的白气瞬间消散。
△ 他抬起酒葫芦晃了晃 —— 空了。
```

### 铁律 2：文学化描写删半

「夕阳染起梧桐叶」「射灯冷光映照在深色木质墙面上」「悠扬的口琴声从远处飘来」—— **这些是散文，不是可执行的画面动作**。删掉或改成可执行的画面指令。

- ❌ 「夕阳染起梧桐叶」
- ✅ `【街道 · 黄昏 · 外】` + 后续描写「张三的影子被夕阳拉长」

### 铁律 3：内心独白不要写成一长串多句

角色内心独白（os）点到为止，⛔ 不要连着堆好几句。

✅ 正例：
```
△ 林冲握紧枪杆，眼神冷峻。
林冲（os）：这世道，逼好人做鬼！
```

❌ 反例（多句内心独白堆砌）：
```
林冲（os）：我从小寒窗苦读，本想报国扬名，没想到被陷害发配沧州。
林冲（os）：高太尉，你今日逼我至此，他日必报此仇。
林冲（os）：可是父母年迈，我若死了，谁来侍奉？
```

### 铁律 4：剧本不写景别和镜头手法

景别（特写 / 近景 / 中景 / 全景 / 远景）与镜头手法（推近 / 拉远 / 摇 / 跟拍 / 慢镜 / 快切 / 定格 / 「镜头扫过」「镜头从全景缓缓推至特写」「希区柯克变焦」「镜头 360 度环绕」）都是**分镜师的工作**，不是你的——所有品类一样，广告、电商也不例外。
分镜师要拿着整集的镜头前后排景别（相邻镜头景别要拉开、节奏按品类走），你在单句里写死的「特写」「慢镜」它未必能照办，照办不了剧本就和成片对不上。

**想让观众看清什么，就把那件事写出来**，怎么拍交给分镜师：

- ❌ `△ 特写慢镜：毛巾压上脸颊，汗珠一碰到布面就被吸走。`
- ✅ `△ 毛巾压上脸颊，汗珠一碰到布面就被吸走，布面的纹理看得清清楚楚。`
- ❌ `△ 特写：备注栏写着「学费已缴」。`
- ✅ `△ 他点开最近一笔转账，备注栏写着「学费已缴」。`

**唯一可以写「镜头」的情形：人物直面观众**——「他转向镜头」「对着镜头说」「眼睛看进镜头」。这是表演（人物打破第四面墙跟观众说话，广告口播、号召下单、自述都靠它），不是景别；景别照样由分镜师定。

## 完整正例（雀神争霸赛 EP3，15 秒，纯放弹簧）

⚠️ 注意：
- **2 个场景、3 个场景段、2 次换景**——主场景演到底，换景只有「闪回」叙事跳切这一处（切进闪回、再切回主场景，白名单理由 2），场景数符合 ≤15 秒的场景预算
- 每场都是**台词主导 + 动作伴随**结构
- 台词总量 6 句约 60 字，按标准档语速念约 13 秒，加上动作留白正好铺满 15 秒

（速记展示，一行 = 一个块；落库时按「示例速记约定」还原成块数组——3 个 `scene_heading` 块 + 5 个 `action` 块 + 6 个 `dialogue` 块，共 14 块，全部按剧情时间顺序排；数 dialogue 块即数句）

```
【VIP休息室 · 日 · 内】

△ 张万雀（30岁，西装，「金牌雀神」徽章）抚摸奖杯。

△ 门被踹开，老周（户部侍郎，瘦削三缕长须）扑通跪下。

老周（嘶哑）：皇上！臣找您八年了！

张万雀（皱眉）：你认错人了，老头。

老周（叩首）：臣不敢认错！陛下印记还在！

张万雀（瞳孔骤缩，低声）：你叫我什么？

【金銮殿 · 日 · 内 · 闪回】

△ 龙椅、金銮殿，张万雀身穿龙袍俯视群臣，画面一闪而过。

老周（os，颤抖）：江山危矣，请陛下回宫！

【VIP休息室 · 日 · 内】

△ 画面切回。老周展开泛黄圣旨，双手颤抖。

△ 张万雀缓缓起身，捡起飘落脚边的圣旨。

张万雀（眼神骤变）：朕……回来了。
```

换景逐段检查：场 1 → 场 2 是「闪回」标记（叙事跳切 ✓）；场 2 → 场 3 是闪回结束回到主场景（同一叙事跳切的回程，开头 action 块写明「画面切回」✓）。没有任何无理由硬切。
