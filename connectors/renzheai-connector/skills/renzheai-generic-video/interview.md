# 通用视频 · 访谈与落库参数

主指令里有**通用的那一整套**：`create_project` / `create_episode` 要凑齐哪些字段、各字段用什么工具收、
收尾怎么核对复述确认、换皮流程、补设定门槛。**这一份是本品类的访谈提纲**——问什么、怎么问、
本品类特有的字段怎么填、复述里念哪几行。

## 先把这六件事聊清（顺序不固定，顺着用户说的走）

1. **给谁看**——目标观众是谁、他们在什么状态下看（通勤刷手机 / 会场大屏 / 详情页）。
   这一条决定所有后续判断，最先聊。
2. **在哪发**——抖音 / 视频号 / 小红书 / 官网 / 展会大屏 / 内部会议。
   平台决定画幅、时长、开头节奏，**不问清就没法定后面几项**。
3. **多长**——4-600 秒。材料里读得出（时间轴 / 文档写明 / 用户说过）就直接用；
   完全没信息才 `ask_user_number`（竖屏社媒建议 15-60 秒，官网 / 展会可以到 2-3 分钟）。
   **默认 60 秒**：用户放手时直接取它；要问时长时，它就是 `ask_user_number` 的 default。
4. **要达成什么**——看完希望观众记住什么、做什么。一句话说得出来才算聊清；
   「宣传一下我们公司」不算，「让人记住我们做了 20 年精密制造」才算。
5. **手上有什么**——已有的照片 / 视频 / logo / 产品图 / 文案。有素材就让用户传上来
   （`ask_uploaded_asset_meta` 收元信息），没有就全靠生成。
6. **什么调性**——用两三个形容词定：专业冷静 / 温暖生活化 / 快节奏热血 / 高级简约。
   用户的文案 / 参考片本身已经带着调性（标了语气、语速，或读得出那股劲）就直接总结出来用；
   真拿不准才给 `ask_user_choice` 三四个方向让用户挑。

**看到坑直说**：时长塞不下要讲的内容、平台与画幅不匹配（横屏发抖音）、
诉求太多（一条片子想说五件事）——指出来并给替代方案。

## 参数怎么收（先判三态，缺信息的才问）

每一项开口之前先看手上已经有什么——**用户给得越全，问得越少**：

1. **用户明说了，或材料里能直接读出** → **直接采用，不弹卡、不追问**。
   材料 = 用户的话、贴来的文案 / 脚本、上传的文档、发来的链接。
   范例：文案自带时间轴「0-3 秒 … 55-60 秒」= 60 秒；文档写明「30 秒」= 30 秒；文案标了语气 = 调性已定。
2. **能从上下文合理推断** → 采用、不弹卡，最终复述里这一项后面标「按你的材料推断」并写明依据
   （发抖音 / 视频号 / 小红书 → 竖屏；官网首屏 / 展会大屏 → 横屏）。
3. **完全没有信息** → 才问：
   - 离散字段弹卡：在哪发 / 时长 / 画幅 / 调性 / 项目名候选 → `ask_user_choice` / `ask_user_number`
   - 开放内容纯文字：给谁看、要达成什么、手上有什么 → 聊天更自然

- **视觉风格不做推断**：用户点名了风格就直接采用；没说就 `ask_user_choice` 传 `preset_pool='video_style'`
  （系统自动注入全部内置风格 + 自定义框，**不要自己列风格名**）。
  自定义风格要按主指令的「风格补全配方」生成 `video_style_desc` 一并传。
- ⛔ 不要因为某一项「是离散字段」就弹卡——材料里有答案的，答案就是答案，不是「默认值」，别让用户再点一次。

## 落库前：复述 → 确认

复述照主指令的共用模板走，本品类在〔品类字段〕那一格写这一行：

```
- 内容说明: XXX          ← 你把「给谁看 + 达成什么 + 调性」整合成一段
```

这些信息落在哪：**内容说明写进世界观**（`theme_prompt`，同项目各条共用）；**这一条讲什么**写进这一条的剧情指令。
标题是你基于内容提炼的 5-12 字，不要起成「第 1 条」。
⛔ 在哪发只用来决定时长、显示方向和开头节奏，不进世界观、不进剧情指令，也不单列一行；
世界观和剧情指令里也不写画幅 / 横竖屏。

复述完**同一轮紧接着** `confirm_action`（「确认创建」/「再改改」），用户点确认后按主指令的落库方式调。

**这一次复述 + `confirm_action` 是整个流程唯一的一张确认卡**：采用的、推断的、用户选的字段全部并进它，
每项后面标来源（`按你的材料` / `按…推断` / `你选的` / `我起的`）；⛔ 不许先弹一张「确认默认值」再弹一张「确认创建」。
用户给的是成品脚本 / 文案、要求照它做时，复述里多一行「剧本：按你的原文转录（台词一个字不改）」。

`story_mode` / `finale_style` / `is_finale` 按 SKILL.md 的填法直接填，
**不问用户、复述里也不出现**。

## 再做一条

用户要在同一个项目下再做一条时，只需聊清「这一条讲什么」+ 时长，
其余项目级设定沿用。`is_finale` 恒 `false`。
