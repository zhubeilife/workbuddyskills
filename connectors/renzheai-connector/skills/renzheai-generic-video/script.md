# 通用视频 · 脚本细则

剧本师主指令里已有**平台机制 + 通用编剧手艺**：工具怎么调、产出形态、块 id 纪律、
台词法则（信息前置 / 动作可视化）、人设与配角格式、换皮重制、自检与合规。
**这一份只有本品类特有的东西** —— 别在这里找台词怎么写、人物怎么立。

## 先判断是哪一种脚本

看项目设定里「要达成什么」，落到下面三种之一：

| 形态 | 什么时候用 | 骨架 |
| --- | --- | --- |
| **解说驱动** | 讲清一件事（科普 / 流程 / 企业介绍） | 提出问题 → 分点讲清 → 收束落点 |
| **场景驱动** | 呈现一段真实过程（纪实 / 跟拍 / 实况） | 起始状态 → 关键节点 → 结果 |
| **诉求驱动** | 让观众记住一件事并行动（推广 / 招募） | 抓住注意 → 给出理由 → 明确下一步 |

拿不准就选**解说驱动**——它最稳，任何题材都能用。

## 无论哪种，这四条都成立

1. **前 3 秒必须有一个具体的东西**：一张脸、一个动作、一句反常识的话。
   ⛔ 不要用「在这个快节奏的时代」这类空转开场。
2. **一条片子只讲一件事**：把用户列的五个卖点压成一个主诉求 + 两个支撑点。
   用户在材料里坚持全都要，你照样压成主次去写（五件事的片子观众一件也记不住），
   并在 summary 里写一句压成了哪一主两辅，由调用方转告用户。
3. **每一段都要能被看见**：写进脚本的每句话都要有对应的画面。
   写不出画面的句子（「我们始终坚持品质」）就是废话，删掉或换成能拍的事实。
4. **结尾给落点**：解说型给结论，场景型给结果，诉求型给下一步动作。
   ⛔ 不要留悬念钩子——这类内容观众通常只看这一条。

## 台词 / 解说词怎么写

- **口语化**：写完念一遍，拗口就改。书面语在语音合成里会变得更僵。
- **按语速估时**：严格按「台词语速三档」那一节的尺子折算，别凭感觉。
- **具体优于抽象**：「20 年」「3000 家门店」「返修率 0.2%」比「值得信赖」有力得多。
  用户没给具体数字就别自己编——换成不需要证明的说法，并在 summary 里列出缺哪些数字，由调用方去问用户。

## 这类片子常撞上的「画面上的字」

口播、科普、介绍类片子最容易觉得「本来就该有字」，这几种都照通用细则「画面文字」的四问走（以下是例子，不是清单）：

- **重点词 / 关键词要突出** → 靠解说词的说法和语气去强调（短句、停顿、重复），配一个能看懂的画面演示；
  ⛔ 不做一排关键词卡，也不写「关键词弹出」——那是成片导出后的包装活，不进脚本。
- **分点讲（一、二、三）** → 序号由解说词带出（「第一个误区……」），不为每一点做一张数字卡。
- **增长数据 / 对比数据** → 数字进解说词，画面拍「变化本身」（前后对比、规模变化）；确实要上画面的，最多一张写着终态数字的静态数据卡。

## 素材清单列什么

- **场景通常 2~4 个**。
- **实物只列画面上真的出现、要给特写的。**
- **没有具体人物就不列人**，别为了凑数造角色。
- **有解说词就为解说的说话人列一条音色**；没有任何人声的纯画面片子不列。
- ⛔ 不列：只在解说词里被提到、画面上不出现的东西；一次性群演；
  用户没提供、也没法从项目设定推出来的具体人或物——**宁可不列，也不要编一个**。

## 什么不该做

- 不要设计人物弧线与情节反转（那是剧情类的活）；
- 不要留跨条悬念；
- 不要在没有素材依据的情况下描述具体的人 / 地点 / 数据。
