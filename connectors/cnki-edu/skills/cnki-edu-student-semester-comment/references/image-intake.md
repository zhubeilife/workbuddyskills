# 图片材料录入规范（截图 / 照片）

用户不会总有导出好的 Excel。他手上更常见的是一堆：成绩单截图、班级成绩趋势图、
拍下来的奖状、教师手写的纸条、作业统计的屏幕照片。

本文件规定这些图片**怎么进链路**。它是 `SKILL.md` Step 2 的前置步骤。

---

## 一、核心口径：图片是「录入通道」，不是「第七类材料」

这是本文件最重要的一句话，决定了后面所有细节：

> **图片不新增材料类型，它只是把材料"录进来"的一种方式。**

链路只有一条，图片没有特权也没有捷径：

```
图片 → （AI 读图转写）→ 一份标准表（xlsx/csv）→ prepare_roster.py → roster.json → 成文
                        ↑ 从这里开始，与原链路**完全一致**
```

三个直接推论：

| 推论 | 说明 |
|---|---|
| **转写之后，图片就没有特殊性了** | 匹配、防串人、缺失统计、小贴士、查重……全部照原样走。不要为"图片来的数据"写任何特殊分支 |
| **脚本不吃图** | `prepare_roster.py` 收到 `.png/.jpg/.pdf` 会**友好拒绝**并告诉你先转写（不会抛 openpyxl 的 "not a zip file" 那种看不懂的错）。读图是 AI 的活，不是脚本的活 |
| **转写质量决定一切** | 后续所有环节都假设"表是对的"。读错一个数字，评语里就会出现一个假事实，而且是**最像真的那种假**——因为它看起来来自材料 |

## 二、四类图片，各自的转写目标

| 图片类型 | 怎么认 | 转写成什么 | 传给谁 |
|---|---|---|---|
| **成绩表格截图** | 有清晰的行列线、表头、姓名列与各科分数 | 标准成绩宽表：`学号/姓名 + 各科 + 总分 + 班级排名`（列名照原图写） | `--scores` |
| **成绩趋势图**（柱状/折线/雷达） | 只有图形与坐标轴标签，没有逐行数字 | 只转写**图上明确标注了数字**的那些；未标注的一律留空（见 §三-3） | `--scores`（当平时趋势）或只作定性参考 |
| **统计截图**（作业/课堂） | 表头含 应交/实交/按时提交率 / 发言/专注/合作/纪律 | 对应统计表，列名照原图写 | `--homework` / `--classroom` |
| **奖状 / 证书 / 荣誉榜** | 有「奖状/证书/荣誉」字样、颁奖单位、学生姓名 | 荣誉清单：`学号/姓名 + 荣誉奖项`，**一条一行** | `--awards` |
| **教师手写描述照片** | 手写文字（纸条、评语本、便签） | `学号/姓名 + 教师描述` | `--notes` |

> 一叠图混着来是常态（成绩截图 + 两张奖状 + 一张手写纸条）。分门别类转写成
> 2~3 个文件后一起传即可，脚本本来就是多输入并行的。

## 三、三条硬口径（每条都对应一类真实事故）

### 1. 回读确认：转写完成先给用户看，确认后才进 Step 2

读图是"人眼转述"，比导入 Excel 多了一层出错机会，而且**错了看不出来**。
所以转写结果必须先回读：

```
我读到的内容，请核对一下（尤其姓名和数字）：

【成绩截图 3 张】共 12 人
| 姓名 | 语文 | 数学 | ... |
| 陈雨欣 | 92 | 94 | ... |
...

【奖状 6 张】共 6 条
| 姓名 | 荣誉 | 我读到的原文 |
| 陈雨欣 | 校级三好学生 | 「...2026年6月，校级三好学生...」 |

【手写描述 1 张】共 1 条
| 姓名 | 描述 |
...

有几处我不确定（照片有反光/字迹潦草），已留空：
- 第 3 张成绩截图，「陶思睿」的英语：像是 88，也可能是 86，请确认
- 第 5 张奖状，落款日期看不清，留空

确认或订正后我就接着往下做。
```

**必须回读的三样**：姓名、数字、单位（分数/名次/级别）。其余可以合并成一行说明。

用户说"你就按你读的做"时，照做，但把「未回读确认」写进交付说明。

### 2. 读不出就留空，绝不猜

模糊、遮挡、反光、字迹潦草、被裁掉一半的单元格 —— **一律留空**。

留空是「无数据」，下游会正确地把它当缺失处理（不算 0 分、不进评语）；
猜错是往评语里写假事实，而且是最难发现的一类假。

不许做的事：靠"这列分数应该差不多"补齐、靠上下文推一个数、把模糊的 8 读成 6 再按"合理"改回来。
**能读成两个以上可能的，就报给用户让他看一眼**——他手上有原图，两秒钟的事。

### 3. 图上没标注的数字，不当分数用

柱状图的高低、折线图的斜率只能得出**趋势**，不能得出**分数**：

| 图 | ✅ 能写 | ❌ 不能写 |
|---|---|---|
| 数学成绩折线图，一路上行 | 「数学这一路看下来是一次比一次稳」 | 「数学考了87分」 |
| 三科柱状对比，语文柱最高 | 「语文是你三科里最稳的一科」 | 「语文92，数学85」 |
| 班里名次柱状图，柱子越来越短 | 「名次一直在往前走」 | 「排名从第12进到第5」 |

判据只有一条：**这个数字在原图上是以数字形式写着的吗？**
是 → 可以转写；不是 → 那它只是你从图形高度"估"出来的，属于虚构（违反接下去的规则 2）。

> 唯一例外：图上直接标了数值标签（柱顶写着 87）。那它就是"以数字形式出现"，
> 可以转写——但仍要走 §三-1 的回读确认。

## 四、转写模板（照抄这几列名，脚本的识别规则就能认出来）

**成绩表**（人名 + 各科；学号没有就整列不要，脚本会改以姓名为主键）
```csv
学号,姓名,语文,数学,英语,总分,班级排名
20240301,陈雨欣,92,94,88,274,3
```

**作业统计 / 课堂统计**（列名照原图，别自己改叫法）
```csv
学号,姓名,应交次数,实交次数,按时提交率,订正完成率
```

**荣誉材料**（`--awards`）——一条一行，级别与时间**并入同一格**
```csv
学号,姓名,荣誉奖项
20240301,陈雨欣,校级三好学生（校级，2026年6月）
20240301,陈雨欣,区青少年科技创新大赛三等奖（区级，2026年5月）
```
为什么级别与时间要写进同一格：脚本认的是「一列荣誉文本」，一条一行会自动用空格合并；
拆成多列时它只会取**一列**（列名含「奖项/荣誉」的那列，都没有时取最长文本列），
级别和时间会安静地丢掉。

**教师描述 / 往年评语**
```csv
学号,姓名,教师描述
20240301,陈雨欣,跑完八百米还回头给同学递水。
```

> 学号可以留空：**奖状上本来就没有学号**。附表里某一行学号为空时，只要那个姓名在名单里唯一，
> 就能按姓名接上（整表都没有学号也行）。但如果姓名写错了（同音/错字），**只有在该行没有学号时**
> 才会尝试近似匹配并列入「疑似同一人」；填了学号的行写错姓名只会提示「姓名不一致」、不会自动纠正。
> 另有两条硬约束在**成绩表**上：整表必须有学号（不能一半有一半没有，会报错），
> 且不能有重复学号。

## 五、几个容易踩的边界

- **一张图里不止一个学生**（拍了一整栏成绩单）→ 按行拆成多行，不要只写第一个
- **奖状没有学号**（奖状上当然没有学号）→ 只有姓名列即可，走姓名匹配；
  重名时脚本会报「疑似同一人」，这时**必须问用户**，不要自己认
- **奖状上的名字与名单不完全一样**（「陈雨鑫」vs「陈雨欣」）→ 与教师描述表同一条规则：
  按学号归一（有学号时），并进「姓名冲突」待人工核对
- **奖状日期很老**（小学时期、去年）→ 照样进来，但成文时只当"稳定特点"的佐证，
  不写成本学期新发生的事（见 `writing-rules.md` 规则 2 的荣誉例外）
- **图片是长截图**（手机滚动截了一张超长成绩表）→ 按行读全，不要只读第一屏；
  读不完就分块读，最后合并
- **同一张图被重复上传** → 转写后自己按「姓名 + 内容」去一次重，别让同一条荣誉进来两遍
  （`prepare_roster.py` 对完全重复的记录会自动去重并提示，但别指望它兜底）

## 六、隐私

奖状照片、成绩截图里都是**未成年人个人信息**（姓名、照片、学校、身份证号后四位都可能出现）。

- 只在本机处理，不上传任何在线文档
- 转写出的中间表（`示例_奖状荣誉.csv` 之类）用完提醒用户自行删除
- 最终回复里附回读清单是必要的（用户要核对），但**不要把成绩明细原样贴进交付说明**
