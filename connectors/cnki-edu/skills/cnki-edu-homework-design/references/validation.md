# 三层验证：这套东西到底合不合适

## 一、顺序不能反

```
L1 技术验证（自己跑）→ L2 质量验证（教研员盲评）→ L3 价值验证（教师试用）
```

**一上来就找老师试是最贵的错。** 一个低级 bug（比如小学低段出了书面题）就能毁掉教师对整套东西的信任，
而这种 bug 你自己跑 30 组参数就能抓到。

设**一条一票否决**：答案错误率 > 0 → 直接判不可用，不进下一层。

---

## 二、L1 技术验证（0.5–1 天，自己做）

跑 **30 组用例**：6 学科 × 4 学段全组合 + 6 个边界用例。

**L1 真正要验的不是"能不能跑通"，是"规则有没有真触发"。**
构造必被拦的用例去看它拦不拦：超时长、书面红线、`gen_cap=0`、题库无覆盖。
写完校验器却从没见它拦过东西，等于没写。

记录字段：用例ID / 学科 / 学段 / 题量 / **预期结果** / 实际结果 / 是否一致 / 耗时 / 拦截项。

---

## 三、L2 质量验证（3–5 天，教研员 2–3 人）

**盲测**：AI 题 / 教师原题 / 其他来源题各 20 题混编，评委不知道哪道是哪组。

| 维度 | 权重 | 说明 |
|---|---|---|
| 科学性（答案正确） | 一票否决 | 错了直接 0 分，整组不可用 |
| 课标对齐 | 高 | 是否真绑定了课标条目，还是套话 |
| 分层合理性 | 中 | 难度标签与实际认知负荷是否匹配 |
| 情境真实性 | 中 | 数据/事件是否真实可查 |
| 语言规范性 | 中 | 分句长度、用词是否适合该学段 |
| 教学价值 | 中 | 这题值不值得学生花时间做 |
| 溯源真实性 | 高 | **见下** |

### 两项必须人工做，自动校验查不出来

1. **随机抽 20 条 `sources` 真的去 CNKI 检索一遍。**
   编造的溯源比没有溯源更糟——它是整套差异化的地基，塌了就什么都不剩。
2. **`adapt` 题与候选题干做相似度比对，>80% 判照抄不合格。**
   照抄是最容易偷懒的地方，也是"AI 改编"这个功能最大的信任风险。

> **自动校验已堵住两个最容易被钻的空子（2026-10 修复）：**
> - 结构级依据校验**不再依赖 `--plan`**——不传计划时，缺 `origin` / 缺 `source_id` / 缺 `based_on` / 缺 CNKI 文献的题同样会被拦，杜绝"无计划就放行纯 AI 编造"。
> - 传了计划后，声明的 `source_id` / `based_on` 必须与计划里真实抓取的候选题 `bank_id` 对得上，引用计划外或编造编号会被直接拦截。
> 但 `generate` 题的 CNKI 文献 `sources` 是否真实，脚本仍无法自动核验，**第 1 条人工抽检（随机抽 20 条去 CNKI 实检）依旧不可省**。

## 四、L3 价值验证（1–2 周，在职教师 5–8 人）

真实备课场景试用。记录：生成后被改动多少处 / 改了哪些地方 / 最终接受率 / 相比自己出题节省多少时间 / 愿不愿再用。

**最有价值的信号是"教师改了什么"，不是分数。**
如果 5 位老师都在改同一处（比如都说情境不接地气），那就是下一版必修的点。

---

## 五、判定标准

**流程稳定跑通 + 答案零错误 + 编辑率 ≤40% 且愿意再用 = 合适。** 缺一条都不算：

- 跑得通但答案有错 → 不敢用
- 答案没错但要改一半 → 省不了时间
- 都好但不想再用 → 没价值

关键指标：

| 指标 | 通过标准 | 是否一票否决 |
|---|---|---|
| 答案/解析错误率 | = 0 | **是** |
| 政策红线（书面/时长） | 拦截率 100% | **是** |
| 溯源真实率 | ≥ 95% | **是** |
| 课标对齐率 | ≥ 90% | 否 |
| 照抄率（adapt） | ≤ 5% | 否 |
| 编辑率 | ≤ 40% | 否 |
| 教师接受率 | ≥ 70% | 否 |
| 耗时节省率 | ≥ 50% | 否 |
| 愿再次使用比例 | ≥ 70% | 否 |

无依据的数据一律用【待补充】占位，**不要补一个看起来合理的数字**。

## 六、配套评分表

评分表自己搭即可，四张表够用：

| 表 | 用途 | 预置内容 |
|---|---|---|
| L1 自测 | 自己跑通用例 | 30 组用例 + 预期结果 |
| L2 盲评 | 教研员验题 | 60 题分组，隐去来源 |
| L3 试用 | 教师试用记录 | 8 人试用记录 |
| 判定标准 | 统一口径 | 18 项判定标准与指标定义 |

需要多人评审时，**先出一版给评委看的盲评说明**（一页纸，写清每个维度怎么打分、什么叫"课标对齐 4 分"），
否则多人口径会散，数据没法用。

## 七、常见误判

| 现象 | 真因 | 怎么修 |
|---|---|---|
| L1 全组通过，但 L2 分数很低 | L1 只验了"能不能跑"，没验"规则有没有触发" | 补边界用例，确认拦截真的发生 |
| L2 分数高，L3 教师不买账 | 评委是教研员视角，不是一线教师视角 | L3 看"改动点"，别看满意度满分 |
| 三组均分差不多 | 盲评分组泄漏，或 AI 组和他源组本就同源 | 重申保密，增加"教学价值"维度区分度 |
| 校验一直绿 | 校验器没接上，或 plan_json 没传进去 | 故意造一道错题看它能不能拦 |
