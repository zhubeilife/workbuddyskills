# 混合供给：真题原样选用 / 改编变式 / 原创生成

## 一、结论

「作业设计的题从哪来」不是原创和检索的二选一，而是三档混合，且**配额跟着作业用途走**。
把这三档当互斥单选，会让教师永远拿不到一道能原样布置的真题。

| 档 | origin | 什么时候用 | 标注要求 |
|---|---|---|---|
| 检索原题 | `retrieve` | 知识点成熟、题库有覆盖、难度情境都匹配 | 必填 `source_id` + 原题出处，**题面一字不改**，**不挂学术溯源**（直接取用原题不须走文献接口） |
| **AI 改编** | `adapt` | 有题但难度/情境/数据不匹配本班 | 必填 `based_on` 且不得照抄题干；**另必填 `answer_check` 一致性验算**（阻塞级） |
| 原创生成 | `generate` | 题库无覆盖，或需新情境/时事/跨学科/真实数据 | 必填 CNKI `sources` |

**默认 `supply=mix`，配额按作业用途取值**，详见下节。三档从来不是三选一。

---

## 一·五、配额跟「作业用途」走（这是本节的核心）

判断供给结构只需要一个问题：**这份作业要不要拿去打分。**

- 作业的目的是「学会」，不是「区分」。学生见到考过的真题不是缺点——真实难度、真实设问、答案已被考试校验，这三点恰恰是教师最看重的。
- 只有承担评价功能（周测/月测/单元测验）时，学生见过原题才是事故：成绩失真、无法横向比较。

| job_type | 原题 | 改编 | 原创 | 依据 |
|---|---|---|---|---|
| 课前预学 | 70% | 20% | 10% | 摸底不需打分，真题是最可信的基线 |
| 课后巩固（默认） | 40% | 50% | 10% | 刚讲过同构例题，需变式防照抄，但留真题对标真实难度 |
| 单元作业 | 35% | 50% | 15% | 真题交代真实考查方式，改编担梯度 |
| 阶段测验 | 10% | 60% | 30% | 唯一必须压制原题的场景 |
| 备考复习 | 65% | 30% | 5% | 熟悉真题本身就是备考内容 |
| 错题重做 | 5% | 75% | 20% | 同考点二刷，留原题等于背答案 |

简称映射（`JOB_ALIAS`）让教师说「单元」「周测」「错题」也能命中，不必说全称。

**三者各自的真实成本**（决定了配比为什么不是均分）：

| 档 | 优势 | 风险 |
|---|---|---|
| `retrieve` | 答案经考试校验、考点被证明考得到、拿来就能印 | 学生可能做过；只能用于练，不能用于评 |
| `adapt` | 拿到原题的质量底座，又解决"不是为我班出的" | 改数据不改成答案是最贵的错——错一次就不再信任 |
| `generate` | 安全、贴合校情、可用 CNKI 素材做差异化 | 没经过任何教学验证，难度漂移，成本最高 |

所以 **改编不是用来替代原题的，是给真题派生变式**（分层作业的 B 卷、错题隔周二刷）；
真题与改编是 1:N 的父子关系，不是互斥关系。

## 一·六、新鲜度：真题不是越老越好用

题库 `Label` 里那串「2026秋•昌吉州校级月考」会被 `parse_paper_label` 拆成结构化信息，作业单上印成人话：

| 拆出来的字段 | 例 | 为什么教师需要它 |
|---|---|---|
| 新鲜度 | 当年题 / 近3年 / 5年内 / 5年以上 | 判断贴不贴近当年命题趋势 |
| 考试类型 | 中考真题 / 期末卷 / 月考题 / 模拟卷 / 开学考… | 校级月考与中考真题含金量完全不同，笼统写「真题」是把信息扔掉 |
| 适用范围 | 校级 / 区县级 / 市级 / 全国统考 | 决定这份作业的难度能不能对标外面 |
| **新旧课标** | 早于 2022 版课程方案（高中为 2017 版课标 2020 年修订） | **最关键的一条**：早于此线的真题可能基于旧教材、考法已变，必须人工核对 |

最后一条是整套链路里唯一能被机器自动发现的位置，所以做成了显式提醒。
**年份都标不出来的题源，等于无法判断它今天还能不能用**——应回查题库补齐，而不是默认可用。

## 一·七、让形式与数量都可改：逐题指认 + 变式包

配额是统计意义上的默认值，真正懂本班的是教师。所以留两个口子：

**① 逐题指认 overrides**（改某一题，不必全盘切换作业用途）

```json
"overrides": {"2": "retrieve", "5": "generate"}
```

指认优先于配额；动到配额时计划里会多一行「配额调整」把改动讲清楚。题号越界或档名非法的写进
`overrides_invalid`，**不静默吞掉**——教师改了却没生效，比不给这个功能更糟。

**② 一题多变式包 variants**（同一考点需要多次训练时用）

```bash
python scripts/homework_kit.py variants --bank bank.json --bank-id Q07 --n 3 --out-plan variant_plan.json
python scripts/homework_kit.py variants --items items.json --id 4 --kinds retune,reverse
```

| key | 名称 | 改什么 | 建议分层 | 典型用途 |
|---|---|---|---|---|
| `retune` | 同构换数 | 只换数值与对象名 | 与母题同层 | 隔周二刷：检验真会还是背答案 |
| `rescene` | 换情境 | 保留考点换成真实情境 | 与母题同层 | 分层作业 B 卷 |
| `reverse` | 逆向设问 | 求 A → 已知 A 求 B | 升一层 | 拓展层出区分度 |
| `recondition` | 增减条件 | 删掉/增加一条条件 | 拓展 | 练审题与建模 |

产出是**全 `adapt`、`gen_max=0`** 的计划，结构与主计划同形，可直接喂给 `validate --plan` 走第 13 条逐题比对。

## 一·八、改编答案为什么要强制验算（第 14 条）

`adapt` 的路径是：先拿到一道答案已被考试校验过的题，再改它的参数或情境——**改完原答案就失效了**。
模型在这里最容易偷懒：只改 `stem` 不改 `answer`。而这类错误一次就足够让教师弃用整套东西。

所以第 14 条要求三件套，且是阻塞级而非提醒级：

```json
"answer_check": {"changed": ["把 2 kg 改成 4 kg"],
                 "recompute": "G=mg=4×10=40 N，故浮力为 40 N",
                 "verdict": "一致"}
```

| 情形 | 判定 | 理由 |
|---|---|---|
| 缺 `answer_check` 或三字段任一为空 | **拦** | 没验算 = 答案可能是原答案 |
| `verdict` 不是「一致」 | **拦** | 承认了改编数据不成立，就别往外发 |
| `changed` 为空 | **拦** | 没列改动项 = 可能压根没改，那不是改编 |
| 答案数值在 `recompute`/`analysis` 中找不到 | 提醒 | 可能是正常表述差异，人工看一眼即可 |

写出来还有一个副作用收益：教师复核时能顺着 `recompute` 查，不必自己动手重算。
这条原本藏在模型脑子里的判断，现在是作业单上印着的一行字。

> **历史产出会被这条拦**：上线前生成的 `items.json` 没有任何验算记录，重跑校验必然失败。
> 这正是要抓的东西。要么用新 prompt 重跑让模型真正重算一遍，要么逐题人工复核后回填；
> **编一条假验算让它"通过"是最不能做的事**——那等于把整套校验器变成摆设。

## 二、为什么不能纯原创

| 风险 | 后果 |
|---|---|
| 答案/解析出错 | 作业直接进课堂，出错就是教学事故 |
| 没经过教学验证 | 生成题没有"这道题学生会在哪错"的实践积累 |
| 教师不信任 | 老师天然更信"能查到出处的题" |
| 成本 | 每题都调模型，慢、贵、质量还不稳 |

## 三、为什么不能纯检索

| 局限 | 后果 |
|---|---|
| 覆盖缺口 | 新教材、新时事、跨学科、校本情境，题库里没有 |
| 无法个性化 | 题库题不是为"我这个班"出的 |
| 没有差异化 | 大家都检索，最后拼的是题库大小，知网没有优势 |
| 情境陈旧 | 题库情境老化，学生做过就失效 |

## 四、改编为什么是主力

它同时拿到两边的优点：**有原题的质量底座**（答案已被验证过），**又解决"这道题不是为我班出的"这个真痛点**。
成本和风险都最低，教师接受度也最高。

---

## 五、知网在这三档里的位置

题库谁都能建，但 **CNKI 是"生成题的原材料"**：期刊里的真实数据、真实案例、史料、实验方案。

所以原创题可以这么立得住：**题是新的，但素材是真的、可溯源的。**
这才是"敢用原创题"的底气，也是区别于纯题库产品的关键。

## 六、路由算法

```bash
python scripts/homework_kit.py route --params params.json --out-plan plan.json
python scripts/homework_kit.py presets     # 查看六类作业用途的配额预设
```

路由算法（6 步）：

1. 读 `job_type` → 取 `JOB_PRESETS` 配额；若教师显式给了 `gen_cap`，则锁死原创额度、其余按比例分给真题与改编
1b. 读 `overrides` → 逐题指认优先占用该档名额（题号越界/档名非法的记录下来，不静默丢弃）
2. 按 `ratio` 把 `total_count` 拆到三层：`基础 3 : 巩固 3 : 拓展 2`（例：8 题 4:4:2）
3. `_split_quota` 用**最大余数法**把三档配额砍成整数，保证三档之和**严格等于**题量（用 round 会差一题）
4. 逐题分配：每层按自己的 mode 偏好顺序（`LEVEL_MODE_ORDER`）取一个还有余额的档
   - 基础层 `retrieve › adapt › generate`　巩固层 `adapt › retrieve › generate`　拓展层 `adapt › generate › retrieve`
   - 原题天然偏基础（单点、答案稳定），原创偏拓展（新情境），改编兜中间
   - 这一步只决定「同配额下原题落在哪一层」，总配额是硬的，不会被挪动
5. 该档题库无候选 → **降级为 `generate`**，并自动放开原创上限（否则校验器会把"客观无题可选"误报成"超配额"）
6. 小学低段命中 → **强制全部 oral**（政策红线直接压到供给层）

输出 `plan_text` 给 LLM 看（含候选题干原文），`plan_json` 给校验器比对——内含 `supply` / `job_type` / `quota` / `degraded`。

> **前提**：题库元数据必须带 `level`（难度档）、`bank_id`、`label`（试卷出处），
> 否则路由无法按分层匹配，`retrieve` 题也印不出真实出处。

### `retrieve` 题的三条硬要求（这是 mix 档最容易做的歪路）

1. **题面、选项、设问、数据一字不改**——"拿来就能布置"是它唯一的立身之本，擅自润色等于取消这一档
2. 模型只补四项：课标绑定、认知层级标注、估时、解析；答案沿用原题
3. 发现原题疑似有误 → **降级为 `adapt` 并在 `meta.notes` 说明**，不得自行改题面

第 13 条校验会拦「计划写 retrieve、输出却是别的 origin」，第 14 条会拦「改编没做答案一致性验算」。

相关子命令：`variants`（拿一道真题派生变式包）、`presets`（打印配额表）。

> **注意**：正因为 retrieve 一字不改，**底座选错的代价远大于 adapt**——改编时模型还能顺手改掉
> 不适合的部分，原题没有补救机会。mix 模式下要更严地人工审底座知识点。

## 七、真实跑出来的结果（已复跑验证）

同一份初二物理《浮力》题库（30 条真題），只改 `job_type`，8 题 4:4:2：

| job_type | 配额 原/改/创 | 实际分布 |
|---|---|---|
| 课后巩固 | 3 / 4 / 1 | `retrieve`×3 `adapt`×4 `generate`×1 |
| 单元作业 | 3 / 4 / 1 | 同上（8 题规模下 35% 与 40% 取整后相同） |
| 阶段测验 | 1 / 5 / 2 | 原题被压到 1 道 |
| 错题重做 | 0 / 6 / 2 | 原题归零 |
| `supply=retrieve` | 8 / 0 / 0 | 全部真题 |

几件值得记住的事：

- **改一个词，整份作业的形态就变了**——这正是必须问用途而不是问"要几道题"的原因。
- **8 题规模下 35% 与 40% 会撞车**（都是 3 题）。题量少于 10 时别向教师强调百分比，直接说题数。
- **没有题库时**：全部降级为 `generate`，`plan_json.degraded` 会写明"题库候选不足，N 道题降级为原创"，
  同时 `gen_max` 自动放开到实际值——校验器不会再把"客观无题可选"误报成"教师超配额"。
  这是旧版会误伤的地方。
- **`gen_cap` 与 `job_type` 同时给时，`gen_cap` 优先**（锁死原创额度，其余按预设比例分给真题与改编）。
  交付说明里要写清哪一个真正生效了。
