# 试卷与解析 · 排版标准 v1.6

> 依据 4 份样例卷实测（2022 北京中考化学 / 2026 绥化中考物理 / 2026 绥化中考英语 / 鲁教版九上数学单元卷，通过本地 editor_sdk 读取，非目测）。
> **结论：4 份同属一套版式族**——页面参数逐项完全一致。故本标准可统一套用，作为 AI 组卷「S7 排版与导出」的落地规范。
>
> **v1.6 变更（2026-10-09）**：解答题**题图位置**统一——
> 题库把题图**直接内嵌在题干 HTML 里**、且位置随机（有的在最前、带 `float:right`；有的在最后）。解答/计算题统一重排为「**题干叙述 → 图（居中）→ 小问（1）（2）…**」：渲染器新增 `extract_stem_figs()`（抽出题干里的 `<img>`）+ `split_at_first_subq()`（在首个小问标号处切开叙述与小问），`_render_q_body()` 按此顺序输出。其余题型（选择/填空/作图/实验）不改版式（题干原样 → 图 → 选项）。
>
> **v1.5 变更（2026-10-09）**：修复**解答/计算题小问不换行**的产物级缺陷——
> 题库正文里 `（1）（2）…` 小问常与题干挤在同一行（有时用 `<br />` 分隔、有时直接用标点相接）。渲染器 `split_subq()` 需把每个小问拆成独立行；**关键坑**：
> ① **不能无脑替换 `（N）`**——题干里存在"阳光小学五（2）班""（1）班"这类**校园称谓**，误判会把它拆行。判据须为：标号在**段首** / 紧邻 `<br />` / 前一字符是句末标点（**含收尾括号 `）`**，覆盖"…（均填"a"或"b"）（2）…"）/ 前一字符是 `>`（紧跟标签）；
> ② 原先实现先删 `（N）` 前的 `<br />` 又不补回 → 丢失换行信号；改为**先把「`<br />（N）`」替换为哨兵 `\x00`**，再统一换行；
> ③ 换行以 `<br />` 表达，转换器会翻成 `<w:br/>`（**已验证**：Q21 段内恰 4 个 `w:br`，每小问一行）。
>
> **v1.4 变更（2026-10-09）**：修复两类**产物级严重缺陷**——
> ① **数学公式（MathJye 分数表）在 docx 里被打散成散乱表格**（如"吸水水""3""4"各占一行、"500r/2500r"竖排）→ 渲染器新增 `normalize_math()`：把分数线性化为 `(分子)/(分母)`、上下标转 `<sub>/<sup>`，真正的数据表（`class="edittable"`）保留；
> ② **解析出现"解：解："** 双写 → 渲染器对题库 `Method` 自带的"解："做去重；
> ③ **产物改为三份独立文件**（试卷 docx / 解析 docx / 细目表 html），不再交付单份合卷；
> ④ 题图去 `float:right`（会与文字错位/压字）。
>
> **v1.3 变更（2026-10-08）**：对产物做逐条「落地性审计」，修正两处"文档有、产物无"的条款——
> ① **行距必须写在元素级**（写 body 会被转换器 ×0.85 补偿成 1.275 倍）；
> ② **悬挂缩进**改用 `margin-left` 单独声明 + 转换后经 `fix_hanging_indent.py` 补 `w:hanging`。
> 详见 §2、§6-1、§7。

## 3. 「试卷」排版标准（逐元素）

| 元素 | 格式规范 |
|---|---|
| 卷名标题 | 15pt 加粗居中，段后留白 |
| 考生信息栏（可选） | 学校 / 班级 / 姓名 / 学号，一行制表位对齐 |
| 题型标题 | **12pt（小四）加粗**，独立成段，段前间距加大；格式 `一、选择题（本题共X小题，每小题X分，共X分）` |
| 情境/材料段 | 10.5pt，独立成段，引出题组 |
| 子标签 | **加粗**，如 `【科学探究】` `【查阅资料】` `【解释与结论】` |
| **题号+题干** | `N．（X分）题干……`；**悬挂缩进** 左缩进 13.65pt、悬挂 13.65pt；两端对齐 |
| **选项** | `A．…` （全角"．"）；**自适应均衡分行**：一行放下→**一行 4 个**；否则→**两行各 2 个**；再否则→**四行各 1 个**。用**无边框表格**实现 |
| 填空 | 下划线空格 `____________`（≥6 个下划线） |
| 题图 | 独立成段、居中；宽度不超版心；不得与文字混排 |
| 表格 | 居中；表头加粗；10.5pt |
| 公式 | 用公式对象/上下标，禁止 `^`、`_`、`x2` 之类纯文本近似 |
| 分值 | 紧跟题号，写作 `（X分）` |

## 4. 「解析」排版标准（逐元素）

> 结构：**"参考答案与试题解析"标题 → 逐题**。每题先重列「题号+题干+选项」（便于对照），再给 `【考点】/【分析】/【解答】`。

| 元素 | 格式规范 |
|---|---|
| 解析区标题 | 居中加粗 15pt（与卷名同级），文本 `{卷名} 参考答案与试题解析` |
| 每题题头 | 重列 `N．（X分）题干……` + 选项（同试卷格式） |
| **【考点】** | 蓝色标签 + 考点文字；**不加任何平台名 / 版权尾缀** |
| **【分析】** | 蓝色标签 + 黑色正文 |
| **【解答】** | 蓝色标签 + 黑色正文，正文以 `解：` 开头 |
| 结论句 | `故选：X。`（选择题）单独收尾；解答题给最终结果 |
| 分步过程 | 每个小问/步骤**独立成行** |
| 图/表 | 与试卷同规则 |

## 6. 排版规则细则（给引擎的硬约束）

1. **题号悬挂缩进**：`1．（1分）` 段用左缩进 + 悬挂各 13.65pt，使续行与题干文字左边缘对齐、题号顶格。
   *落地方式*：CSS 写 `margin-left:13.65pt`（**必须单独声明**——转换器不解析 `margin` 四值简写）+ 负 `text-indent`（仅浏览器预览有效，转换器会忽略）；转换后由 `scripts/fix_hanging_indent.py` 就地补 `w:hanging="273"`，得到 `w:ind left=273 hanging=273`。
2. **选项对齐 + 绝不折行**：用**无边框表格**实现自适应均衡分行；**硬约束：任何单个选项都不得折行**。做法——把选项表总宽当作固定预算（实测转换器为 **432pt**），逐列计算"该列最长选项宽度 + 内边距"，令**每列宽 ≥ 该列最长选项 + 内边距**，不足则降级到更少列/更多行。禁止用 inline-block+margin（转 Word 会丢间距、ABCD 粘连）。**不要给选项表加边框**（`w:tblBorders` 全 `none`）。
3. **试题间距**：题干段前 ~10pt、段后 ~4pt；选项表段后 ~8pt。
4. **解答题小问分行**：题目与解析中，`（1）（2）…` 每个小问**独立成行**。由渲染器 `split_subq()` 落地。**易错点**：① 题干里的**校园称谓**（"五（2）班""（1）班"）**不得误拆**——只在标号位于段首 / 紧邻 `<br />` / 前一字符为句末标点（含收尾括号 `）`）或标签结束符 `>` 时才换行；② 题库正文可能用 `<br />` 分隔小问，也可能用标点直接相接，两种都要覆盖；③ 换行信号用 `<br />`（转换器翻成 `<w:br/>`），需**保留**而非删除。
5. **解答题图的位置**：解答/计算题的题图统一放在「**题干叙述下方、小问上方**」，即版式顺序 = 题干叙述 → 图（居中独立成段）→ 小问（1）（2）…。由 `_render_q_body()` 落地：先用 `extract_stem_figs()` 抽出题干内嵌的 `<img>`，再用 `split_at_first_subq()` 在首个小问标号处切开叙述与小问。**原因**：题库把图直接塞在题干 HTML 里、位置随机（有的在最前带 `float:right`、有的在最后），直接渲染会出现"图挤在题首"或"图掉到题尾"。小问块用 `.qsub`（去悬挂缩进、左边对齐）。**其余题型不改**（选择/填空/作图/实验仍按 题干原样 → 图 → 选项）。
6. **填空**：统一下划线空格；解析中不再留空。
7. **图片**：独立成段、居中、等比缩放至版心；题图统一走 `render_paper.IMG`（题库图片域名，可用环境变量 `ZJ_IMG_HOST` 覆盖）+ `referrerpolicy="no-referrer" loading="lazy"`。**去除题库图片的 `float:right`**——题库题干图常带 `style="...float:right"`，在 docx 里会与正文错位/压字，须统一改为独立居中成段。
8. **公式**：用上下标/公式对象，禁止纯文本近似。⚠️ **题库数学标记必须先线性化**：`MathJye` 分数用嵌套 `<table>` 表达，html-to-docx 会把嵌套表渲染成散乱的独立表格（分子、分母各占一行）。渲染器 `render_paper.py` 的 `normalize_math()` 负责把分数转 `(分子)/(分母)`、上下标（`vertical-align:sub/super` 的 span 与 `mathtag="msubsup_sub/sup"` 的 div）转 `<sub>/<sup>`；**真正的数据表（`class="edittable"`）不得误伤**。
9. **分页**：试卷与解析之间**强制分页**（合卷模式）；**默认交付三份独立文件**（试卷 / 解析 / 细目表），各自单独成文。
10. **颜色**：正文黑；解析标签蓝；不引入样例以外的高亮/彩色。
11. **页边距必须显式传参**：HTML→docx 转换器**不读 CSS `@page` 页边距**（默认左右 **3.17cm**），必须在转换命令里显式传 `--margin-top 2.5 --margin-bottom 2.5 --margin-left 2.0 --margin-right 2.0`。
11. **字号要"钉死"在元素上**：转换器**不继承 `body` 的 `font-size`**（回落默认 11pt）。正文/选项/解析段须**显式**写 `font-size:10.5pt`；题型标题显式 `12pt`、卷名/解析标题显式 `15pt`。
12. **解析「解：」去重**：题库 `Method` 字段常自带"解："前缀，渲染器【解答】不得无条件再前置一次（否则"解：解："）。渲染时先剥离已有前缀再统一加一次。

## 7. 实现提示（转换器已知行为，来自实测）

- 选项表中的 `A` 与 `．` 之间，转换器**会插入空格**，使实际文本比原串宽约 11pt → 宽度估算需计入。
- 表格总宽被转换器**归一化为 432pt**（与页边距无关）→ 排版预算取此保守值。
- `white-space:nowrap` **不会**被翻译成 `w:noWrap`，故"不折行"**只能靠列宽反算保证**。
- **行距的两种等价写法**（元素级 vs body 级，实测）：元素级 `line-height:1.5` → `w:line="360"`（真正的 1.5 倍）；`body { line-height:1.5 }` → 被注入到 Normal 样式且 ×0.85 → `w:line="306"`（1.275 倍）。故**行距一律钉在元素上**。
- **缩进**：`margin-left:13.65pt` → `w:ind w:left="273"` ✓；`padding-left` ✗ 忽略；负 `text-indent` ✗ 忽略（故悬挂须后处理）。
- **表格单元格的行距**由转换器转成**段前/段后间距**（`w:before/w:after = (line-height−1)/2 × font-size`）并保持 `w:line="240"`——表格内单行文本居多，视觉等效，无需干预。
- **`margin` 四值简写不被解析**：`margin: 10pt 0 4pt 13.65pt` 中的左边距会丢失 → 需拆成 `margin-left` 等单属性声明。
