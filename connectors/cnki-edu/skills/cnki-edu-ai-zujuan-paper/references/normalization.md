## 2. 难度：全网词汇 → 五档 → dg → Degree

**关键口径**：题库难度系数 **P 越大越容易**（P=正确率）。对外**统一五档**，其余词汇全部归并到五档；**原始 P/Degree 系数只作内部过滤用，不进任何对外输出**。

| 档位（对外唯一口径） | dg | P / Degree 区间 | 五级（教测） | 三档通俗 | 课标层次 | 教师口语 | 星级 |
|---|---|---|---|---|---|---|---|
| **易** | 11 | 0.8–1.0 | 容易题 | 易 | 了解 | 送分题 / 基础题 / 白给 | ★ |
| **较易** | 12 | 0.6–0.8 | 较易题 | 易·中 | 理解 | 简单 / 偏易 / 一般 | ★★ |
| **中档** | 13 | 0.4–0.6 | 中等题 | 中 | 掌握 | 中档题 / 常规题 / 典型题 | ★★★ |
| **较难** | 14 | 0.2–0.4 | 较难题 | 中·难 | 掌握→运用 | 提高题 / 拔高题 / 有难度 | ★★★★ |
| **难** | 15 | 0.0–0.2 | 难题 | 难 | 运用 | 压轴题 / 创新题 / 竞赛级 | ★★★★★ |

**模糊词兜底**：适中→13；偏难/稍难→14；极难/超难→15；偏易/稍易→12。

**P 值 → dg 直算规则**：`dg = 11 if P>=0.8 else 12 if P>=0.6 else 13 if P>=0.4 else 14 if P>=0.2 else 15`。

**三档 → dg 展开**：易→{11,12}；中→{12,13,14} 取 13 为主；难→{14,15} 取 15 为主。

> ⚠️ `dg` 是**离散档位**，不能传连续区间。要"0.4–0.8"这类范围，需分别查 `dg=12`、`dg=13` 再按返回里的 `Degree` 字段（0–1 连续值）客户端过滤。

## 3. 认知层次 → 难度（仅供推导）

对外**不用**认知层次作难度名；仅当用户按「了解/理解/掌握/运用」描述时，据此落到 dg。

| 认知层次（含近义词） | 默认 dg | 说明 |
|---|---|---|
| 了解（知道 / 初步认识 / 感受 / 经历） | 11 | 识记、辨认 |
| 理解（认识 / 会 / 说明 / 比较） | 12 | 说清"为什么" |
| 掌握（能 / 分析 / 证明 / 探索） | 13（偏应用时 14） | 用于新情境 |
| 运用（解决问题 / 证明 / 创造方法） | 15（偏中档时 14） | 综合与实践 |
| 过程目标（体验 / 体会 / 感受） | 12 | 按对应内容层次就近取 |

> 文档里若出现「应用」，并入「掌握 / 运用」（建议 dg=13/14）。

## 7. 知识点归一化（**强制三步：先拉 → 智能匹配 → 再搜题**）

> 细目表/用户给的知识点名是**教材或教师口径**，与题库考点名**常常不一致**。**不得**拿细目表原名直连 `point[]`（会命中错题或报 `String index out of range: -1`）。必须先归一化。

**第 1 步 · 拉取该学段学科的知识点全集**
```
调 mcp__<SERVER>__tkPoint(subjectCode)  →  递归展平所有节点  →  得到「库标准考点名」全集（会话内缓存）
```

**第 2 步 · AI 智能匹配（逐个细目表知识点 → 库标准考点名）**
```
细目表知识点 w
  → 在「库标准考点名」全集上做语义匹配：文本相似 + 同义词 + 上下位/包含关系 + 学科常识
  → 输出 1 个首选标准名（宽知识点可给多个组成 point[]）
  → 置信度分级：
       高（唯一强匹配）   → 直接用标准名
       中（多个合理候选） → 记候选，选题时"抽 5 取 1"覆盖，必要时列给用户确认
       低 / 无匹配        → 标「待兜底」，走第 3 步降级
```

**第 3 步 · 按（归一化后的）知识点 + 题型 + 难度搜题**
```
主力：mcp__<SERVER>__tkSearchSubjectQuestion(subjectCode, point=[标准考点名], ct=题型码, dg=难度档, so=来源码)
降级（仅低/无匹配，或直搜报 String index out of range: -1）：
      mcp__<SERVER>__tkSearchQuestion(keyword=知识点关键词, subjectCode, type=题型码) → 挑主题最贴合的一题
```
- **记录**：选题记录须同时保留「细目表原名」与「库标准名」两列，并标注置信度/兜底来源，便于复核。
  ⚠️ **仅限内部留档**：这一列是题库接口的元数据字段值，**不进入任何对外产物**——双向细目表一律**不渲染**「库标准考点名」列（`render_blueprint.py` 已按此实现）。

**约束（实测）**：`mcp__<SERVER>__tkPoint` 树按「题材/模块」组织，**无单篇课文级节点、无年级字段**。所以：
- 单篇课文 / 章节级锁定 → 走 `mcp__<SERVER>__tkSearchQuestion` 关键词，或 `mcp__<SERVER>__tkBook` + 章节映射。
- 知识点全量拉取较重（单科 0.3–3.8 MB）→ 会话内缓存，二次组卷复用。

**`point` 参数注意**：`mcp__<SERVER>__tkSearchSubjectQuestion` 的 `point[]` 必须是**考点中文名**（不是数字 Key）；传无效名直接抛异常、无优雅降级。

## 8. 教材版本 / 年级学期

- 年级+学期 → 教材版本：调 `mcp__<SERVER>__tkBook(subjectCode)`，`data` 为按教材版本分组的字典，每个版本下列「册」（册名含年级+学期，如「七年级上册」；五四制含「六年级上/下」）。
- ⚠️ `mcp__<SERVER>__tkPoint` 的考点节点与 `mcp__<SERVER>__tkBook` 的章节节点**无现成映射字段** → 「年级+学期 → 知识点」需一份外部课程大纲映射表，或由 AI 结合教材章节名推断后请用户确认。
