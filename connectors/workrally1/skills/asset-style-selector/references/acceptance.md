# 选择器验收用例

维护时阅读本表。先做文件与引用检查，再由执行者按情境模拟；真实会话和模型生图效果须单独验证，不用关键词命中代替实际执行证明。

## 统一入口与全库浏览用例

所有入口均使用同一87种目录。推荐只是四项子集，旧名称不恢复固定菜单；以下列表编号必须按当前展示快照解析。

| ID | 输入/状态 | 预期行为 |
| --- | --- | --- |
| T01 | 有家庭广告需求，调用“启动资产四风格” | 进入统一库，推荐写实加三项需求匹配风格并提供全库浏览；无旧固定菜单 |
| T02 | “四风格选择器，使用硬核废土3D做角色” | 从统一目录匹配唯一条目，按库文件执行；不强迫确认旧2号，不加载旧模板 |
| T03 | 推荐菜单后“选1” | 选择剧情片写实；主流程用写实基底，独立请求用库文件，不加载旧硬科幻1号 |
| T04 | 本轮推荐第2项为生活方式极简，回复“选2” | 使用本轮快照中的库ID，不套固定九层框架 |
| T05 | “浏览全部风格”，无剧本 | 展示87项分类目录；可分页但提供范围、剩余数、下一页；不先索要剧本 |
| T06 | 推荐之后“有哪些风格” | 打开同一全库，不再次只列四项，不要求换模式 |
| T07 | “按分类查看2D风格” | 展示目录内全部匹配分类项，可继续搜索/翻页，不只列一项二维预设 |
| T08 | 要求“把87种完整列出” | 全量输出标准名与分类；集合与目录一致、无遗漏重复，不加载87篇提示词正文 |
| T09 | 选中未在推荐四项中的库条目 | 允许直接确认并加载该条目；不要求先换一批把它加入推荐 |
| T10 | 浏览第二页后回复页内编号 | 解析当前页快照；不沿用推荐菜单的同号映射；指代不清才询问 |
| T11 | 已选风格后浏览全库，再“返回推荐” | 共享原确认，导航不重置、不产生新生成；重新选择才变更风格 |
| T12 | 已有媒介硬约束，浏览全库时指定冲突条目 | 说明冲突并确认是否变更约束，不静默改变媒介；全库条目不被删除 |
| T13 | 推荐组件只支持四个选项 | 四个风格都保留；组件外提供全库浏览、分类与点名导航，不拿“更多”替换第4种风格 |
| T14 | “换一批” | 固定写实候选，另外三项重新按需求筛选；仍提供全库浏览 |
| T15 | 未确认时“继续”“随便”或混合多个编号 | 不默认选中写实，不自动生成；要求有效单选 |
| T16 | 明确只要中文提示词 | 按所选文件适配中文正文，必要固定尾缀仅保留一次；不调用生成服务 |
| T17 | 角色参考图与风格参考图角色混淆 | 分别锁身份、空间与画风，冲突先询问，不因浏览入口变更主体事实 |
| T18 | 任意最终提示词 | 无未填占位符；单一风格；尾缀不重复；中英主体与光向一致 |

## 动态推荐用例（主流程 §0F 与普通风格入口）

按 `../SKILL.md` 5.5 验收。除写实候选外不锁定三项的具体名单；检查推荐依据、差异及加载行为，避免测试本身成为另一套固定菜单。

| ID | 输入/状态 | 预期行为 |
| --- | --- | --- |
| D01 | §0F：夏夜家庭空调广告，父母照顾孩子，温情卧室叙事 | 第1项剧情片写实；其余三项分别解释家庭情绪、家居空间或人物表现的依据，不因旧 A 菜单自动推荐硬科幻/废土；只读目录 |
| D02 | 普通“选风格”：海底科研站发现发光生态，探索与惊奇 | 同样走5.5；动态三项根据水下科研、生态与探索氛围筛选，不照搬D01家庭广告的理由或旧四项 |
| D03 | 新剧本明确要求黏土定格生日派对，要求重新推荐 | 匹配媒介优先；若只有一项明确符合，不凑三项，不把相关但不支持定格的风格说成满足需求 |
| D04 | 用户只说“选风格”，无剧本/产品/用途上下文 | 仅补问题材/产品和主要情绪，不使用固定四项兜底，不虚构推荐依据 |
| D05 | 有可用产品/用途信息但没有完整剧本 | 使用已有需求作为依据，不强求完整剧本；动态项标明依据来自需求而非不存在的镜头 |
| D06 | 明确“只要2D，不要写实” | 写实项只作不可选说明；组件不支持禁用时放组件外；可选动态项全部满足2D，不用写实或3D凑数 |
| D07 | 正常菜单后“换一批” | 写实项不变；另三项重新筛选、与已展示动态项不重复且仍有依据；不足时说明，不自动更新已确认风格 |
| D08 | 动态菜单第2项为生活方式极简，用户说“选2” | 解析本轮快照，仅加载对应库文件；不映射为旧 A 废土分支，不加载common.md或九层框架 |
| D09 | §0F菜单后“选1” | 选定剧情片写实，使用主流程写实基底；不按旧 A 的1号加载硬科幻，不叠加两份完整prompt |
| D10 | 新会话恢复同一空调项目，原风格确认仍有效 | 复用确认，不弹菜单、不重新生图；新项目不得继承该确认 |
| D11 | 普通入口直接指定唯一标准名“生活方式极简” | 匹配目录后直达5.4，不自动进入 A 菜单，不再次要求四选一 |
| D12 | 未确认时“继续”“都行”、多个编号或无效编号 | 不默认选择写实，不开始生成；简短要求有效单选 |
| D13 | 库目录不可读或对应文件缺失 | 明确报告缺失，不从记忆编造条目、ID或风格正文 |
| D14 | 任意动态菜单展示与确认 | 仅显示标准名、分类、特征、需求依据；ID和路径只用于内部记录；四项去重，动态项不再包含剧情片写实 |
| D15 | 同一剧本在“普通选风格”和§0F各进入一次 | 两个入口均遵守5.5，均非固定 A 菜单；不要求两次候选顺序完全一致，但都需真实依据 |

## 静态验收清单

- 主SKILL.md带有效name、description、agent_created和显式版本。
- 包中只有一个名为SKILL.md的文件，防止四个原稿被当成子技能注册。
- 所有Markdown相对链接和manifest中的文件均存在且不越出包根目录。
- 四份原稿SHA-256与源文件一致；原文件内容未变化。
- 运行文件没有来源机器的绝对路径依赖、下载命令或可执行脚本。
- 目录含87个唯一标准名与87个有效文件链接，与styles目录逐一对应；数量不改为84，不删除任意三项。
- 主入口无A/B路由或旧固定菜单；旧01–04模板及common明确为历史参考，不作为运行规则。
- 推荐示例同时提供全库浏览导航；全量浏览覆盖目录集合，选择不受四项推荐限制。
- 主流程写实基底仅为库条目的执行适配，不作为另一选择入口。
- 不含初始化示例文件、不含未处理TODO。
