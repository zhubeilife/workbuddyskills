# 岗位需求诊断与 JD 模板

## 输入采集

- 招聘目标与业务背景：
- 岗位名称、职级、汇报关系：
- 核心职责与预期成果：
- 必备条件：
- 优选条件：
- 可协商条件：
- 工作地点、到岗时间、用工/预算限制：
- 已知冲突或待确认事项：

## 事实门禁清单（先于任何诊断或 JD）

| 信息项 | 用户提供的原文/材料依据 | 状态 | 可否直接写入 JD |
| --- | --- | --- | --- |
|  |  | 已确认事实 / 用户给定标准 / 建议 / 待确认 | 是 / 否 |

仅“已确认事实”和“用户给定标准”可进入 JD；“用户给定标准”如存在合理性、可验证性或合规风险，必须先在诊断中保留风险说明。由行业常识或模型判断推导出的客户层级、工具、能力门槛、职责强度、数字和日期均不可直接写入。

JD 正文只能对允许写入的信息做语义等价改写，不能补充责任主体、执行方式、客户对象、结果承诺或工作条件。任何待确认建议均放在“可选条款（待业务确认）”，不得使用 ⚠ 等标记混入 JD 正文。

## 需求诊断输出

1. 已确认的岗位事实
2. 缺失信息与最少澄清问题
3. 条件冲突、不可验证项或招聘风险
4. 必备 / 优选 / 可协商条件
5. 可进入 JD 的信息与暂不应写入的信息

> 条件分层规则：用户未明确给出的条件只能放入“建议向业务方确认”或“可选建议”，不能列为必备或优选。

## JD 草案输出

1. 岗位名称与岗位概述
2. 核心职责
3. 任职要求（必备与优选分开）
4. 工作地点与其他已确认信息
5. 待确认占位项
6. 编辑说明与版本差异

## 质量评估维度

| 维度 | 检查问题 | 输出 |
| --- | --- | --- |
| 名称准确性 | 是否与职责、职级一致 | 证据与建议 |
| 职责完整性 | 是否说明目标、范围、关键协作 | 缺失项 |
| 要求合理性 | 是否区分必备/优选，是否可验证 | 冲突或澄清项 |
| 前后一致性 | 职责、职级、地点、经验是否矛盾 | 问题位置 |
| 清晰度与吸引力 | 是否具体、易懂且不夸大 | 编辑建议 |

> 质量结论规则：没有薪酬、学历、福利、工具、出差或组织信息，不自动等同于“不可发布”；应根据用户明确要求和当前 JD 是否自相矛盾，分别标为“影响定稿”“建议补充”或“可不写”。
