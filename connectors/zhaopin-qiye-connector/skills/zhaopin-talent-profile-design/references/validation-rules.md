# 画像与匹配校验规则 v0.1

- 每个维度必须有等级、值、文本和来源。
- must 与 not_want 不得对同一值同时生效；冲突必须标记。
- status 为 pending 或 excluded 的要求不得参与硬规则。
- “不限”“不要求”不能被当成限制条件。
- 同一维度重复要求需要合并并保留来源。
- 必须区分事实、推断和待验证信息。
- 公司、学校等不能作为能力的无理由替代指标。
- 不使用性别、户籍等敏感因素进行推荐、淘汰或排序。
- 大厂、优秀、稳定、有潜力等模糊词必须拆成可观察证据。
- 缺少证据不能直接判定候选人不满足。
- 硬条件不能被 bonus 或模糊亮点抵消。
- 待确认项只保留解释当前明确要求所必需的最小缺口；不得把产品/部署/收费模式、客户规模、续约或流失指标、客户分层、实施分工、汇报线、团队管理等未提供项目列入默认清单。
- 证据与面试问题只能回指当前画像要求；只允许候选人口述本人动作与结果，不索要客户名单、前雇主资料、背景核实、证明文件或第三方联系人。
- 不得因岗位名称或行业惯例设置“非销售/非客服/非售前”等隐性排除项。地点仅可核验能否满足岗位办公安排，不问居住、通勤、搬迁或私人原因。
- B 端只能按材料原词列为服务对象/经验条件，不得改写为“非 C 端”或任何隐性排除。
- 未确认权重与锚点时，评估卡只能使用“直接支持 / 证据不足 / 待验证”等证据状态；不得使用高/中/低、加分、优先级、权重或自定义能力档位。偏好项不得写作“加分性偏好”“加分线索”等；证据状态不能以自洽、可信或完整等质量判断为转换条件。
- 客户运营、续约推进等职责不得被补写为启用、健康度、复盘、流失预警、续约风险、商务协同等具体框架、指标或情境；面试问题只问候选人已承担过的对应职责、本人动作与结果，不问假设性处置题。
