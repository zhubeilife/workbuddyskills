# 能力边界与后续扩展

## 已纳入：方法与材料工作流

本 Skill 不依赖智联账户、MCP、CLI 或浏览器回端。它处理用户当前会话中主动提供的材料，交付招聘与求职辅助产物。

默认交付为对话内容；创建或保存文件属于额外动作，只有用户明确提出后才可执行。面试任务若需文件化，候选人材料与考官材料必须分别交付，不能同文件混放。

## 明确不纳入：真实系统与写操作

以下能力需单独完成 API、认证、权限、脱敏、审计、撤销、异常和 WorkBuddy 审核确认后，才可规划为 Connector + Skill：

- 职位创建、发布、修改、刷新、暂停和关闭；
- 招聘数据查询、投递处理、候选人/历史人才库检索和候选人流程更新；
- 向候选人发送消息、分析平台内会话或自动跟进；
- 基于企业系统数据的招聘数据分析；
- 任何候选人数据出域、批量导出或自动化决策。

AI 候选人检索不属于本 Skill 的既有能力。实现前必须确认检索权限、字段、候选人授权/合规依据、脱敏、审计、异常处置、回端必要性和归因方案。

## JD 合规检查的边界

本 Skill 的 JD 质量评估可以标记表达不清、要求冲突、疑似限制性措辞或事实缺失，但不能给出法律、平台规则或企业制度意义上的“合规通过”。正式 JD 合规检查需要经批准、可维护、可追溯的规则来源，并明确适用地区、渠道和企业规则版本。
