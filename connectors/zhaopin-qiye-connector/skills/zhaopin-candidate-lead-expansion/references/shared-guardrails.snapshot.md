# 第二批招聘 Skill 共享护栏（只读）

> **用途**：刘沐晗第二批五项 Skill 及后续同类能力的作者侧公共约束。它只承载横切的安全、证据和异常处理规则；各 Skill 的领域流程、输入字段和输出模板必须独立维护。  
> **状态**：用户于 2026-09-04 确认的项目规则。它不声明任何智联 API、数据字段、平台权限或合规结论。

## 1. 使用边界

- 仅处理用户明确提供或明确授权使用的材料。授权不清、来源不明或超出当前任务目的时，不读取、不推断、不转发个人信息；改为说明所需授权和最小材料。
- 只保留完成当前分析所需的最小信息。默认不复述联系方式、身份证件、精确住址、账号凭据、无关家庭信息或其他非必要敏感个人信息。
- 不自动淘汰、录用、拒绝、联系、发送消息、投递、改变候选人状态或代表用户作出决定。输出只能提供结构化事实、专业建议、风险提示和待验证问题。
- 不把候选人沟通内容、猎头初访材料或正式面试材料发送到外部系统；不承诺存储、留存、审计或删除行为，除非当前批准的能力和系统已明确提供。

## 2. 三层输出契约

所有输出应清晰区分以下三类信息，且不相互替代：

| 层级 | 含义 | 写法 |
| --- | --- | --- |
| 事实 | 可从用户授权材料直接定位的信息。 | 使用“材料显示 / 候选人陈述 / 面试记录提到”，必要时注明材料来源或片段。 |
| 顾问判断 | 基于事实的分析、建议、风险提示或优先级。 | 说明判断依据和不确定性，不冒充已验证事实或录用决定。 |
| 待验证项 | 材料缺失、彼此冲突、无授权或无法确认的内容。 | 提出最小核验问题、需要的材料或建议的下一步；不得自行补全。 |

## 3. 材料类型边界

| 材料 | 可做 | 不可做 |
| --- | --- | --- |
| 猎头初访 | 结构化候选人陈述、经历、动机、约束、顾问观察和待跟进问题。 | 当作正式面试结论，或将顾问推测写成候选人事实。 |
| 正式面试 | 整理问题、回答、证据、面试官评价、意见分歧和待验证项。 | 代替既有面试反馈分析给出证据质量裁决，或作录用决定。 |
| 候选人沟通 | 在授权范围内分析已提供沟通内容中的意愿、顾虑和推进阻力。 | 读取、发送或推断未提供的平台消息、私信、邮件或社交关系。 |
| 职位 / JD / 简历 | 提取用户提供的事实、匹配证据、缺口和待确认项。 | 虚构经历、成果、薪酬、资格或将一般文本检查称为法律 / 平台合规结论。 |

## 4. 统一异常处理

| 情形 | 必须处理方式 |
| --- | --- |
| 文件无法读取或材料格式不可用 | 说明无法可靠提取的原因，列出可接受的替代格式或用户可粘贴的最小内容；不得臆测文件内容。 |
| 材料缺失 | 输出已知事实与缺失清单，提出最小补充问题；不得以常识填空。 |
| 记录冲突 | 并列展示冲突来源，标为待验证，提供核验问题；不得自行选择更“合理”的版本。 |
| 授权不清 | 停止处理相关个人材料，询问处理目的、授权范围和材料来源；可提供不含个人信息的空白模板。 |
| 涉及高风险决定 | 重申仅提供辅助分析，交由具有相应权限的人员核验和决定。 |

## 5. 复用方式

- 作者在创建或修改第二批 Skill 前先阅读本文件，再阅读 `WORKBUDDY_SECOND_BATCH_ROADMAP.md`、`WORKBUDDY_ECOSYSTEM_RULES.md` 及 `docs/skill-analysis/02-skill-building-playbook.md`。
- 每个独立包只链接或生成引用本文件所需的最小版本；不得把五个领域流程复制到公共文档，也不得在五个包中手工维护互相漂移的安全规则。
- WorkBuddy 是否支持独立包的跨目录引用尚待确认。发布包必须是自包含且可审核的：若需将本文件内容随包携带，应使用可追溯的发布快照并记录源版本，而不是改写规则。
