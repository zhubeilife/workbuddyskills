# 寻访策略校验

- must 优先用于精准召回，not_want 用于排除或后置核验。
- 扩展策略每次只放宽一个变量，并保留放宽记录。
- 不得把公司名直接等价为能力。
- 布尔式中的每组词要说明召回目的。
- 结果不足时仅在用户确认可调整的变量后给出可逆放宽顺序；未给确认时列为待确认，不设默认阈值或自动调整。
- 结果过多时优先增加业务、项目、岗位层关键词，不增加敏感个人条件。
- 每层明确实际生效的关键词、公司、地域等过滤范围；公司池若仅作探索建议，注明未用于过滤。只放宽一个变量时，同时比较检索式与过滤范围，不能暗中改变第二个条件。
- 布尔式默认是概念策略，未在目标渠道验证时不保证语法或运算符被严格支持。区分岗位调研、公开作品线索和授权人才搜索；职位、面经、培训命中不能计作人才召回，不在缺少逐条结果时报告召回效果。
- 未获用户确认可协商时，明确要求只能作同义/异名扩展，不得把年限、地点、B 端、续约推进等写作“放宽变量”。
- 不得从企业软件、数字化服务或任何公司/产品词推断 ERP、CRM、MES、PLM、SaaS、订阅制、收费模式、客户健康度、留存、NDR 或其他未提供产品类别/指标；也不得把它们混入关键词或假设。
- 未提供渠道时，不假定有结构化字段、地点/年限解析、自动筛选或后置过滤能力。
- 渠道未知时，也不得假定至少支持文本检索、布尔运算、近义词、排序或任何其他能力；概念检索式只能作为待渠道确认的逻辑草案。
- 请求确认可放宽条件时，不得预设年限数值、地点协商空间或其他放宽边界；只请求用户明确可调整的条件及其边界。
- 偏好项无已确认权重和锚点时，只可单独记录或人工复核，不得写成加分、排序或优先级规则。
- 未提供画像版本时必须标“未提供”，不得自行编造 v0、v1 或临时版本。
- “企业软件”只能作为产品/业务场景词，不能改写为服务对象或 B 端证据；办公地点只可核验能否满足岗位办公安排，不得引入常驻地、通勤、搬迁、合同地点、出差或驻场细节。
- 相近岗位若不能从名称中同时确认全部明确要求，只能标为探索方向；不得称为同岗位等价或混入精准、扩展层。
- “续约推进”不得扩写为续费、续约率、续约达成或其他收费/结果指标；仅可使用不涉及商业模式和指标的词汇等价表达，例如 `renewal` 或“合同续签”。
- 候选人材料或检索结果未直接出现某一明确要求时，只能标待验证/证据不足；不得默认不满足、排除或不进入人工核验。只有直接相反证据才可标不满足。
- 渠道未知时，只可请求用户说明目标渠道/平台，不得列举、假设或推荐具体渠道；地点条件不得被用于举例或设计协商、出差、驻场、通勤、搬迁等路径。
- 不得在假设、待确认项、示例或词表中列举未提供的具体产品类别（包括 ERP、CRM、MES、PLM、私有化部署等）。
- 职级变体（专员、主管、负责人、总监等）不属于标题等价；只能作为探索方向。关键词命中只代表待核验线索，不得称候选人、合格候选人、召回噪声或匹配成立。
- 不得引入本地部署、许可模式、甲方信息化/数字化项目、跨城、出差或驻场等未提供的产品、场景或工作方式；假设只能保留“未提供，待确认”，不得用未提供示例展开。
- 偏好项无权重和锚点时，不得称“加分线索”，只能称单独记录或人工复核维度。
