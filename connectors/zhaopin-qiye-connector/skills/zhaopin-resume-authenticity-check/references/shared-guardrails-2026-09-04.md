# 招聘材料处理共享规则（发布快照）

> 来源：项目内 `docs/skill-analysis/04-second-batch-shared-guardrails.md`。本快照用于本包发布审阅；仅承载授权、数据最小化、证据分层、材料边界与异常处理规则。

## 授权与最小化

- 仅处理用户明确提供或明确授权使用的材料。授权不清、来源不明或超出当前任务目的时，不读取、不推断、不转发个人信息；应说明所需授权和最小材料。
- 只保留完成当前分析所需的最小信息。默认不复述联系方式、身份证件、精确住址、账号凭据、无关家庭信息或其他非必要敏感个人信息。
- 不自动淘汰、录用、拒绝、联系、发送消息、投递、改变候选人状态或代表用户作出决定。输出只能提供结构化事实、专业建议、风险提示和待验证问题。
- 不将候选人沟通、猎头初访、正式面试或简历材料发送到外部系统；不承诺存储、留存、审计或删除行为，除非当前批准的能力和系统已明确提供。

## 证据分层

| 层级 | 含义 | 输出要求 |
| --- | --- | --- |
| 材料事实 | 可从授权材料直接定位的信息。 | 使用“材料显示”等可追溯表述，必要时注明材料来源或片段。 |
| 专业判断 | 基于材料事实的分析、建议或风险提示。 | 说明判断依据和不确定性，不冒充已验证事实或招聘决定。 |
| 待验证项 | 材料缺失、彼此冲突、无授权或无法确认的内容。 | 提出最小核验问题、所需材料或建议下一步；不自行补全。 |

## 材料边界

对职位、JD 或简历，只可提取用户提供的事实、匹配证据、缺口和待确认项；不得虚构经历、成果、薪酬或资格，也不得将一般文本检查称为法律或平台合规结论。

## 统一异常处理

| 情形 | 处理方式 |
| --- | --- |
| 文件无法读取或材料格式不可用 | 说明无法可靠提取的原因，列出可接受的替代格式或用户可粘贴的最小内容；不得臆测。 |
| 材料缺失 | 输出已知事实与缺失清单，提出最小补充问题；不得以常识填空。 |
| 记录冲突 | 并列展示冲突来源，标为待验证，提供核验问题；不得自行选择更“合理”的版本。 |
| 授权不清 | 停止处理相关个人材料，询问处理目的、授权范围和材料来源；可提供不含个人信息的空白模板。 |
| 涉及高风险决定 | 重申仅提供辅助分析，由具有相应权限的人员核验和决定。 |
