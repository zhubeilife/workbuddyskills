## §1 产品模型速览

TCHouse-X 是**离在线一体化云原生数据仓库**，实例由以下部分组成：

```
┌─────────────────────────────────────────────────────────┐
│                  TCHouse-X 实例（Instance）             │
│                                                         │
│  ┌───────────────┐ ┌───────────────┐ ┌───────────────┐  │
│  │ 标准 Warehouse │ │ 标准 Warehouse │ │ 自适应 WH(Beta)│  │
│  │ (wh_online)   │ │ (wh_etl)      │ │  (wh_adhoc)   │  │
│  │ Small × 3     │ │ Medium × 2    │ │  Max 128 CU   │  │
│  └───────┬───────┘ └───────┬───────┘ └───────┬───────┘  │
│          │                 │                 │          │
│          └─── Serverless 离线批处理（按需触发）──────┐  │
│                    /*+engine=batch*/               │  │
│                                                     ▼  │
│  ┌─────────────────────────────────────────────────┐   │
│  │              TCLake 统一存储（前置依赖）           │   │
│  │      单主账号单地域一份 / 按量独立计费              │   │
│  └─────────────────────────────────────────────────┘   │
│                                                         │
│  接入服务节点（认证 / SQL 解析 / 调度）— 由 X 托管，不计费 │
└─────────────────────────────────────────────────────────┘
```

**核心概念**：

| 概念               | 说明                                                                                                       |
| ------------------ | ---------------------------------------------------------------------------------------------------------- |
| **CU**             | 计算资源单位。`1 CU = 1 vCPU + 4 GiB RAM`                                                                  |
| **标准 Warehouse** | 多个同规格节点组成的分布式在线计算集群。支持垂直/水平弹性、分时/定时/自动弹性                              |
| **自适应 Warehouse** | Beta。只需配置最大 CU + 单 SQL 最大 CU，系统按查询复杂度自动扩缩虚拟集群；最大 CU 可选 `4 / 8 / 16 / 32 / 64 / 128 / 256 / 512 / 1024`（9 档）                              |
| **Serverless**     | 离线批处理资源。SQL 中加 `/*+engine=batch*/` hint 触发；可指定 Executor / Driver 规格与数量                  |
| **TCLake**         | 底层统一存储。单主账号单地域仅一份，实例前置依赖，独立按量计费                                              |
| **Catalog**        | TCLake 中保存实例内表数据的目录。实例创建时自动生成，可自定义名称                                            |

**在总 CU 相同的情况下**：高并发场景，**更高的节点规格**通常带来更好的性能；其他场景，**更多的节点数量**更有利于性能（并行度）提升。

## §2 应用场景 → 架构映射

以官网《应用场景》口径把用户诉求收敛到 5 类：

### 2.1 实时 OLAP 分析

| 子场景                       | 用户需求画像                                                                     | 推荐架构                                                                          |
| ---------------------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 在线分析加速                 | 业务用 MySQL/PG 等 OLTP，但需要加速在线分析                                       | 单个标准 Warehouse，规格按数据量选（见 §3）                                        |
| 在线分析 + 资源隔离          | 多租户 / 多业务，需要计算隔离                                                      | 多个标准 Warehouse，每业务一个（wh_biz1、wh_biz2……）                                |
| 在线分析 + 弹性伸缩          | 潮汐 / 峰谷效应大，希望优化成本                                                    | 标准 Warehouse + 分时弹性 / 定时启停 / 自动弹性 三选一（见 §5）                     |

### 2.2 离在线一体化分析

| 子场景                          | 用户需求画像                                                                                              | 推荐架构                                                                            |
| ------------------------------- | --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 离在线业务隔离                  | 有离线 + 在线两种业务，希望互不干扰。数据量 ≤ 百 TB，离线不复杂                                             | 一个标准 Warehouse（在线）+ Serverless（离线，`/*+engine=batch*/`）                  |
| 数据中心架构简化                | 数据体系大，复杂 ETL（Hive / Spark），希望简化「离线出库到 CK/PG/Presto」链路，一份数据同时支撑离线与在线   | 多 Warehouse（wh_online + wh_etl）+ Serverless（SparkJar / PySpark 复杂 ETL）        |

## §3 选型决策树

### 3.1 Warehouse 规格 × 节点数 决策

```
数据量判断：
├── < 1TB（小规模，POC / 测试）
│   ├── 并发 < 5  → 2X-Small × 1（4 CU）
│   ├── 并发 < 15 → X-Small × 1~2（8~16 CU）
│   └── 并发 ≥ 15 → Small × 1~2（16~32 CU）
├── 1TB ~ 10TB（中小规模）
│   ├── 并发 < 20 → Small × 2~3（32~48 CU）
│   ├── 并发 20~50 → Small × 3~5 或 Medium × 2~3（48~96 CU）
│   └── 并发 ≥ 50 → Medium × 3+（96+ CU）
├── 10TB ~ 50TB（中大规模）
│   ├── 简单聚合为主 → Medium × 3~5（96~160 CU）
│   └── 复杂 JOIN → Medium × 5+ 或 Large × 3+（160+ CU）
├── > 50TB（大规模）
│   └── Large × 3+，考虑多 Warehouse 隔离 + 分时弹性
└── 极高并发（> 100 QPS） / 极低延迟 / 免运维诉求
    └── 自适应 Warehouse（Beta），最大 CU 从 `4 / 8 / 16 / 32 / 64 / 128 / 256 / 512 / 1024` 中选取（含 128 档以上适合大型突发场景）
```

### 3.2 并发要求 → 节点数调整

| 并发 QPS | 调整策略                                                          |
| -------- | ----------------------------------------------------------------- |
| < 10     | 基础配置即可                                                       |
| 10-50    | 节点数 × 1.5（向上取整）                                           |
| 50-100   | 节点数 × 2，或叠加多 Warehouse 分流                                 |
| 100-500  | 多 Warehouse 隔离（在线 / 报表 / 临时查询各独立）                    |
| > 500    | 自适应 Warehouse 或多 Warehouse + 自动弹性组合                       |

### 3.3 延迟要求 → 规格调整

| 延迟要求          | 调整策略                                                                    |
| ----------------- | --------------------------------------------------------------------------- |
| > 5 秒（宽松）    | 小规格（X-Small / Small）即可                                                |
| 1-5 秒（标准）    | Small ~ Medium                                                              |
| < 1 秒（严格）    | Medium ~ Large + 更多节点（并行度）                                          |
| < 100ms（极致）   | Large + 多节点 + 物化视图 / 结果缓存（业务层）                                |

### 3.4 是否需要多 Warehouse

```
业务数 ≥ 2 且需要资源隔离？
├─ 是 → 多 Warehouse
│      ├─ 在线报表 → wh_online（标准，长期运行）
│      ├─ ETL 批任务 → wh_etl（标准 + 定时启停）或 Serverless
│      └─ 临时探索查询 → wh_adhoc（小规格 + 分时弹性 或 自适应）
└─ 否 → 单 Warehouse 即可
```

### 3.5 是否需要 Serverless

```
是否有离线批处理任务？
├─ 是（ETL / SparkJar / PySpark）
│  ├─ 简单 SQL ETL → SQL 加 /*+engine=batch*/
│  └─ 复杂逻辑 → SparkJar 或 PySpark 作业
└─ 否 → 不规划 Serverless
```

## §4 标准 Warehouse 规格档位速查

> 官网《标准 Warehouse 计算资源管理》明确的规格档位（**只有这 5 档，不能自定义中间值**）：

| 节点规格   | 单节点 CU 数 | 单节点资源       | 适用场景                                              |
| ---------- | ------------ | ---------------- | ----------------------------------------------------- |
| 2X-Small   | 4 CU         | 4 vCPU / 16 GiB  | 测试 / POC / 极低负载                                  |
| X-Small    | 8 CU         | 8 vCPU / 32 GiB  | 小规模生产 / 低并发                                    |
| Small      | 16 CU        | 16 vCPU / 64 GiB | 中等规模 / 通用场景（**最常用起步档**）                |
| Medium     | 32 CU        | 32 vCPU / 128 GiB| 中大规模 / 复杂查询                                    |
| Large      | 64 CU        | 64 vCPU / 256 GiB| 大规模 / 高并发                                        |

**节点个数**：无强制上限，按业务需求填写；生产建议 ≥ 2（可用性 + 并发）。

**总 CU 计算**：`Warehouse 总 CU = 节点规格 CU × 节点个数`

**示例**：`Small × 3` → 总 CU = 16 × 3 = 48 CU

## §5 弹性策略选择

标准 Warehouse 支持 4 种弹性计划（**同一 Warehouse 同时只能启用一种**）：

| 弹性计划     | 适用场景                                     | 关键配置                                                          |
| ------------ | -------------------------------------------- | ----------------------------------------------------------------- |
| 不启用       | 负载稳定，无明显波动                          | —                                                                 |
| 分时弹性     | 白天 / 夜晚不同规格，业务波峰波谷规律         | 2-24 条策略；起始时间步长 15 分钟；相邻策略间隔 ≥ 1 小时；相邻规格不得相同 |
| 定时启停     | 仅业务时段使用（如 8:00~20:00）              | 每天/每周/每月周期；起停时间点步长 15 分钟；提交后 10 分钟内当日生效 |
| 自动弹性     | 波动不规律，按 CPU 阈值自动扩容               | 观测时间 5~999 分钟；CPU 阈值 40%~100%；最大规格上限；静默时间 10~999 分钟 |

### 5.1 决策树

```
负载模式判断：
├── 完全稳定，无波动 → 不启用弹性计划
├── 有规律的波峰波谷（白天高、夜里低）→ 分时弹性
├── 仅特定时段使用（如工作时段）→ 定时启停
├── 波动不规律，突发流量 → 自动弹性
└── 免运维诉求强，希望自动应对任意负载 → 自适应 Warehouse（Beta）
```

### 5.2 分时弹性 示例配置

**场景**：白天（9:00-21:00）高峰用 `Small × 5`，夜间（21:00-9:00）用 `Small × 2` 节省成本。

```yaml
弹性计划: 分时弹性
周期: 每天
策略:
  - 起始时间: 09:00, 规格: Small, 节点数: 5
  - 起始时间: 21:00, 规格: Small, 节点数: 2
# 结束时间系统自动闭环，24 小时循环
```

### 5.3 定时启停 示例配置

**场景**：仅工作日 8:00-20:00 使用。

```yaml
弹性计划: 定时启停
周期: 每周
生效日: 周一~周五
启动时间: 08:00
暂停时间: 20:00
```

### 5.4 自动弹性 示例配置

**场景**：日常 `Small × 2`，CPU 持续高于 70% 时自动扩容。

```yaml
弹性计划: 自动弹性
观测时间: 10 分钟
扩容 CPU 阈值: 70%
最大扩容规格: Small × 6（96 CU）
静默时间: 15 分钟
```

## §6 Serverless 离线批处理选型

### 6.1 何时使用

- 数据 ETL（CREATE TABLE AS SELECT / INSERT INTO SELECT）
- 复杂 Spark 作业（SparkJar / PySpark）
- 需要与在线查询「物理隔离」的批处理

### 6.2 触发方式

**SQL 方式**（推荐，最简单）：

```sql
/*+engine=batch*/
INSERT INTO sales_db.orders_2
SELECT * FROM sales_db.orders WHERE dt = '2026-07-10';
```

**带资源配置的 Hint**（覆盖默认 `2X-Small × 1`）：

```sql
/*+engine=batch, executor_specs=Small, executor_count=4, driver_specs=X-Small*/
INSERT INTO ... SELECT ...
```

**SparkJar / PySpark 作业**（走「数据作业」入口）：

- Executor 规格 + 个数（可选 2X-Small ~ Medium）
- Driver 规格（默认 2X-Small）
- Main Class（SparkJar）或入口脚本（PySpark）

### 6.3 资源规模推荐

| 数据量 / 作业时长                | Executor 规格 | Executor 个数 | Driver 规格 |
| -------------------------------- | ------------- | ------------- | ----------- |
| < 10GB / < 5 分钟                | 2X-Small      | 1             | 2X-Small    |
| 10GB ~ 100GB / 5-30 分钟          | X-Small       | 2~4           | 2X-Small    |
| 100GB ~ 1TB / 30 分钟-2 小时      | Small         | 3~6           | X-Small     |
| > 1TB / 长作业                    | Medium        | 4+            | X-Small     |

## §7 多 Warehouse 隔离设计

TCHouse-X 一个实例内可创建多个 Warehouse，它们**计算隔离但共享 TCLake 存储**，是资源隔离的核心手段。

### 7.1 典型多 Warehouse 拓扑

| 拓扑模式         | Warehouse 组合                                                                     | 适用场景                                        |
| ---------------- | ----------------------------------------------------------------------------------- | ----------------------------------------------- |
| 单一 Warehouse   | `wh_default`（Small × 3）                                                          | 单业务，无隔离需求                              |
| 在线 + 离线      | `wh_online`（Small × 3，长期运行）+ Serverless（按需 `/*+engine=batch*/`）           | 离在线一体，最常见                              |
| 在线 + ETL 独立  | `wh_online`（Medium × 3）+ `wh_etl`（Small × 4，定时启停 22:00-06:00）              | ETL 与在线分析隔离，避免相互干扰                |
| 多业务隔离       | `wh_biz1` + `wh_biz2` + `wh_biz3`                                                  | 多租户 / 多业务线并行                            |
| 弹性突发         | `wh_default`（常驻小规模）+ `wh_burst`（自适应 Warehouse，最大 128 / 256 / 512 / 1024 CU 可选，突发流量）       | 有突发大查询但成本敏感                          |

### 7.2 命名建议

- 用途前缀：`wh_online` / `wh_etl` / `wh_report` / `wh_adhoc`
- 业务前缀：`wh_bi_finance` / `wh_bi_ops`
- 环境前缀：`wh_prod_online` / `wh_test_online`

## §8 用户体系与数据安全

### 8.1 用户体系

| 用户体系       | 状态    | 适用场景                                          |
| -------------- | ------- | ------------------------------------------------- |
| CAM 子账号     | ✅ 正式 | 默认推荐；已有腾讯云子账号体系，权限统一管理        |
| 自定义用户     | ✅ 正式 | 需要自定义用户名 / 密码；与 BI 工具集成便利         |
| 自定义 LDAP    | ⚠️ Beta | 企业已有 LDAP 单点登录；需联系腾讯云开通            |

### 8.2 数据安全

- **SSL/TLS 传输加密**：默认关闭；金融 / 合规场景建议开启
- **VPC 隔离**：所有 Warehouse 部署在用户指定 VPC 内，天然网络隔离
- **子网可用 IP**：**必须 > 6**（官网硬约束）

## §9 CU 规模校验公式

### 9.1 CU 估算

```
估算所需 CU ≈ max(
  峰值并发 QPS × 单查询平均 CU 消耗,
  热数据量(GB) × 内存缓存系数
)

参数取值：
- 单查询平均 CU 消耗：简单聚合 0.5 CU / 中等 1 CU / 复杂 JOIN 1.5-2 CU
- 内存缓存系数：0.02（热数据 5% 缓存于内存，1 CU=4 GiB）
```

### 9.2 校验流程

```
对每个方案执行：
1. 计算方案总 CU = 节点规格 CU × 节点数
   （自适应 Warehouse 直接用「Warehouse 最大 CU」）
2. 计算 所需 CU
3. IF 方案总 CU ≥ 所需 CU × 0.8:
     → 校验通过（留 20% 缓冲）
4. ELSE:
     → 优先增加节点数（保持规格档位不变）
     → 若节点数 > 8 仍不够 → 上调节点规格档位（Small → Medium → Large）
     → 更新方案并注明「已自动上调以满足负载」
```

### 9.3 示例

**场景**：数据量 10 TB，热数据约 500 GB，峰值 50 并发，复杂 JOIN 为主。

```
所需 CU = max(50 × 1.5, 500 × 0.02) = max(75, 10) = 75 CU
方案 A：Small × 3 = 48 CU → 48 < 75 × 0.8 = 60 ❌
自动上调：Small × 5 = 80 CU → 80 ≥ 60 ✅
或档位提升：Medium × 3 = 96 CU → 96 ≥ 60 ✅
```

## 方案 A 详细配置（推荐）

### Warehouse
- 名称：`wh_default`
- 类型：标准 Warehouse
- 节点规格：Small（16 CU / 节点）
- 节点个数：3
- 总 CU：48 CU
- 弹性计划：不启用

### Serverless
- 按需触发：在需要跑离线 ETL 的 SQL 前加 `/*+engine=batch*/`
- 默认资源：Executor 2X-Small × 1，Driver 2X-Small × 1
- 更大作业时按需覆盖：`/*+engine=batch, executor_specs=X-Small, executor_count=2*/`

### 网络与安全
- VPC：请选择目标地域下已有 VPC
- 子网：选择剩余可用 IP > 6 的子网
- 传输加密：按需开启 SSL/TLS

### 用户体系
- CAM 子账号（默认）

### TCLake
- 目标地域首次创建实例时授权自动开通
- Catalog 名称：默认由系统生成，可自定义

### 选型理由
- 数据量约 5 TB + 20 QPS → 落在中小规模区间，Small × 3（48 CU）满足负载校验
  （所需 CU ≈ 20 × 1.0 = 20 CU，方案 48 CU ≥ 20 × 0.8 = 16 ✓）
- 无明显潮汐 → 不启用弹性计划，保持稳定
- 无离线 ETL → 不专门规划 Serverless，仅保留按需触发能力
- 单业务 → 单 Warehouse 即可，无需资源隔离

## 方案 B 详细配置（性能优先）

### Warehouse × 2（多 Warehouse 隔离）
- `wh_online`（Medium × 3，96 CU，无弹性）— 承载在线报表 / BI 分析
- `wh_etl`（Small × 2，32 CU，定时启停 22:00-06:00）— 承载 ETL 批任务

### Serverless
- 复杂 ETL / SparkJar / PySpark 作业走 Serverless
- 推荐 Executor：X-Small × 4，Driver：X-Small

### 网络与安全
- VPC / 子网同方案 A
- 传输加密：开启 SSL/TLS

### 选型理由
- 明确要求「在线 + ETL 隔离」→ 双 Warehouse 计算隔离
- ETL 仅夜间执行 → wh_etl 定时启停降低成本
- 复杂离线逻辑 → Serverless 独立执行，不占用 Warehouse 资源

## 方案 C 详细配置（经济型）

### Warehouse
- `wh_default`（X-Small × 2，16 CU）
- 弹性计划：定时启停（工作日 8:00 启动 / 20:00 暂停）

### Serverless
- 按需触发

### 选型理由
- 数据量小 / 测试或非核心场景 → X-Small × 2 起步
- 仅工作时段使用 → 定时启停降至最低成本
- 不上 SSL/TLS，不做多 Warehouse 隔离

## 最终推荐

推荐 **方案 A**，理由：
1. 满足业务负载（并发 20 QPS、数据 5 TB 全部覆盖）
2. 单 Warehouse 架构最简单，运维成本最低
