## §1 选型决策树

### 数据规模 → BE 节点规格

```
数据规模判断：
├── < 500GB（小规模）
│   ├── 并发 < 10 QPS → BE 4C16G × 3 节点（最小 3 副本）
│   └── 并发 ≥ 10 QPS → BE 8C32G × 3 节点
├── 500GB - 5TB（中小规模）
│   ├── 并发 < 20 QPS → BE 16C64G × 3 节点
│   └── 并发 ≥ 20 QPS → BE 16C64G × 3-6 节点
├── 5TB - 20TB（中等规模）
│   ├── 查询简单（聚合为主）→ BE 32C128G × 3-6 节点
│   └── 查询复杂（多表 JOIN）→ BE 64C256G × 3-9 节点
├── 20TB - 100TB（大规模）
│   ├── 高并发点查 → 存算分离架构（IsSSC=true，BE + CN 弹性扩展）
│   └── 复杂分析 → BE 64C256G × 9-15 节点
└── > 100TB（超大规模）
    └── 存算分离 + 冷热分层（COS 冷数据），分集群部署
```

### 并发要求 → 节点数量调整

| 并发 QPS | 调整策略 |
|----------|---------|
| < 10 | 基础配置（BE 3 节点）即可 |
| 10-50 | BE 节点数 × 1.5（保持 3 的整数倍以满足副本调度） |
| 50-200 | BE 节点数 × 2，考虑存算分离（CN 处理读） |
| 200-500 | 存算分离架构 + CN 4-8 节点弹性扩缩 |
| > 500 | 多集群方案 + 物化视图预计算 |

### 延迟要求 → 存储与内存调整

| 延迟要求 | 调整策略 |
|----------|---------|
| > 5 秒（宽松） | 高性能云硬盘即可 |
| 1-5 秒（标准） | SSD 云硬盘 |
| < 1 秒（严格） | 增强型 SSD（CLOUD_HSSD）+ 内存规格上调一档 |
| < 100ms（极致） | CLOUD_HSSD + 大内存 + 物化视图（异步/同步）|

## §2 规格映射表

### Doris 节点角色

| 角色 | 必选/可选 | 数量约束 | 说明 |
|------|----------|---------|------|
| FE | 必选 | 1（无HA）/ 3+（HA）| 元数据、查询规划，HA 模式至少 3 个（1 master + 2 follower） |
| BE | 必选 | ≥ 3（默认 3 副本）| 存储 + 计算（存算一体） |
| CN | 可选 | 0+ | 仅存算分离模式（IsSSC=true）使用，纯计算节点，弹性扩缩 |

### BE/CN 规格示例

> 实际可用规格请通过 `TCHouseDDescribeSpec` 查询当前地域，下表为常见规格示意。

| 规格名称 | CPU | 内存 | 适用场景 |
|---------|-----|------|---------|
| 4C16G | 4 | 16 GB | 测试/开发 |
| 8C32G | 8 | 32 GB | 小规模生产 |
| 16C64G | 16 | 64 GB | 中等规模/通用（最常用） |
| 32C128G | 32 | 128 GB | 大规模/复杂查询 |
| 64C256G | 64 | 256 GB | 超大规模/高并发 |

### FE 规格

| 规格 | 适用场景 |
|------|---------|
| 4C16G | 小集群（≤ 6 BE） |
| 8C32G | 中集群（6-20 BE） |
| 16C64G | 大集群（> 20 BE 或元数据量大） |

### 副本数与 BE 节点数关系

| 副本数 | BE 节点数最小值 | 建议 |
|-------|---------------|------|
| 1（仅测试） | ≥ 1 | 数据丢失即丢失，仅测试用 |
| 3（默认/推荐） | ≥ 3 | 生产标配，BE 数为 3 的整数倍 |
| 5（金融级） | ≥ 5 | 极高可靠性，成本高 |

> **重要**：BE 节点数应是副本数的整数倍以便 Tablet 均衡。例如 3 副本 → BE 节点数为 3、6、9、12...

## §3 存储选型指南

### 磁盘类型对比

| 磁盘类型 | 代码 | IOPS | 吞吐量 | 单价 | 适用场景 |
|---------|------|------|--------|------|---------|
| 高性能云硬盘 | CLOUD_PREMIUM | 中等 | 中等 | 低 | 冷数据/日志/成本敏感 |
| SSD 云硬盘 | CLOUD_SSD | 高 | 高 | 中 | 通用 OLAP/标准场景 |
| 增强型 SSD | CLOUD_HSSD | 极高 | 极高 | 高 | 低延迟/高并发/热数据（推荐生产） |

### 本地盘 vs 云盘选型决策

| 维度 | 本地盘（如 H_16_64 系列） | 云盘（CLOUD_HSSD/SSD/PREMIUM） |
|------|-------------------------|--------------------------------|
| 单 TB 价格 | 低（性价比高） | 较高 |
| 在线扩容 | 不支持（需添节点迁数据） | 支持单盘/盘数弹性扩容 |
| 售罄风险 | 中等 | 中高（热門地域 16C64G 云盘易售罄） |
| 容量弹性 | 固定（随机型绑定） | 高 |

**决策规则**：
- 容量**不确定 / 增长快 / 需要在线弹性扩容** → **首选云盘**（CLOUD_HSSD/SSD）
- 容量稳定 / 追求极致性价比 / 热門地域云盘售罄 → **选本地盘**（并提示用户“本地盘不可在线扩容，需添节点迁数据”）
- 主推云盘机型售罄时：参见 SKILL.md 步骤 1b 的售罄降级策略，优先降级到**同档本地盘机型**或**相邻档位云盘机型组合**

### 磁盘容量计算

```
总存储需求(GB) = 原始数据量 × 压缩比 × 副本数 × 冗余系数
单节点存储 = 总存储需求 ÷ BE 节点数

其中：
- 压缩比：根据业务场景（见下表）
- 副本数：默认 3（生产推荐），测试可选 1
- 冗余系数：建议 1.3（预留 30% 用于 Compaction/临时文件/增长）
```

### 压缩比与默认系数表（统一校验口径）

> 与 SKILL.md 步骤 2.5 的存储校验公式保持一致。未明确指定时一律使用默认值。

| 系数 | 默认值 |
|------|--------|
| 压缩比（聚合模型 AGGREGATE/UNIQUE） | **0.30** |
| 压缩比（明细模型 DUPLICATE） | **0.40** |
| 压缩比（时序数据） | **0.20** |
| 副本数 | **3** |
| 冗余系数 | **1.3** |
| 格式化损耗系数 | **0.9** |

### 压缩比参考值

| 业务场景 | 压缩比 | 说明 |
|---------|--------|------|
| OLAP 聚合分析（报表/BI） | 0.25~0.35 | 列存 + 高重复字段，压缩效果最好 |
| 实时写入/日志分析 | 0.35~0.50 | 文本字段较多 |
| 混合负载（OLAP + 点查） | 0.30~0.45 | 取决于数据结构 |
| 宽表/高基数字段多 | 0.40~0.55 | UUID、URL、JSON 等压缩率较差 |
| 时序数据（监控/IoT） | 0.15~0.25 | 数值型重复度极高 |

> **选型建议**：
> - 用户未明确场景时，默认使用 **0.35**（偏保守）
> - 不确定时宁可高估，避免存储不足

### 云盘数量建议

| 场景 | 云盘数量 | 说明 |
|------|---------|------|
| 小规模（< 2TB/节点） | 1 块 | 简单管理 |
| 中规模（2-10TB/节点） | 2-4 块 | 并行 IO 提升性能 |
| 大规模（> 10TB/节点） | 4-10 块 | 最大化 IO 带宽 |

## §4 高可用与架构方案

### 高可用决策

| 场景 | FE HA | BE 副本数 | 跨 AZ | 说明 |
|------|-------|----------|-------|------|
| 测试/开发 | 否（FE 1 节点） | 1 | 否 | 节省成本 |
| 生产-基本可用 | 是（FE 3） | 3 | 否 | 标准生产配置 |
| 生产-高可用 | 是（FE 3） | 3 | 是 | 跨 AZ 部署 |
| 金融/核心业务 | 是（FE 5） | 3-5 | 是 | 跨 AZ + 备份策略 |

### 高可用对资源的影响

- FE HA：至少 3 个 FE 节点，建议 1 master + 2 follower
- 多副本：存储是单副本的 N 倍（默认 3 副本）
- 跨 AZ：网络延迟增加 1-3ms，BE 节点需分布在多 AZ

### 架构选型：存算一体 vs 存算分离

| 维度 | 存算一体（IsSSC=false） | 存算分离（IsSSC=true） |
|------|----------------------|----------------------|
| 节点角色 | FE + BE | FE + BE + CN |
| 数据存储 | BE 本地盘 | 共享存储（COS）+ BE 缓存 |
| 弹性 | 扩容需迁移数据，慢 | CN 秒级弹性扩缩 |
| 适用场景 | 中小规模/稳态负载 | 大规模/突发高并发 |
| 成本 | 计算与存储绑定 | 计算与存储分离，灵活 |

**选型建议**：
- 数据量 < 20TB 且并发稳定 → 存算一体
- 高并发突发 / 数据量 > 50TB / 需要按需扩缩 → 存算分离
- 历史/冷数据多 → 存算分离 + 冷热分层

## §5 容量规划公式

### 存储容量

```
总存储需求(GB) = 日增量(GB) × 保留天数 × 压缩比(0.3~0.5) × 副本数(默认3) × 1.3(冗余)
单 BE 节点存储 = 总存储需求 ÷ BE 节点数
```

### 内存估算

```
建议内存 ≥ 热数据量 × 10%（用于 Page Cache 和查询中间结果）
单次查询内存 ≈ 扫描数据量 × 2-5%（取决于查询复杂度）
并发内存需求 = 单次查询内存 × 并发数
```

### 节点数估算

```
最小 BE 节点数 = max(
  ceil(总存储需求 / 单节点最大磁盘容量),
  ceil(并发 QPS / 单节点可承载 QPS),
  副本数  // 至少等于副本数
)

向上取整为副本数的整数倍。

其中：
- 单 BE 可承载 QPS ≈ CPU 核数 × 0.5-1（简单查询）或 × 0.2-0.5（复杂查询）
```

### 存储容量校验（强制 ASSERT）

> **重要**：在输出任何推荐方案前，必须对每个方案执行以下校验。

```
集群可用存储 = BE 节点数 × 盘数 × 单盘大小(GB) × 0.9（格式化损耗）
需求存储 = 数据量(GB) × 副本数 × 1.3（冗余系数）

ASSERT: 集群可用存储 ≥ 需求存储
```

**校验失败时的自动调整策略**（按优先级顺序）：

1. **上调单盘大小**：`新单盘大小 = ceil(需求存储 / (BE 节点数 × 盘数 × 0.9))`，向上取整到 100GB 整数倍
2. **增加云盘数量**：若单盘大小已达 MaxDiskSize 上限，增加 DiskCount
3. **增加 BE 节点数**：若云盘数量也达上限，增加 BE 节点数（保持副本数整数倍）

**示例**：
```
场景：10TB 压缩后数据，3 副本，6 BE 节点 × 4 盘 × 200GB

集群可用存储 = 6 × 4 × 200 × 0.9 = 4,320 GB = 4.3 TB
需求存储 = 10,000 × 3 × 1.3 = 39,000 GB = 39 TB

ASSERT 失败：4.3 TB < 39 TB
→ 自动上调单盘大小 = ceil(39000 / (6 × 4 × 0.9)) = ceil(1805.6) = 1900 GB
→ 校验：6 × 4 × 1900 × 0.9 = 41,040 GB = 41 TB ≥ 39 TB ✓
```
