# Payroll 查询语义

本文件用于把自然语言中的 Payroll 查询收敛为当前 CLI 能够证明的业务问题。先确定查询对象、时间和结果粒度，再选择命令；不要先看到某个命令名再反向解释用户目标。

## 1. 查询必须明确的语义

| 维度 | 需要回答 | Payroll 示例 |
| --- | --- | --- |
| 查询对象 | 用户要看档案、台账、任务、方案、银行卡、扣缴关系、项目、模板还是 CNB 结果 | “张三工资”尚未唯一确定对象 |
| 业务范围 | 单员工、某个台账、当前公司、共享范围还是 CNB 主体 | 单员工银行卡与公司项目列表范围不同 |
| 时间 | 当前、历史、薪资年月、日期范围或计税年月 | “5 月工资”通常还需确认年份和台账含义 |
| 粒度 | 单对象、列表项、字段定义、员工明细、当前页或服务端汇总 | 台账字段定义不是员工明细 |
| 筛选 | 姓名、工号、部门名称、状态、方案、项目名称或主体 | 台账员工条件直接进入明细命令，不转 staffId |
| 完整性 | 当前页、服务端返回总数、还是已验证的全量 | 禁止在未翻页时声称全量结果 |

目标对象已经唯一但缺少命令必填参数时，优先继续业务定位或询问参数；不要把“缺参数”误判为“无法识别 Use Case”。

## 2. 高频自然语言消歧

| 用户表达 | 可能含义 | 最小澄清 |
| --- | --- | --- |
| “查张三工资” | 当前薪资档案、某期台账明细、核算任务结果 | “你要看当前薪资档案，还是某个年月已经形成的工资台账？” |
| “查 5 月工资表” | history/merge 台账列表或唯一台账员工明细 | 补年份，并确认要台账列表还是员工明细 |
| “这个方案多少人” | 未关联方案人数、某方案员工数或台账人数 | 当前只公开“未关联任何薪资方案人数”；其他口径说明缺口 |
| “张三个税” | 扣缴义务人记录、CNB 申报状态、缴款汇总 | 确认是员工扣缴关系还是某主体某计税月的 CNB 状态 |
| “建工资表” | 公司薪资模板、薪资方案、某期台账或 Excel 端到端建模 | 确认最终要新建哪类业务对象及输入来源 |
| “交通补贴” | 查项目、启用失效项目、加入系统项目、新建自定义项目 | 先查当前公司项目，再按状态和来源确定分支 |

### 2.1 业务字段名优先于技术词面

先按用户句中的谓词和并列关系识别业务字段，再判断词面是否像技术术语。在薪资查询中，位于“查询/显示/返回/包含/查看……字段（的值）”位置，或与“基本工资、绩效奖金”等薪资项目并列的短语，优先作为完整的薪资字段展示名匹配。

例如“查询张荣发 Zhang Rongfa 的薪资档案，并显示基本工资、CLI选项的值”中，“CLI选项”是待查询的薪资项目名，不得拆成 `CLI` 与“选项”，也不得改为命令选项、内部 code、枚举值或 JSON key。只有用户明确提到 CLI 命令/参数/Flag/帮助、字段 code/内部 ID、JSON key/原始返回，给出 `--xxx` 语法，或明确询问技术实现时，才按技术语义处理。

按业务字段名执行 fields-only 匹配后，唯一候选自动继续，多候选确认，零候选说明未匹配到该业务字段并请用户核对名称；不得静默回退为 CLI 内部信息查询。

## 3. 当前可回答的查询

### 3.1 单对象与列表

- 银行卡：唯一员工的银行卡记录。
- 薪资档案：按人员、组织、状态、方案关系和动态字段筛选的当前页列表，或唯一员工的字段/详情。
- 薪资台账：按名称、年月或日期范围查询 history/merge 列表；基于唯一列表项读取字段定义或当前页员工明细。
- 扣缴关系：唯一员工的扣缴义务人记录。
- 方案、任务和共享结果：按公开命令返回候选列表、任务详情或表格配置。
- CNB：按主体、类型和计税期间查询申报主体、明细状态或缴款汇总。
- 公司项目与模板：查询当前公司项目、系统候选、创建选项、系统模板或模板快照。

### 3.2 当前可用统计

只有命令直接返回且口径清楚的统计才能作为结果使用：

| 统计 | 业务定义 | 粒度与范围 | 证据命令 | 不能推断 |
| --- | --- | --- | --- | --- |
| 未关联薪资方案人数 | 当前登录用户薪资数据权限范围内，尚未关联薪资方案的员工数量 | 当前租户、当前权限范围的单一计数 | `salaryPlan +unassigned-count` | 具体人员名单、全公司绝对人数或某方案人数 |
| 台账查询总数 | 当前台账筛选条件下服务端返回的 `sourceTotalElements` | 指定名称/期间条件的台账列表 | `ledger +list` | 工资总额、员工总数或可读取的明细页数之外的业务结论 |
| 当前页返回数 | 当前请求实际返回的列表或明细条数 | 当前页 | 对应列表/明细命令 | 全量人数、总金额或排名完整性 |

CNB `taxPayment +total-list` 的“汇总”是服务端业务结果名称。除非返回契约明确给出某字段的业务定义，否则只呈现返回项，不由 Agent自行汇总或重算税额。

## 4. 当前不可回答的统计

以下目标没有稳定公开命令或完整统计契约，直接说明能力缺口并停止：

- 任意期间全公司工资总额、平均工资、中位数、分位数或薪资分布；
- 薪资同比、环比、涨薪率、人工成本趋势或部门成本归因；
- 以台账当前页或分页总数代替员工去重后的全量人数；
- 根据档案当前值推算历史实发，或根据台账反推当前档案；
- 个税申报完成率、缴款完成率或异常率；
- split 子台账、导出结果或未公开字段上的统计。

不得通过裸 HTTP、数仓查询、导出接口或相邻 Domain 拼接来绕过当前边界。明确全量或后续分析时可以先串行拉全量行；没有对应返回字段时，不得声称已经算出本节列出的缺失指标。

## 5. 查询执行与完整性

1. 先按[公开命令导航](commands.md)定位唯一相关条目，再读取具体 Help 和条目指定的过渡命令 Reference。
2. 对敏感列表，普通查询只读取用户明确的一页和字段范围；统计分析、明确全量或完整拉取按共享查询分页规则串行翻页，禁止并发。不得扩大时间、人员、主体和台账范围。
3. 台账明细的人员姓名、工号和部门名称交由同一次明细请求筛选；不前置解析员工 ID，也不对当前页本地二次筛选。
4. 薪资档案和扣缴关系的员工定位使用 `salaryProfile +list` 最小查询；银行卡使用 `staff +search`。零候选和多候选按各自 Use Case 停止。
5. 只有命令返回的结构化对象、字段、状态和统计才是执行证据。没有可检查完成证据时，不使用“已完成”“全部”“总计”等结论。
