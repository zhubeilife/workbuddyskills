# 公司薪资项目

公司薪资项目是档案、模板和台账引用的薪资字段定义。名称用于用户理解和匹配，`metaId` 用于定位公司项目记录，`code` 用于公式和业务字段绑定。三者不能互换。

## 1. 项目来源和状态

| 语义 | 含义 | Agent 行为 |
| --- | --- | --- |
| 当前公司有效项目 | 已在当前公司且可直接使用 | 精确同名唯一候选可复用 |
| 当前公司失效项目 | 已在当前公司但当前不可直接使用 | 用户确认后批量启用；读回有效才可复用 |
| 未加入公司的系统项目 | 系统已有定义，但当前公司尚未加入 | 当前公司无可接受候选时再查询并加入 |
| 自定义项目 | 当前公司自行定义的新项目 | 仅在公司项目和系统项目都无匹配时创建 |

系统/自定义描述项目来源，不等同有效/失效状态。存在失效精确同名公司项目时，不得创建新的同名项目。

## 2. 查询与候选定位

1. `salaryField +list --name <名称>` 按名称包含匹配。为发现同名失效项，省略 `--valid`。
2. 唯一精确名称且有效时可作为复用候选；多候选按项目名称、状态、类型和类别让用户选择。
3. `salaryField +detail` 只接受已确认的真实 `metaId`。
4. 模板上下文中的候选使用 `companyTemplate +addable-fields`；第二步组装模板规则时使用命令返回的完整 `ruleField`，不得自行拼对象。
5. 当前公司没有可接受候选时，再使用 `salaryField +system-not-added` 查找未加入公司的系统项目。
6. 新建自定义项目之前使用 `salaryField +create-options` 读取当前类别、类型、进位和公司成本选项；缺少名称的选项不得进入用户选择。

## 3. 写入决策顺序

```text
公司有效精确同名 -> 复用
公司失效精确同名 -> 确认启用 -> 读回有效 -> 复用
公司无可接受候选 -> 查询未加入系统项目 -> 唯一命中 -> 确认加入
公司和系统均无匹配 -> 读取创建选项 -> 确认完整设置 -> 创建自定义项目
```

- `salaryField +batch-enable` 只恢复有效状态，不修改名称、公式或其他设置。确认项目名称和数量后只提交一次；部分失败或结果未知时停止并重新查询，不自动重试。
- `salaryField +add-system` 必须使用 `system-not-added` 返回的完整候选对象。用户给 code 时还必须与候选一致。
- `salaryField +create` 的确认必须包含名称、类型、类别、进位、小数位、公司成本、强制使用、薪资档案引用和必填设置。
- `forcedToUse=true` 会影响新建及历史薪资模板，必须在确认中显式说明。
- `salaryField +batch-create` 是一个原子创建批次，不接受把循环单条命令伪装成批量。响应不确定时停止并按名称和状态回查。

所有写命令先 dry-run，再按业务名称和影响数量确认。dry-run 只证明本地请求可构造，不证明远端权限、并发状态或最终写入成功。

## 4. Excel 边界

完整 Excel 表头识别和项目映射进入[薪资项目匹配 Use Case](../use-cases/salary-field-match/guide.md)。该 Use Case 复用本文件的项目语义和公开命令；稳定业务知识不保存单次 Excel 运行产物，也不把 Excel 单元格列直接视为公司薪资项目。
