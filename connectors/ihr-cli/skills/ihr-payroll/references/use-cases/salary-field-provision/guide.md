# Use Case：配置公司薪资项目

## 目标定义

把用户给出的薪资项目业务名称收敛为当前公司可复用项目、确认启用的失效项目、确认加入的系统项目或新建自定义项目，并以命令返回和只读回查证明最终项目状态。

## 业务判断

1. 先按[公司薪资项目](../../domain/salary-fields.md)理解名称、metaId、code、来源和有效状态。
2. 决策顺序固定为：公司有效项目 → 公司失效项目启用 → 未加入系统项目 → 自定义新建。
3. 有失效精确同名项目时，用户拒绝启用也不得创建同名项目；应改名或结束。
4. 多候选按业务名称、状态、类型和类别确认，不自动选择第一项。
5. 完整 Excel 表头映射改读[薪资项目匹配 Use Case](../salary-field-match/guide.md)；本 Guide 处理单个或用户明确的小范围项目目标。

## 执行与验证

1. 在[公开命令导航](../../domain/commands.md)定位 `salaryField +list`，省略 `valid` 查询精确名称候选。
2. 有效唯一候选直接复用；失效唯一候选在用户确认名称和数量后，对 `batch-enable` 先 dry-run 再执行一次，并读回全部有效。
3. 公司无可接受候选时查询 `system-not-added`。唯一精确系统候选经确认后，对 `add-system` dry-run并执行一次，再读回公司项目。
4. 公司和系统均无匹配时读取 `create-options`。展示名称化的完整创建设置；用户确认后对 `salaryField +create` dry-run并执行一次，再按名称和返回 ID 回查。
5. 用户明确提交一个已确认批次时，使用 `salaryField +batch-create` 一次原子提交并按有序结果绑定；不得循环单条命令。

## 停止条件

- 精确同名候选状态不明、多候选未确认或创建选项缺少名称；
- 有失效同名项目但用户拒绝启用且未改名；
- 用户未确认完整自定义项目设置或 `forcedToUse` 影响；
- dry-run 与最终请求不一致、批次部分失败、写入结果未知或读回未生效；
- 命令契约不足或目标只能由未注册 metadata command 完成。禁止 raw 接口和自动重试。
