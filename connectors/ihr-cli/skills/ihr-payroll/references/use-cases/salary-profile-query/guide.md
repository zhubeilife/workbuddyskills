# Use Case：查询人员薪资档案

## 目标定义

在当前 Payroll 数据权限范围内定位员工，解析用户要求的薪资字段，并查询当前或历史薪资档案摘要或详情。档案结果描述员工薪资配置事实，不表示某期已经核算或实发。

## 业务判断

1. 用户只要人员或档案列表时，不自动升级为敏感详情查询。
2. 姓名或工号通过 `salaryProfile +list` 在同一权限范围内定位，不使用 Staff 或 Master Data 替代。
3. 动态字段名称通过 `salaryProfile +detail --fields-only` 解析。字段发现不需要员工，也不读取员工档案。
4. 部门、职位或职级名称需要对应 ID 时，按[查询对象与结果](../../domain/query-objects.md)的条件使用 `ihr-master-data`。
5. 当前档案、历史档案和某期台账不能互相替代；用户实际要发放结果时转入台账 Use Case。

## 执行与验证

1. 在[公开命令导航](../../domain/commands.md)定位 `salaryProfile +list`，读取 Help 和[档案列表契约](../../commands/salary-profile-list.md)。
2. 员工定位时保持 `fields` 为空并只请求当前页。唯一候选自动保存真实 `staffId`；多候选按姓名、工号和部门确认。
3. 零候选只回复“当前条件下未查到对应人员或相关数据”，并请用户核对姓名、工号或范围；不得说“没有薪资档案”。
4. 用户给字段展示名时，读取[档案详情契约](../../commands/salary-profile-detail.md)并执行 fields-only。唯一字段匹配后保存 code，多候选按名称、类型和选项确认。
5. 用户确认唯一员工和字段范围后执行详情。结构化响应中的员工摘要、`fields/profiles` 与请求范围一致，才算当前查询完成。

## 停止条件

- 员工或字段存在多个候选且用户未确认；
- 详情没有真实 staffId、字段超过 50 个或契约不足；
- 用户要求自动翻页、枚举员工、读取未确认字段或用档案推算历史实发；
- 鉴权、权限、业务、网络或响应解释失败。不得回退 Staff、旧详情或 raw 接口。
