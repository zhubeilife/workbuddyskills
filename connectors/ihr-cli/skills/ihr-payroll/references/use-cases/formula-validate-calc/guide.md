# Use Case：校验与试算薪资公式

## 目标定义

在不修改公司薪资模板的前提下，确认薪资公式的语法、字段引用、函数和循环依赖，并可用用户明确的样例值进行试算。校验和试算分别报告证据，不把它们表述为保存成功或实际工资结果。

## 业务判断

1. 先确认用户要校验、试算，还是最终保存到已有模板。
2. 用户以薪资项目名称编写时使用 `IDEOGRAPHIC`；已经是字段 code 时使用 `CODE`。
3. Excel 单元格公式不能直接当作薪资系统公式，必须先按专用 Excel/公式流程转换和确认。
4. 使用函数时先查询当前函数集合，并按[薪资公式](../../domain/formula.md)和[公式语言](../../commands/formula-language.md)解释。
5. 用户最终要保存到模板时，本 Use Case 在校验/试算后结束，后续改读[公式编辑 Use Case](../formula-edit/guide.md)。

## 执行与验证

1. 在[公开命令导航](../../domain/commands.md)定位 `formula +functions/+validate/+calc`，分别读取 Help 和过渡 Reference。
2. 校验前确认当前字段、公式正文、公式格式和所有可引用字段；执行 `formula +validate`。
3. 只有响应明确表示校验通过，且返回的规范化公式/`exprItems` 与当前字段一致，才报告校验通过。
4. 需要试算时，使用校验后的内部 code 公式和用户明确的样例字段值，确认进位规则和小数位后执行 `formula +calc`。
5. 试算结果只标注为“当前样例结果”，不推断员工实际工资、模板值或台账值。

## 停止条件

- 字段或函数多候选、引用不完整、存在循环依赖或公式不能转换；
- 用户未给试算所需样例值、进位规则或小数位；
- 用户要求跳过校验直接保存，或把 Excel 公式直接写入模板；
- 鉴权、权限、业务、网络或响应解释失败。不得删改公式片段后自动重试。
