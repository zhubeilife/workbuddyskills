# Use Case：编辑薪资字段公式

## 目标定义

本 Use Case 独立处理一个或多个薪资字段公式。Excel 工作簿、表格识别、薪资项目匹配和模板创建均不是前置条件；用户可以直接提供公式、字段映射、样例值和可选模板 ID。

公式处理的字段确认和选项确认遵循 `ihr-payroll` 的 `references/commands/display-names.md`：字段引用、公式格式、来源、进位规则和结果状态用名称展示。code 公式只作为内部 payload 或后续保存结果，不作为用户选择字段的标签；接口缺少名称时先向用户询问名称。

## 业务判断

| 用户目标 | 必要输入 | 执行范围 |
| --- | --- | --- |
| 只校验/预览公式 | 公式正文；所有引用与薪资项目名称或 code 的对应关系 | `VALIDATE` |
| 只试算公式 | 经校验返回的内部 code 公式、依赖样例、进位规则和小数位 | `CALCULATE` |
| 修改并保存模板公式 | `payrollConfigId`、唯一目标字段、源公式文本、依赖样例 | `SNAPSHOT -> VALIDATE -> CALCULATE -> SAVE` |

用户只要求校验、预览或试算时，在该阶段完成后停止。不得把只读意图升级为模板修改。

用户把工作簿作为输入且目标是生成完整公司模板时，改读[公司薪资模板复杂目标导航](../../domain/company-template.md)。

## 执行与验证

读取 [公式处理流程](formula-workflow.md)。确认每个 Excel 单元格/列或业务概念对应的薪资项目；缺失、歧义或无法保持原语义时询问用户，不生成近似公式。用户确认、修改或接受推荐的公式必须是当前编辑器中的薪资系统公式文本；Excel 单元格公式只能作为来源展示，不能作为最终确认公式。Excel 公式列来自模板创建流程时，不论目标字段是复用项目、加入系统项目还是新建项目，都必须逐列确认最终处理方式：沿用目标项目当前设置、改为输入，或改为使用薪资系统公式。

当用户提供的 Excel 公式包含 `VLOOKUP` 时，先进入“查找表迁移选择”，向用户同时提供两种方案，并在用户选择前保持 `needs_confirmation`：

1. **按表单内容改写为嵌套 `IF`**：读取用户提供的查找表内容、匹配模式和返回列，把每一行映射转换为 `IF` 分支。精确匹配必须使用等于判断；近似匹配只有在查找键顺序、边界和未命中行为已确认后才能使用大小比较。查找表缺少内容或语义不完整时，先向用户补齐，不猜测规则。
2. **在智搭云添加对应表单后使用 `VLOOKUP`**：建议用户先在智搭云建立包含查找键和返回值的业务表单，再把该数据源映射为薪资公式可引用的字段，随后按当前公式语言转换为 `VLOOKUP`。该方案不把 Excel 区域地址直接带入薪资公式；表单创建和字段映射须由用户另行确认，本 Use Case 不代替用户创建智搭云表单。

展示方案时说明取舍：嵌套 `IF` 适合规则少且稳定的查找表，标准调整需要改公式；智搭云表单适合规则经常变化或需要业务人员维护的查找表，但需要先完成表单和字段接入。用户选定方案后，继续生成薪资系统公式、校验并试算；未选定前不得将原 Excel `VLOOKUP` 直接翻译为已完成公式。

按需读取当前公司函数、公式语言语义和 Excel 差异。公司模板编辑场景中，先用 `formula +validate` 把当前编辑器公式文本提交给 `cirDependency`；公式文本使用薪资项目名称时传 `formulaFormat=IDEOGRAPHIC`，只有用户明确提供字段 code 公式时才传 `CODE`。校验通过后使用返回的 `codeFormula` 作为后续试算和保存用内部公式；保存前必须对每个目标分别取得 `validated=true` 和 `formula +calc` 的非空结果。用户还需确认试算结果符合预期。若必须通过 stdin 传入中文公式文本，先显式设定 UTF-8 输入/输出编码，避免默认管道把中文替换成 `?`。

## 模板保存

用户明确要求修改模板时，读取 [模板公式保存流程](save-workflow.md)。从最新 snapshot 复制完整规则，只修改已确认目标的 `source` 和公式设置；保留项目位置、其他项目、`originSource`、类型、计税、进位及其余设置。

先执行 `companyTemplate +save-rules --dry-run`，展示每个目标项目名称、旧公式、当前编辑器公式文本、试算结果，以及完整模板项目统计。取得只覆盖当前 snapshot 和 payload 的独立确认后只保存一次；只有 `verified=true` 才算保存完成。内部 code 公式由校验返回的 `exprItems` 拼接生成，只在用户明确要求技术详情时展示。

## 确认与恢复

- 公式查询、校验和试算只在用户明确的公式与字段范围内执行；多个目标逐个完成校验与试算，不自动扩大到模板其他项目。
- 保存确认独立于公式处理确认。用户确认试算不等于授权写入模板。
- 参数或公式错误可以在同一目标范围内修正后重新转换、校验和试算。
- 鉴权、权限、业务失败或无法确定字段映射时停止；不使用其他公司数据或 raw 接口补齐。
- 保存前 snapshot 过期时重新读取、重新生成预览并重新确认。保存结果未知时只读 snapshot 核对，不自动再次写入。
- 只使用本 Use Case 引用的 payroll Shortcut，不使用 `ihr-interface`、完整 URL、裸 HTTP 或身份字段绕过。

## 产物

用户未指定输出位置时，在系统临时目录的 `ihr-cli/payroll-formula-edit/<唯一运行 ID>/artifact-vNNN/` 写出 [公式处理产物](artifact-schema.md)。不询问临时目录，不写项目源码、当前工作目录或 `test/runs`。样例原始值默认不写入产物。

## 完成条件

- 只读模式：对应阶段有明确成功结果，产物状态与用户目标一致，没有把未执行阶段标记完成。
- 保存模式：所有目标均完成校验、非空试算及结果确认；保存读回 `verified=true`，模板 ID 和目标公式一致。
- 任何未解析引用、校验失败、未确认试算结果、写入未知或读回不一致均为未完成。
