# Use Case：查询人员个税扣缴义务人

## 目标定义

在当前 Payroll 数据范围内定位一个员工，并查询该员工的扣缴主体关系记录。结果只呈现命令返回的主体、税号、日期和变动信息，不自行推断当前有效主体，也不等同 CNB 申报状态。

## 业务判断

1. 用户给姓名或工号时，只用 `salaryProfile +list` 的最小查询定位 staffId；不读取动态档案字段。
2. 零候选只说明未查到对应人员或相关数据，不得说员工没有薪资档案或扣缴关系。
3. 多候选按姓名、工号和部门确认，不循环尝试 staffId。
4. 用户要 CNB 申报主体、申报状态或缴款汇总时，改走对应 CNB 查询命令，不使用本 Use Case。
5. 用户要主体列表、多员工查询、修改扣缴关系或按日期自动认定当前主体时，当前能力不支持。

## 执行与验证

1. 在[公开命令导航](../../domain/commands.md)定位 `salaryProfile +list`，读取 Help 和[档案列表契约](../../commands/salary-profile-list.md)，取得唯一员工。
2. 定位 `corporation +detail`，读取 Help 和[扣缴义务人契约](../../commands/corporation.md)。
3. 用户确认一个员工身份后执行一次详情。响应 `staffId` 与前序员工一致且 `records` 可解释时，才算完成。
4. 按原值呈现用户要求的 Payroll/个税业务字段；内部 ID、页面控制字段和未请求字段不主动展示。

## 停止条件

- 员工零候选或多候选未确认；
- 请求主体列表、批量员工、关系修改或当前能力未返回的状态；
- 鉴权、权限、业务、网络或响应解释失败。不得改用 Staff、Master Data、相邻主体接口或 raw 请求。
