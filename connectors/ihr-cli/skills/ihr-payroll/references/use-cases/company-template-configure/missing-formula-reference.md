# 保存时补齐公式引用项目

`companyTemplate +save-rules` 返回本错误后执行。完成条件：缺失引用已补进模板并再次保存成功，或用户拒绝/无法解析后第二步保持未完成。

## 识别

错误文案匹配：`公式中，引用的【…】尚未添加至当前薪资表，无法引用`

按顺序取到第一条能解析出【】的文案：

1. `error.message` 为 JSON 对象（或可解析为对象）时，遍历每个值的 `errorMsg` / `name` / `code`
2. `error.message` 为字符串时，按上述句式提取

`name` 是公式所在项目的业务名称。【】内是尚未入表的引用，格式 `来源名称$项目名称`，例如 `员工薪资$绩效工资`。一条响应可含多个缺失引用，全部列出后再问一次。

完成：全部【】引用已列出；解析失败则展示原始错误文案并停止。

## 确认

向用户展示公式项目名称、尚未入表的来源名称与项目名称，并确认是否把这些引用项目加入当前模板后重新保存。

- 拒绝：第二步保持未完成
- 确认：只覆盖本次列出的引用项目；此前 RULES 保存确认失效

## 加入

1. 读取最新 `companyTemplate +snapshot`，并用同一模板执行 `companyTemplate +addable-fields --for-rules`；本次 RULES 已读且未过期时可复用。
2. 对每个【来源名称$项目名称】，在 snapshot 中尚不存在的 addable 叶子里解析唯一 `ruleField`：先按项目名称精确匹配；多候选用来源名称收窄（`sourceName`、`ruleField.refService` 或分组路径中的来源名称）；仍不唯一则列出项目名称、类型名称、类别名称和来源名称请用户选择。零候选或该名称已在模板中：停止并报告。
3. 把确认后的 `ruleField` 合并进完整 rules：默认放到公式项目同一分组、紧挨其前；公式项目未分组则进入未分组列表、紧挨其前。用户指定分组时按用户指定。同一 `code` 只保留一次。

完成：每个确认加入的引用都有唯一 `ruleField` 且已合并进完整 rules。

## 保存

按[第二步配置规则](second-step-rules.md)用最新 snapshot 重新合并，生成新 payload 并 `--dry-run`。确认摘要展示新增项目名称、分组位置，以及新的分组数、项目总数、输入项数和公式项数。取得只覆盖该新 payload 的确认后执行一次 `save-rules`。

完成：`verified=true`，或写入已发生后只读快照满足第二步业务不变量。同类错误且缺失引用集合与上次不同时，回到识别；集合相同则停止。
