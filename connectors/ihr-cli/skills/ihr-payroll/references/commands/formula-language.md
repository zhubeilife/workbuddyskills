# 薪资公式语言参考

## 说明

本文只描述薪资公式引擎的表达式语法，以及已有函数的签名、参数、运算逻辑和 Excel 差异。

公式以 `=` 开头；未以 `=` 开头的输入会被当作单个值，而不是表达式。字符串使用双引号，例如 `"在职"`。示例中的 `fieldCode` 表示薪资项目或其他可引用字段的编码。

## 运算符与语法符号

### 运算符

| 符号 | 含义 | 当前逻辑 | 与 Excel 的主要差异 |
| --- | --- | --- | --- |
| `+` | 加法 | 两个操作数相加；一元 `-x` 按 `0-x` 处理，但不支持一元 `+x` | 数字字符串会转成数字，空值或缺失值按 `0`；Excel 的隐式转换规则更复杂 |
| `-` | 减法/负数 | 左值减右值 | 同上 |
| `*` | 乘法 | 两个操作数相乘 | 同上 |
| `/` | 除法 | 除数为 `0` 返回除零错误；普通数值计算保留 12 位并使用 HALF_EVEN | Excel 使用自身浮点精度，不承诺相同的第 12 位舍入结果 |
| `^` | 乘方 | 使用浮点乘方；与 `*`、`/`、`&` 位于同一解析层级 | Excel 的幂运算优先级与本引擎不同，连续混用时必须加括号 |
| `&` | 字符串连接 | 字符串直接连接；数字、空白和日期先转成文本，其他类型报错 | 与 Excel 的类型转换范围不同 |
| `=` | 等于 | 数字按值比较；日期按时间比较；字符串按区分大小写的字典序比较，数字与可转数字字符串可按数值比较 | 公式开头的第一个 `=` 只是公式标记，不参与比较 |
| `≠` | 不等于 | 等于的反运算 | 不支持 Excel 常用的 `<>` 写法，必须使用 `≠` |
| `<`、`<=`、`>`、`>=` | 大小比较 | 数字、日期和字符串按各自规则比较；空值参与大小比较时返回 `FALSE` | 混合类型比较和空值规则不保证与 Excel 一致 |

数字字符串可参与四则运算；空值和缺失变量按 `0` 参与四则运算；不可转成数字的文本会报参数类型错误。比较式、幂运算、连接符和四则运算混用时应显式使用括号，避免依赖解析器与 Excel 不同的优先级。

### 结构符号

| 符号 | 用途 |
| --- | --- |
| `(`、`)` | 函数参数和表达式分组 |
| `,` | 分隔函数参数或数组同一行的元素 |
| `{`、`}` | 定义数组常量，例如 `{1,2;3,4}` |
| `;` | 分隔数组的行 |
| `$` | 连接变量的命名空间与字段名 |

## 通用规则

- 函数名不区分大小写，本文统一使用大写。
- 日期函数主要接受日期值或可解析的日期字符串，不接受 Excel 日期序列号。可识别的字符串格式包括 `yyyy-MM-dd`、`yyyy-MM-dd HH:mm:ss`、`yyyy/MM/dd`、`yyyy-MM` 和 13 位毫秒时间戳；未匹配格式时返回空日期或函数定义的日期错误。
- 多数需要整数的参数会直接截去小数部分，而不是四舍五入。
- 数组按行、列保存。部分查找和统计函数只读取第一行或第一列，具体见函数条目。
- 被选中的参数或依赖字段计算出错误时，多数函数会原样传播该错误；各函数的特殊空值规则以对应条目为准。
- Excel 差异只描述当前实现能够确认的行为。名称相同不表示签名、类型转换、返回类型或错误值相同。

## 逻辑与选择

### `AND(value1[, value2, ...])`

- 参数：至少 1 个。每个标量参数必须是数字或布尔值；`0` 为假，非 `0` 为真。数组会逐元素检查。
- 逻辑：遇到第一个假值立即返回 `FALSE`；缺失值在标量或数组中按真处理，数组中的非数字值按假处理。
- Excel 差异：Excel 通常忽略引用区域中的文本和空白；本引擎的数组非数字值会使结果为假，标量非数字值直接报错。

### `OR(value1[, value2, ...])`

- 参数：至少 1 个。数字或布尔值按 `0/非0` 判断；数组会逐元素检查。
- 逻辑：遇到第一个真值立即返回 `TRUE`；缺失值按假处理，数组中的非数字值也按假处理。
- Excel 差异：Excel 对引用区域中的文本、空白和“没有逻辑值”的错误规则不同；本引擎标量非数字值会报错。

### `IF(logical_test, value_if_true[, value_if_false])`

- 参数：2 或 3 个。`logical_test` 必须计算为数字或布尔值；省略第三个参数时默认为 `FALSE`。
- 逻辑：`logical_test` 为非 `0` 时只计算并返回第二个参数，否则只计算第三个参数；被选中结果为缺失值时返回 `0`。
- Excel 差异：本引擎不接受普通文本作为条件，并把被选中的缺失值固定转为 `0`。

### `TRUE()` / `FALSE()`

- 参数：无。
- 逻辑：分别返回布尔值 `TRUE` 和 `FALSE`，参与数字运算时分别相当于 `1` 和 `0`。
- Excel 差异：核心语义一致；返回值仍受本引擎自己的类型转换规则约束。

### `CHOOSE(index_num, value_array[, default_value])`

- 参数：2 或 3 个。`index_num` 为整数；`value_array` 必须是数组；`default_value` 为未命中时的可选默认值。
- 逻辑：从数组第一行取第 `index_num` 列，索引从 `1` 开始。索引为 `-1` 或超出列数时返回默认值；没有默认值时返回错误。应只使用 `-1` 或大于等于 `1` 的索引。
- Excel 差异：Excel 的签名是 `CHOOSE(index_num, value1, value2, ...)`；本引擎把所有候选放在第二个数组参数中，并额外定义了 `-1` 和默认值语义。

## 统计与排序

### `AVERAGE(number1[, number2, ...])`

- 参数：至少 1 个。
- 逻辑：只统计顶层数字参数和可转成数字的字符串；其他值忽略。数组不会展开。没有有效数字时返回 `0`。
- Excel 差异：Excel 支持范围/数组并在没有数字时返回除零错误；本引擎不展开数组、忽略布尔值，并返回 `0`。

### `COUNT(value)`

- 参数：恰好 1 个。
- 逻辑：参数中的函数错误会传播；除此之外固定返回 `1`，不会真正统计数组或数字数量。
- Excel 差异：Excel 会统计所有数字值；本引擎当前不是 Excel `COUNT` 的计数实现。

### `LARGE(array, k)` / `SMALL(array, k)`

- 参数：恰好 2 个。第一参数必须直接计算为数组；`k` 为从 `1` 开始的整数名次。
- 逻辑：数组元素必须为数字；空元素按 `0`；`LARGE` 降序、`SMALL` 升序后取第 `k` 个。`k<1` 或超过元素数返回错误。
- Excel 差异：Excel 通常忽略数组中的空白和文本；本引擎把空白计为 `0`，非数字文本会报错。

### `MAX(value1[, value2, ...])` / `MIN(value1[, value2, ...])`

- 参数：至少 1 个；数组会递归展开。
- 逻辑：同类数字取最大/最小值，日期比较先后并返回 `yyyy-MM-dd` 文本，字符串按字典序比较。空集合返回 `0`。混合数字、日期和文本时，结果类型及比较范围会受参数顺序影响，应只传同类值。
- Excel 差异：Excel 的 `MAX/MIN` 主要返回数字并按引用/直接参数区别处理文本；本引擎允许字符串和日期参与比较，且混合类型具有顺序依赖。

### `RANK(number_field, FIELD(reference), [order])`

- 参数：2 或 3 个。第一参数必须是字段变量；第二参数必须写成 `FIELD(...)`；第三参数必须是整数字面量 `0` 或 `1`。
- 逻辑：参数结构合法且依赖没有错误时固定返回 `1`，没有执行真实排名。
- Excel 差异：Excel 会在引用集合中计算实际名次；本引擎当前只校验特定字段结构并返回常量。

### `SUM(number1[, number2, ...])`

- 参数：至少 1 个；数组会递归展开。
- 逻辑：累加数字和布尔值，非数字值、数字字符串和错误对象按 `0` 忽略。
- Excel 差异：Excel 对直接参数、引用中的布尔值/数字文本以及错误值有不同规则；本引擎会忽略错误值，并且不转换数字字符串。

### `SUMIF(range, criteria, sum_range[, ...])`

- 参数：至少 3 个，多余参数忽略。`range` 和 `sum_range` 必须是数组。
- 逻辑：只逐行比较 `range` 第一列，与 `criteria` 做不区分大小写的精确相等比较；命中行对应的 `sum_range` 第一列转为数字后累加。无命中返回 `0`。
- Excel 差异：Excel 的 `sum_range` 可省略，并支持 `>10`、通配符等条件语法；本引擎要求第三参数，只支持精确相等，且只读取两个数组的第一列。

## 舍入与格式化

### `ROUND(number, num_digits)`

- 参数：恰好 2 个。`number` 可为数字或数字字符串；`num_digits` 必须为数字并截成整数。
- 逻辑：按 HALF_UP 舍入，负数先取绝对值再恢复符号，因此中点远离 `0`；`num_digits<0` 返回不支持错误。
- Excel 差异：Excel 支持负的位数，用于舍入到十位、百位等；本引擎只支持 `0` 及以上。

### `ROUNDDOWN(number, num_digits)`

- 参数：恰好 2 个，位数必须为非负整数。
- 逻辑：按指定小数位向 `0` 截断。
- Excel 差异：方向与 Excel 接近，但 Excel 支持负位数；本引擎不支持。

### `ROUNDUP(number, num_digits)`

- 参数：恰好 2 个，位数必须为非负整数；日期类型明确不支持。
- 逻辑：只要被舍弃部分非 `0`，就按指定小数位远离 `0` 舍入。
- Excel 差异：方向与 Excel 接近，但 Excel 支持负位数；本引擎不支持，且日期输入返回专用错误。

### `CEILING(number, significance)`

- 参数：恰好 2 个严格数字参数，两个非零参数必须同号。
- 逻辑：`significance=0` 返回 `0`；其他情况按 `number - number % significance + significance` 计算，负的 `significance` 在取余后按 `0` 参与最后一步。
- Excel 差异：当前算法与 Excel 不等价，尤其正数已是基数整数倍时仍会再加一个基数，例如 `CEILING(10,5)` 返回 `15`。

### `FLOOR(number, significance)`

- 参数：恰好 2 个严格数字参数，两个非零参数必须同号。
- 逻辑：`significance=0` 返回 `0`；否则计算 `number - round(number % significance, 8)`。
- Excel 差异：Excel 各版本的 `FLOOR`/`FLOOR.MATH` 对负数和零基数有专门规则；本引擎固定使用上述取余算法，零基数返回 `0`。

### `FIXED(number, decimals[, no_commas])`

- 参数：2 或 3 个。前两个必须为数字；`decimals` 是格式化小数位；`no_commas` 用 `0/FALSE` 或非 `0/TRUE` 控制是否移除千分位。
- 逻辑：先按 `ROUND` 逻辑舍入，再按运行环境区域格式返回字符串。`no_commas` 省略或为假时包含千分位。
- Excel 差异：Excel 的 `decimals` 可省略且默认为 `2`；本引擎要求显式提供，并受服务运行环境的数字格式影响。

## 文本

### `CONCATENATE(text1[, text2, ...])`

- 参数：至少 1 个。
- 逻辑：字符串原样拼接，数字和布尔值使用其文本形式；日期、数组、空白及其他类型直接忽略。
- Excel 差异：Excel 会转换更多标量类型，也支持更广的引用行为；本引擎只拼接字符串和数字类值。

### `LEFT(text, num_chars)` / `RIGHT(text, num_chars)`

- 参数：恰好 2 个。文本参数可由数字或日期转成文本；长度参数截成整数且必须至少为 `1`。
- 逻辑：分别返回最左或最右的指定字符数；长度超过文本时返回整个文本。
- Excel 差异：Excel 的 `num_chars` 可省略且默认 `1`，并允许 `0` 返回空文本；本引擎必须提供且拒绝 `0`。

### `LEN(text)`

- 参数：恰好 1 个；数组返回值错误。
- 逻辑：字符串计算 Java UTF-16 长度，其他标量先使用其文本形式；返回数字类型。
- Excel 差异：包含代理对的 Unicode 字符可能按两个代码单元计数；这不保证与新版 Excel 的字符计数一致。

### `MID(text, start_num, num_chars)`

- 参数：恰好 3 个。起始位置从 `1` 开始；起始位置和长度均截去小数。
- 逻辑：`start_num<1` 或 `num_chars<0` 返回错误；长度为 `0` 返回空文本；超出文本尾部时截到结尾。
- Excel 差异：核心截取规则接近；本引擎会把数字和日期参数直接转成自身文本格式，错误文本和类型转换细节不同。

### `SEARCH(source_text, target_text[, from_index])`

- 参数：2 或 3 个。第一参数是被搜索的完整文本，第二参数是要找的文本；`from_index` 是可选的零基起点，默认 `0`。
- 逻辑：执行区分大小写的普通子串搜索；找到时返回一基位置，未找到返回 `0`。不支持通配符。
- Excel 差异：Excel 的参数顺序是 `SEARCH(find_text, within_text, [start_num])`，搜索不区分大小写，起点从 `1` 开始，支持通配符，未找到返回错误；本引擎这些行为均不同。

### `TEXT(value, format_text)`

- 参数：恰好 2 个，第一参数必须为数字。
- 逻辑：当前格式化器不产生结果，因此合法数字输入也返回值错误；第二参数当前没有形成可用的格式化行为。
- Excel 差异：Excel 会按 `format_text` 返回格式化文本；本引擎当前没有实现该运算逻辑。

### `VALUE(text)`

- 参数：恰好 1 个。
- 逻辑：数字原样返回；文本只按标准浮点数字面量转换，数组返回值错误，转换失败也返回值错误。
- Excel 差异：Excel 可理解千分位、货币、百分比和多种日期/区域格式；本引擎不处理这些本地化格式。

## 日期与日历

### `DATE(year, month, day)`

- 参数：恰好 3 个，可为数字或数字字符串，均截去小数。年份范围为 `1900-9999`；月份必须大于 `-year*12`；日期不能小于 `-31`。
- 逻辑：使用宽松日历构造日期，月份和日期可正向或负向跨月滚动，返回 `yyyy-MM-dd` 字符串。
- Excel 差异：Excel 把 `0-1899` 的年份加 `1900`，本引擎直接拒绝；返回值是日期文本而不是 Excel 日期序列号，负日期还有额外下限。

### `DATEDIF(start_date, end_date[, unit[, signed]])`

- 参数：2 到 4 个。`unit` 默认为 `D`，支持 `Y`（完整年）、`M`（完整月）、`D`（天）、`H`（小时）、`N`（分钟）；第四参数只接受文本 `TRUE`。
- 逻辑：默认返回绝对差值；第四参数为 `TRUE` 时保留 `end-start` 的正负号。小时和分钟计算前去掉秒和毫秒。无效日期在正常计算中返回 `0`。
- Excel 差异：Excel 必须提供第三参数，支持 `MD/YM/YD`，不支持 `H/N`，且开始日期晚于结束日期通常报错；本引擎默认绝对值，并用第四参数开启有符号结果。

### `YEAR(date)` / `MONTH(date)` / `DAY(date)` / `HOUR(date)` / `MINUTE(date)`

- 参数：各恰好 1 个，接受日期值或可解析日期字符串。
- 逻辑：按服务运行时默认时区取对应字段。空日期对象返回 `0`，空字符串返回空值；数字和 Excel 日期序列号返回日期格式错误。
- Excel 差异：Excel 接受日期序列号并返回对应部分；本引擎主要接受日期或日期文本，返回类型和空值行为不同。

### `EOMONTH(start_date, months)`

- 参数：恰好 2 个。开始日期为日期或日期字符串；月份偏移必须为数字并截成整数。
- 逻辑：先移动指定月数，再返回目标月最后一天的 `yyyy-MM-dd` 字符串。
- Excel 差异：Excel 返回日期序列号并可按 Excel 日期规则转换输入；本引擎返回文本且不接受序列号。

### `TODAY()`

- 参数：无。
- 逻辑：按服务默认时区返回当前日期的 `yyyy-MM-dd` 字符串，每次计算重新取值。
- Excel 差异：Excel 返回可参与日期运算的序列值；本引擎返回文本。

### `NOW()`

- 参数：无。
- 逻辑：与 `TODAY()` 完全相同，只返回 `yyyy-MM-dd`，不包含时间。
- Excel 差异：Excel `NOW()` 返回当前日期和时间；本引擎不会返回时、分、秒。

### `WEEKDAY(date)`

- 参数：恰好 1 个，接受日期或日期字符串。
- 逻辑：返回 `星期日` 到 `星期六` 的中文字符串。
- Excel 差异：Excel 返回数字并可用 `return_type` 选择编号体系；本引擎不接受第二参数，返回中文星期名称。

### `WEEKNUM(date[, return_type])`

- 参数：1 或 2 个。日期可为日期值、日期字符串或 `1900-9999` 的整数年份；`return_type` 只支持数字 `1`（周日开始）或 `2`（周一开始），默认 `1`。
- 逻辑：1 月 1 日所在周为第 1 周，根据指定周起始日计算当年第几周；整数年份按该年日期解析。
- Excel 差异：Excel 支持更多 `return_type`，包括 ISO 体系；本引擎只支持 `1/2`，也额外接受单独的年份整数。

### `NETWORKDAYS(start_date, end_date[, holidays])`

- 参数：2 或 3 个；`holidays` 必须是日期数组。
- 逻辑：开始、结束日期均计入范围。开始晚于结束返回错误。工作日由求值上下文中的公司和日历模板决定：特殊日期优先，其次是调休工作日、法定/调整休息日和模板工作周；`holidays` 再排除指定日期。
- Excel 差异：Excel 默认只按周六、周日和显式假期计算；本引擎会读取公司日历、法定节假日、调休和特殊工作日，结果可能明显不同。

### `NETWORKDAYS_INTL(start_date, end_date[, weekend[, holidays]])`

- 参数：2 到 4 个。`weekend` 可为 Excel 风格代码 `1-7`、`11-17`，或周一到周日的 7 字符串，`1` 表示周末；默认 `0000011`。第四参数必须是日期数组。
- 逻辑：范围包含首尾日期。开始晚于结束时先交换范围计算，再返回负数；显式假期从工作日中排除。7 字符串中只有字符 `1` 会被视为周末。
- Excel 差异：函数名使用下划线而不是 Excel 的点号；本引擎接受任意 7 字符串并只识别其中的 `1`，日期也不使用 Excel 序列号。

### `LHOLIDAYDAYS(start_date, end_date[, ...])`

- 参数：至少 2 个，多余参数会被解析但不参与结果。
- 逻辑：按首尾日期的闭区间，从求值上下文中的公司和日历模板统计同时标记为“法定类别”和“法定节假日”的日期数；空日期返回 `0`，开始晚于结束返回错误。
- Excel 差异：这是业务自定义函数，Excel 没有同名标准函数；结果依赖公司日历数据。

## 查找与引用

### `MATCH(lookup_value, lookup_array)`

- 参数：恰好 2 个。第二参数必须为数组。
- 逻辑：只扫描数组第一行，做不区分大小写的精确匹配；返回从 `1` 开始的列号，未找到返回 `-1`。
- Excel 差异：Excel 可用第三参数选择精确或近似匹配，默认近似匹配，未找到返回 `#N/A`；本引擎只有两参数精确模式并返回 `-1`。

### `LOOKUP(lookup_value, table_array)`

- 参数：恰好 2 个。第二参数必须至少有 2 列。
- 逻辑：在第一列按升序近似查找，返回同一行第二列；精确值优先，否则取不大于查找值的最后一行。查找值小于首行或数组无效时返回值错误。数字按数值顺序比较；同类型字符串只区分相等与不等，不提供可靠的字典序近似匹配。
- Excel 差异：Excel 支持向量形式和结果向量；本引擎固定使用二维数组的第 1、2 列。

### `VLOOKUP(lookup_value, table_array, result_column[, mode_or_result_column])`

- 参数：3 或 4 个。三参数形式在第一列查找，第三参数指定返回列。四参数的第四值若能转为文本 `TRUE/FALSE`，使用 Excel 风格近似/精确模式；否则启用旧式四参数：第三参数指定查找列，第四参数指定返回列，均从 `1` 开始。
- 逻辑：近似模式要求查找列升序，精确值优先，否则取不大于查找值的最后一行；精确模式未命中返回空字符串。结果列越界返回错误。
- Excel 差异：Excel 的第四参数只表示近似/精确，并常用数字 `0/1`；本引擎只有第四参数转成文本后等于 `TRUE/FALSE` 才进入该模式，数字 `0/1` 会进入“查找列+返回列”的旧式重载。精确未命中返回空字符串而非 `#N/A`，近似未命中和单行数组也有不同边界行为。

### `HLOOKUP(lookup_value, table_array, result_row[, result_row_legacy])`

- 参数：3 或 4 个。三参数形式在第一行查找并由第三参数指定返回行；四参数形式把第三参数改为查找行、第四参数作为返回行，均从 `1` 开始。
- 逻辑：始终按升序近似查找，精确值优先，否则取不大于查找值的最后一列；不提供精确模式开关。
- Excel 差异：Excel 的第四参数是近似/精确布尔值；本引擎第四参数是返回行号，四参数含义完全不同，且始终近似匹配。

## 扩展与占位函数

### `DISTANCE(coordinate_field1, coordinate_field2)`

- 参数：恰好 2 个，必须直接引用两个坐标字段，不能传经纬度字面量。
- 逻辑：校验经度 `[-180,180]`、纬度 `[-90,90]`，使用地球半径 `6371393` 米的 Haversine 公式返回两点球面距离，单位为米；坐标缺失返回空值错误。
- Excel 差异：Excel 没有同名标准函数；这是坐标字段专用函数。

### `HOC(hoc_field, option_name, option_id[, comparator])`

- 参数：3 或 4 个。第四参数支持 `=`、`≠`、`contains`，默认 `=`。
- 逻辑：字段必须计算为高级组件值。`=`/`≠` 比较选项 ID；`contains` 检查字段 ID 文本是否包含指定 ID。`option_name` 必须非空但不参与最终相等比较。字段或候选值缺失时，`=`/`contains` 返回假，`≠` 返回真。
- Excel 差异：Excel 没有同名标准函数；这是引擎扩展的高级组件选项 ID 比较函数。

### `FIELD(reference)`

- 参数：恰好 1 个。
- 逻辑：当前不产生可用返回值，主要作为 `RANK` 第二参数的结构标记。
- Excel 差异：Excel 没有同名标准工作表函数；本引擎也未实现字段集合读取。
