# 员工对象：固定信息与可配置字段

只在问题涉及员工身份、花名册、员工详情、固定字段、动态字段或字段筛选时读取。本文件定义“员工”这一业务对象；教育、工作经历、证书、家庭成员、绩效和培训属于[员工档案记录](archives.md)，入职、转正、调动和离职属于独立的任职业务流程，流程内部再由不同过程对象承载。

## 1. 对象定义

员工对象表示租户内一个人的员工身份、当前任职信息和与员工直接相关的资料。它不是待入职表单、某一条档案记录，也不是入职、转正、调动或离职流程的总称。

### 身份与范围

- `id` 是员工的稳定业务标识；部分命令把同一标识命名为 `staffId`。
- 部门、职位、职务、职级、主管和工作地点是员工在查询时点的任职引用。它们描述员工此刻的任职关系，不自动代表历史关系或待生效目标。
- 字段是否出现取决于命令的返回范围、员工数据权限、功能权限、租户配置和脱敏规则。字段未出现时不能直接解释为空。
- 本文件收录所有已确认且具有稳定业务含义的固定字段。底层预留列、排序辅助值、内部计算时间、展示拼接值、过程控制标志和没有明确含义的编号不进入员工业务字段表；它们也不能被 Agent 当作可发现字段或查询条件。

### 字段类型约定

| 类型 | 说明 |
| --- | --- |
| 文本 | 名称、代码、备注或外部账号等文本值 |
| 文本标识 | 以文本承载的业务 ID，例如 `jobTitleId`、`positionId` |
| 整数标识 | 以整数承载的业务 ID，例如 `departmentId` |
| 日期 | 业务日期或时间；具体输出格式以命令契约为准 |
| 整数 | 计数、时长或数量 |
| 小数 | 年限等允许小数的业务数值 |
| 布尔值 | 是/否开关或认证结果 |
| 动态字段集合 | 由租户字段定义决定的字段名和值集合 |

字段类型描述业务值的实际承载方式，不代替具体命令的参数和返回契约。特别注意：`jobTitleId`、`positionId`、`positionLevelId`、`supervisorId`、`companySiteId` 和 `corporationId` 都是文本标识；`departmentId` 与 `firstLevelDepartmentId` 是整数标识。

## 2. 固定业务字段

下表是员工对象中已确认有业务含义的固定字段目录。每个字段都单独列出名称、类型和用途；`staff +get` 可以返回比列表更多的字段，但具体字段仍受服务端权限、租户配置、脱敏和接口投影影响，不保证每条命令都会返回。

## 3. 不纳入业务字段表的底层属性

员工数据中可能存在以下几类值，但它们没有稳定、独立的业务含义，不能作为 Agent 的业务字段：

- 租户会话上下文标识、记录删除标记和内部更新时间；
- `basicInfo1`、`basicInfo2`、`hrInfo1` 至 `hrInfo20` 等没有固定业务名称的预留列；
- 部门全路径拼接值、排序序号、层级排序值等展示或排序辅助值；
- 计算时间、过程控制标志、文件标识拼接值和未声明结构的提醒人员值。

如果未来命令契约为其中某个值提供稳定的业务名称、类型和使用规则，应在对应业务对象中重新登记；在此之前不得通过字段名猜测含义、筛选条件或统计口径。

## 4. Flex Meta 与自定义字段

Flex Meta 描述租户配置了哪些员工字段、档案集合、字段类型和选项；员工对象保存的是字段值。两者必须先后确认，不能把元数据标识当作员工字段值。

| 标识 | 业务用途 | 约束 |
| --- | --- | --- |
| `metaDataId` | 定位一份字段或档案元数据配置 | 不是员工字段名，也不是档案记录标识 |
| `metaCode` | 定位一类档案集合 | 不能与 `metaDataId` 互换 |
| `fieldName` | 定位实际字段 code | 中文显示名不能直接当 code |
| `codeValueId` | 定位平铺选项集合 | 不能替代字段名 |
| `codeTypeId + groupCode` | 共同定位树形选项集合 | 两者缺一不可 |

### 已知字段名

用户已经给出真实 `fieldName` 时，可以在命令允许的范围内请求该字段值；这只证明值可返回，不自动证明字段的中文名称、选项文案或统计含义。

### 只有显示名或模糊描述

```text
用户表达
  -> 查询员工字段元数据
  -> 确认唯一 fieldName、字段类型和选项来源
  -> 查询员工值
```

无法获得唯一字段定义时，停止字段级查询，不猜字段名、类型或选项值。

### 自定义档案字段

自定义档案先确认元数据类型为 `SUBSET` 和真实 `metaCode`，再读取该档案记录。自定义档案字段不通过员工花名册的 `--fields` 代替；字段解释由该档案的元数据决定。

## 5. 主数据引用

员工结果中的组织引用与名称必须保持对应关系：

| 员工字段 | 业务对象 | 解析规则 |
| --- | --- | --- |
| `departmentId` / `departmentName` | 部门 | `departmentId` 是整数标识；已有名称时不重复解析 |
| `positionId` / `positionName` | 职位 | `positionId` 是文本标识 |
| `jobTitleId` / `jobTitleName` | 职务 | `jobTitleId` 是文本标识，不是整数 |
| `positionLevelId` / `positionLevelName` | 职级 | `positionLevelId` 是文本标识 |
| `corporationId` / `corporationName` | 法人公司 | `corporationId` 是文本标识，区别于租户上下文 |
| `companySiteId` / `companySiteName` | 工作地点 | `companySiteId` 是文本标识 |
| `supervisorId` / `supervisorName` | 员工 | 主管本身仍以员工标识定位 |

需要名称转标识时，按 [主数据解析 Skill](../../../ihr-master-data/SKILL.md) 的真实规则处理；不以名称相同作为关联证据。

## 6. 查询与停止规则

1. 先区分员工主记录、员工档案和入转调离流程中的过程对象；“员工资料”不自动展开全部对象。
2. 姓名、工号和手机号只用于发现候选；详情、档案明细和培训明细需要唯一员工标识。
3. 执行查询前先在[Staff 公开命令导航](commands.md)定位命令，再读取该命令的 Help、Schema 或过渡命令 Reference。
4. `--fields` 只选择返回投影；字段名和筛选操作符必须有元数据或命令契约证据。
5. 字段未返回可能是未请求、权限、脱敏、租户配置或服务端投影造成的；不能直接断言字段为空。
