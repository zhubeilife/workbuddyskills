# 员工入职

只在问题涉及待入职、入职信息、入职登记表、入职审批、创建或编辑待入职，以及确认入职时读取。

## 四类记录与标识

| 业务内容 | 主要作用 | 稳定标识 | 当前公开动作 |
| --- | --- | --- | --- |
| 待入职表单 | 保存拟入职人员、预计入职日期、部门职位及确认状态 | `entryFormId` | 查询、详情、创建、编辑、确认入职 |
| 入职信息 | 承载登记资料和附件关联 | `entryInfoId` | 通过登记表结果用于附件查询或审核衔接 |
| 入职登记表 | 候选人提交的登记资料及 HR 审核状态 | `registrationId` | 审核列表、详情、附件、审核通过 |
| 入职审批记录 | 当前用户可见的业务审批记录 | 审批记录自己的业务标识 | 仅查询待审批列表 |

这些记录可能关联同一人员，但不能互换标识，也不能用一个状态推断另一个对象已经完成。

## 待入职状态与最终目标

`entry +search` 的 `state` 是列表入口，不是全局统一状态机：

| `state` | 列表含义 | 不代表 |
| --- | --- | --- |
| `pending` | 待入职记录 | 资料完整、登记审核或审批均已通过 |
| `joined` | 已确认入职记录 | 当前花名册全部字段或所有下游模块已经更新 |
| `abandoned` | 已放弃入职记录 | 员工办理过离职 |

创建成功只形成待入职记录；审核登记表成功只推进登记表；确认入职以待入职表单为目标触发归档，预计入职日期未到时可能先确认、后归档。用户只说“办理入职”时，如果目标阶段无法唯一判断，应询问“是新增待入职、修改待入职资料、审核登记表，还是确认待入职并触发归档？”

## 创建待入职

创建的最小业务信息为姓名、真实部门 ID、手机号和预计入职日期。部门名称必须经 Organization 或 Master Data 的公开能力解析为唯一 ID；职位、员工类型、合同类型、证件类型、性别和自定义字段等 code 必须来自可信输入或当前租户配置。

执行链会检查当前租户创建配置、动态必填字段、手机号重复、可选的证件号重复和黑名单。dry-run 只检查本地格式并展示这些计划，不会执行远端检查。手机号或证件号冲突、命中黑名单、动态必填缺失、无数据权限或强编制失败时停止。

## 编辑待入职

更新不是单字段 patch，而是基于当前详情构造完整更新载荷：

1. 用 `entryFormId` 读取当前详情。
2. 每次都读取当前租户对该记录可维护的字段规则。
3. 未修改字段沿用旧值；不得因用户没有重述而清空。
4. 只读字段不得修改；选项使用真实 `value`；只追问当前详情和用户输入都缺失的可编辑必填字段。
5. 规范化比较旧值与新值；没有实际变化时不提交。

字段规则属于当前租户、当前时点，不跨租户缓存。详情或字段规则读取失败时，整个编辑目标停止。

## 确认入职

确认入职是高影响写操作：目标必须是唯一、可见的待入职表单，并使用精确匹配的 `entryFormId` 确认。成功后还要回读已入职列表，并在预计日期满足归档条件且获得 `staffId` 时核对花名册；不能仅凭进程退出码宣布人员已经进入花名册。

确认前还必须核对关联流程状态。当前业务逻辑中：

- 登记表不在 `REJECTED/PASSED/ABANDON` 这些已结束状态时，确认待入职会放弃关联的登记表收集流程；
- 入职审批不在 `PASS/DENIED/ARCHIVE` 这些已结束状态时，确认待入职会放弃或作废关联审批。

如果存在进行中的登记收集或审批，必须向用户说明将被终止的具体对象和状态，并取得针对该副作用的明确确认；不能只展示“确认入职”四个字。

编制校验分两类：

- 强编制失败：停止，不能绕过。
- 弱编制警告：向用户解释具体警告，取得新的明确同意后，才允许以 `hcWeak=true` 重试一次。

网络超时或响应不明时先查询 `joined` 列表和花名册确认结果，不直接重复确认。

## 入职登记表审核

登记表审核列表只允许 `CONFIRM`（待确认）和 `RECHECK`（退回修改）。执行审核通过前必须：

1. 用同一个 `registrationId` 查询详情。
2. 核对姓名、脱敏手机号、登记状态及关联 `entryInfoId/entryFormId`。
3. 用户要求或模板规定需要附件时，查询附件槽位并检查必填材料是否存在；命令只读文件元数据，不读取文件内容。
4. 展示是否发送短信/邮件和审核备注，取得用户对该登记表的明确确认。

审核通过会把登记资料同步到已有待入职，或在没有对应记录时创建待入职，并可能按当前规则补充工号；它仍不等于确认入职或进入花名册。确认摘要必须同时说明“登记表将通过”和“对应待入职将被创建或更新”。

手机号、证件号重复，资料或权限校验失败，或强编制失败时停止；弱编警告只能在二次确认后重试一次。超时或结果未知时重新查询登记表和关联待入职状态，不重复提交。

## 入职审批查询

`entry application +search` 只查询当前用户可见的待审批入职记录，允许的待审批状态为 `INITIATE`、`WAITING_HR_APPROVAL`、`AUDIT`。它不是待入职表单列表，也不是登记表审核列表；当前没有处理该审批记录的公开 Staff 命令。
