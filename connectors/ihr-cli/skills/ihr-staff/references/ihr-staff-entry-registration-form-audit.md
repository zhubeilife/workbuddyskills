# ihr-cli staff entry registration-form +audit

按一条入职登记表 ID，在 CLI 进程内部完成模板员工必填字段检查，以及待入职、入职审批、有效黑名单和历史离职关联检查。

```bash
ihr-cli staff entry registration-form +audit --registration-id <登记表ID>
```

该命令先读取登记表详情，并按登记表模板的字段级 `staffRequired` 在 CLI 进程内计算员工必填字段是否缺失；随后在输出层脱敏前完成只读关联。关联优先级为：登记表详情中的 `entryProcessFormId` 关联待入职和入职审批；若流程 ID 缺失，待入职和历史离职可使用 CLI 进程内取得的完整手机号作为受限查询条件，`entryBasicInfoId` 仍可用于入职审批；只有这些业务条件都不可用时，才回退到完整证件号兼容查询。查询实际返回 0 条时直接表示“未发现记录”，只有查询条件不足、接口失败或候选无法唯一确认时才提示人工复核。黑名单改用租户感知的待入职黑名单校验接口，由服务端根据当前公司的黑名单基础设置决定使用证件号或姓名+手机号。调用方不得从 `+search` 或 `+get` 的脱敏输出提取证件号并传给其他命令，也不得自行替代租户黑名单匹配逻辑。

输入只支持一个登记表 ID，支持 `--json`/`--stdin`，与分项参数互斥；不分页、不批量、不执行任何写入。详情未返回任何姓名、手机号和证件号时，黑名单检查返回“未取得可关联身份”；查询返回 0 条时写“未发现相关记录”，不得改写为人工复核；仅在查询条件不足或接口失败时写“需人工复核”。黑名单仍可按租户配置使用姓名+手机号校验。任何不可用状态都不得推断为未命中。

这是 `READ / SENSITIVE + TENANT_SCOPED / SINGLE` 能力，当前审核助手使用它补充流程存在提示；审核通过仍需单独确认姓名和手机号后执行 `+approval-pass`。

## 必填字段结果

- 输出包含 `requiredFields` 员工必填字段完整性结果及四类辅助检查的 `matched`、`count`、`records`；`requiredFields` 只返回字段展示名、所属分组、缺失数量和状态，不输出动态字段编码或证件号。
- 员工漏填判据只来自模板字段级 `staffRequired`；银行卡字段未勾选员工必填时不得据此报缺失。审核人必填、公司级附件要求和 `bankFlag` 不参与员工漏填判断。
- 如果模板字段列表为空，或字段列表中任一字段没有返回 `staffRequired` 标识，`requiredFields.status` 返回 `UNAVAILABLE`，调用方必须写“需人工复核”，不得按“没有必填项”处理。

## 身份字段原值比对

- 待入职命中后，CLI 按流程表单 ID读取待入职详情；如果响应中的证件号或手机号被掩码，仍以精确业务 ID判定记录归属，不因掩码丢弃命中。存在可用原值时，再分别比较登记表详情与待入职详情的手机号、证件号。
- 输出只返回 `identityComparison.idCard` 和 `identityComparison.mobile` 状态：`MATCH`、`MISMATCH` 或 `UNAVAILABLE`，不返回原始手机号或证件号。
- 调用方必须按状态输出“一致/不一致/无法比对”，不得比较两侧掩码文本；`UNAVAILABLE` 不等同于“不一致”。
