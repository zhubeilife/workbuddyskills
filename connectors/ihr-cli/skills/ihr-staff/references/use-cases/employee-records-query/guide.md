# 查询同一员工的跨类别资料

## 目标定义

用户希望围绕同一个员工组合查询两个或更多独立数据范围，例如员工信息、固定或自定义档案、标签、合同、协议、培训、入转调离或异动记录。

完成标准是：唯一确认员工，只查询用户要求的类别，分别呈现每类结果、时点和失败边界。不得把各类结果拼成一个来源不明的“完整员工对象”。

## 业务判断

1. 把用户目标拆成明确类别，并按需读取对应 Domain Reference：
   - 员工对象及其动态字段：[员工对象：固定信息与可配置字段](../../domain/employee.md)；
   - 固定或自定义档案：[员工档案](../../domain/archives.md)；
   - 待入职与登记：[员工入职](../../domain/onboarding.md)；
   - 入职、转正、调动、离职：[入职、转正、调动与离职记录](../../domain/lifecycle.md)；
   - 标签、合同、协议、异动、培训：[员工业务记录](../../domain/employee-business-records.md)。
2. 用户只有姓名、工号或手机号时，先用最小花名册查询形成候选。零候选说明当前范围未返回；多候选只展示区分所需字段并请用户选择。
3. 后续命令要求 `staffId` 时，只使用已确认候选的 ID。教育经历按姓名或工号查询遵循 Archive 的直接条件，不强行改为 `staffId`。
4. 用户泛称“全部资料”时先确认所需类别和时间范围；不默认拉取全部动态字段、全部档案、全部历史单据或所有页。
5. 涉及自定义档案时转入[自定义员工档案](../custom-archive-query/guide.md)。只有动态字段中文名而没有真实 `fieldName` 时，当前 Meta Detail 缺口导致该部分停止，不影响其他已明确类别。

## 执行与验证

1. 在[公开命令导航](../../domain/commands.md)中为每个类别选择最小命令集合，并读取各自契约。
2. 列表命令默认只读取当前页；如果用户确实要求下一页，逐次明确继续，不自动全量翻页。
3. 分类别保留来源和业务含义：
   - 花名册是当前快照；
   - Archive 是经历记录；
   - 入职、转正、调动、离职记录是四种独立的过程业务记录；
   - 异动是已发生变化；
   - 合同、协议和培训各有独立粒度。
4. 对每个类别记录 `成功 / 空结果 / 未执行 / 失败 / 契约不足`。一个类别失败时可以保留其他成功结果，但整体不得称为“完整资料”。
5. 最终只展示用户要求的业务字段。内部 ID 只用于命令衔接，敏感信息脱敏；如果不同记录出现矛盾，只陈述各自来源和时点，不自行选一个覆盖另一个。
