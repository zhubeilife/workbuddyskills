# 确认单条待入职

## 目标定义

确认一条待入职记录。若预计入职日期已满足归档条件，目标还包括在花名册中形成员工；若预计入职日期尚未到达，系统可能先完成确认、待日期到达后再归档，不能把两种结果混为一个即时状态。

只适用于单条待入职确认；登记表审核、批量确认以及转正/调动/离职确认不属于本目标。

## 业务判断

读取[员工入职](../../domain/onboarding.md)和[待入职写入命令](../../commands/entry-write.md)：

1. 在 `pending` 列表中形成唯一候选，取得真实 `entryFormId`。
2. 回读详情，核对姓名、脱敏手机号、证件信息、部门、预计入职日期和当前状态。目标不一致、关键资料缺失或用户期望立即入职但日期仍在未来时，先澄清或编辑资料。
3. 核对关联登记表和入职审批：登记表尚未处于 `REJECTED/PASSED/ABANDON`，或审批尚未处于 `PASS/DENIED/ARCHIVE` 时，本次确认会放弃/作废对应流程。列出对象和当前状态，不能隐含处理。
4. 明确告诉用户本次是确认待入职；预计日期未到时可能不会立即出现在花名册。
5. 首次执行固定 `hcWeak=false`。

上述查询只用于形成待确认计划。真正提交时仍必须由 CLI 或后端重新校验 `entryFormId` 的最新状态、关联流程和确认条件，不能信任 Agent 对“已经可以确认”的判断。

## 执行与验证

1. 对唯一 `entryFormId` 执行 dry-run。dry-run 只验证本地输入并展示权限/确认调用计划。
2. 展示目标 ID、姓名、部门、预计入职日期、预期归档时点，以及将被放弃/作废的登记或审批流程；取得用户对目标和这些副作用的明确确认。
3. 使用同一 ID 和精确匹配的 `confirm-entry-form-id` 执行一次。
4. 强编制或资料校验失败立即停止。弱编制警告时先确认当前状态未被推进，再向用户解释警告；只有新的明确同意后才以 `hcWeak=true` 重试一次。
5. 回读 `entry +search --state joined`：唯一命中且核心身份一致，证明待入职已确认。
6. 如果预计日期已满足归档条件，再按可获得的 `staffId` 或唯一身份线索查询花名册；唯一员工记录且状态符合预期，才能报告已进入花名册。预计日期未到或花名册尚未返回时，报告“已确认，尚未验证归档”，不得宣称即时入职完成。

请求超时、网络中断或响应未知时，先执行第 5、6 步对账。确认状态和花名册结果仍无法确定时停止，不重复确认。
