# 审核通过单条入职登记表

## 目标定义

HR 对一条处于待确认或退回修改状态的入职登记表完成审核通过。目标状态是登记表审核成功，不是确认待入职进入花名册，也不是处理 Workflow 中的通用审批任务。

## 业务判断

读取[员工入职](../../domain/onboarding.md)和[入职登记命令](../../commands/registration-form.md)：

1. 使用姓名、脱敏手机号、流水号或登记 ID 在审核列表中形成唯一候选；只接受 `CONFIRM/RECHECK`。
2. 用同一个 `registrationId` 查询详情，核对姓名、脱敏手机号、登记状态、模板和关联 `entryInfoId/entryFormId`。
3. 详情中必填字段显示未填写时停止审核，并指出缺失项。
4. 用户要求核验附件，或模板/附件槽位声明必填时，使用关联 `entryInfoId` 查询附件；必填槽位缺少文件时停止。
5. 明确是否发送短信、邮件以及审核备注。通知默认均为 false，不能因页面或历史操作推断为 true。
6. 说明审核通过会把登记资料同步到已有待入职，或创建对应待入职，但不会直接进入花名册。

以上核对结果只是提交前计划；最终审核时必须由 CLI 或后端重新校验登记表的最新状态、关联对象和重复审核条件，不能把 Agent 的判断作为授权依据。

## 执行与验证

1. 对该 `registrationId`、关联 `entryId`、通知选择和备注执行 dry-run；首次固定 `hcWeak=false`。
2. 向用户展示姓名、脱敏手机号、登记表 ID、当前状态、资料/附件核对结果、通知选择、备注，以及将创建或更新对应待入职的影响，取得明确确认。
3. 使用完全一致的业务输入和精确匹配的 `confirm-registration-id` 执行一次。
4. `response.state=true` 是本次提交成功证据；出现编制警告时，先确认状态未推进，再解释警告。强编失败停止；弱编只在新的明确同意后重试一次。
5. 重新查询同一登记表。详情明确显示通过，或记录已从只含 `CONFIRM/RECHECK` 的审核列表移出并有可解释的成功响应，且可获得时关联 `entryFormId` 能定位到一致的待入职记录，才报告审核完成。

外部通知失败、响应超时或状态无法回读时，不把命令进程成功等同完整目标完成。先只读对账；仍未知时停止，不重复审核，以免重复通知或重复推进状态。
