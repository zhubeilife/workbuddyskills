# 创建单条待入职记录

## 目标定义

为一个明确人员创建一条待入职记录。目标状态是“待入职记录已创建并能被查询”，不是“人员已经进入花名册”。

只适用于单人创建；批量导入、新增花名册员工或创建招聘候选人不属于本目标。

## 业务判断

读取[员工入职](../../domain/onboarding.md)和[待入职写入命令](../../commands/entry-write.md)：

1. 收集姓名、手机号、预计入职日期和部门。部门名称必须解析为唯一真实 ID；零候选或多候选时停止并请用户选择。
2. 职位、员工类型、合同类型、证件类型、性别和自定义字段只有在用户提供可信 code 或当前安全契约能够唯一解析时才提交，不根据中文名称猜 code。
3. 检查用户目标确实是创建待入职，而不是立即确认入职或修改已有记录。
4. 首次请求固定 `hcWeak=false`。不得通过弱编参数预先绕过编制校验。

## 执行与验证

1. 在命令导航定位 `staff entry +create`，读取 Help 和过渡 Reference。
2. 先 dry-run。确认它只代表本地输入有效和调用计划可构造，不宣称远端校验通过。
3. 向用户展示：姓名、脱敏手机号、部门名称及 ID、预计入职日期、可选字段摘要、自定义字段数量，以及“将创建待入职而非直接进入花名册”。
4. 用户明确确认后，使用完全相同的载荷并传入与姓名精确一致的 `confirm-name` 执行一次。
5. 执行链中任一条件失败即停止：租户必填字段缺失、手机号或证件号重复、命中黑名单、部门权限失败、强编失败或其他业务错误。
6. 成功响应中若能得到 `entryFormId`，使用它回读详情；否则按姓名和脱敏手机号在 `pending` 列表中形成唯一候选。唯一命中且核心字段一致才报告创建成功。

弱编制警告出现时，先只读检查待入职记录是否已经创建；未创建且用户理解警告后再次明确同意，才允许同载荷 `hcWeak=true` 重试一次。

如果执行超时、连接中断或响应无法解释，状态为“结果未知”。先查询待入职和花名册；仍不能唯一确认时停止，不再次创建。
