# 安装与连接

使用客户端原生远程 MCP，不安装本地执行器或运行环境。安装操作由 Agent 在已有权限内执行，用户参与客户端必要的确认和浏览器登录授权。

## 包与配置来源

完整连接器包含 `connector-meta.json`、`mcp.json`、`icon.svg`、`skills/wimo-gen/`。技能目录包含 `SKILL.md`、`references/` 和 `agents/openai.yaml`，安装时全部保留。

核对 `connector-meta.json.source` 与 `mcp.json` 中唯一服务名称一致；服务启用、类型为 `streamableHttp`、URL 为不含凭据的 HTTPS 地址、timeout 为正数。Codex 依赖声明的服务名称、URL 必须与 `mcp.json` 一致，transport 为 `streamable_http`。声明采用 YAML 支持的 JSON 语法。缺少文件或配置不一致时停止安装，不猜地址、不从其他环境补值。

安装后的技能可能已与包根目录分离。后续使用客户端已注册的配置与技能依赖声明，不猜相对路径或拼接域名。

## Codex：原生技能依赖安装

1. 将 `skills/wimo-gen/` 完整安装到当前 Codex 支持的技能目录，保留 `agents/openai.yaml`。通过当前客户端技能发现入口确认技能及依赖已被识别。
2. 不提前执行 `codex mcp add`，也不先手动写入 MCP 配置。该独立进程不会刷新当前桌面会话；同名配置还会使依赖安装跳过。已有配置按下节处理。
3. 告知用户“技能文件已安装，连接待验证”，请其在**原会话下一条消息**发送 `$wimo-gen 帮我生成一张小猫图片`，也可换成自己的创作需求或 `$wimo-gen 检查连接`。必须保留 `$wimo-gen` 明确引用。当前轮里下载、阅读 SKILL.md 或助手输出这段文字，都不能替代下一轮用户触发。
4. Codex 在处理明确引用时执行原生依赖安装，按客户端策略请求安装确认、进行 OAuth 并刷新运行中的连接。用户完成登录授权后，确认当前会话能调用 Wimo 工具，执行 `creator_check_token`；成功后继续用户的创作需求。若本轮刚完成依赖注册／连接，但模型尚未获得工具，按下节的工具列表延迟处理，不把服务注册误判为失败。

此机制要求当前 Codex 支持并启用 `skill_mcp_dependency_install`；通过官方能力入口核实，不擅自改客户端安全策略。能力缺失、策略拒绝或授权失败时明确报告原因，不反复重试或声称下一条消息必定成功。Codex 依赖声明不支持 WorkBuddy 的 `timeout` 字段，按 Codex 原生超时策略执行，不伪造字段或声称两者超时一致。

### 当前会话没有工具但客户端已有注册

仅凭当前会话没有 `creator_*` 工具，不能判断连接器未安装或地址不一致。先通过当前 Codex 的官方 MCP 状态入口核对同名服务：

- 已存在 `wimo-gen`、状态启用、URL 为 `https://wimogen.com/mcp`：不要重新安装、删除或执行 `codex mcp add`。若状态显示未登录，使用官方 OAuth 登录入口（CLI 对应 `codex mcp login wimo-gen`），完成浏览器授权后新开会话或等待下一轮工具列表刷新。
- 不存在 `wimo-gen`，或已注册 URL 与包内声明不一致：停止创作，按上文重新安装完整包；不能靠 `creator_*` 名称猜测服务或改写地址。
- 已显示已登录但当前轮仍无工具：按下一节的工具列表延迟处理；不要重复登录或迁移配置。

状态入口只能用于诊断和官方登录，不能代替当前会话实际工具发现；只有当前会话能调用 `creator_check_token` 才能报告连接完成。

## Codex：已有安装诊断与迁移

先通过当前会话的工具搜索／发现入口查找 Wimo 工具；实际调用成功则复用，不迁移。独立诊断进程发现工具、`codex mcp list` 的 OAuth 状态或配置文件存在，都不能证明当前会话已加载。

### 刚安装后的工具列表延迟

本机 Codex 0.154.0-alpha.6.2 复现：依赖安装会刷新底层 MCP，但当前轮的模型工具列表可能在安装前已经建立。底层握手或调用成功，不代表本轮模型已经能调用；下一轮才会重新建立工具列表。

若本轮刚完成原生注册，模型工具列表却没有 `creator_*` 工具：

1. **先用 `codex mcp list` 确认服务状态**：检查 `wimo-gen` 是否已注册、URL 是否正确（`https://wimogen.com/mcp`）、OAuth 状态是否为已登录。这是轻量诊断，无需用户退出客户端或重启；不能仅凭模型工具列表缺失就认定未注册。
2. **服务正常但无工具 → 推荐新会话**：确认服务已注册且已登录后，告知用户”Codex 的工具列表是会话级缓存，当前会话在依赖安装前已建立工具列表，不会刷新。请**新建一个 Codex 会话**，发送 `$wimo-gen 检查连接`，新会话将完整加载工具。”附带诊断结论让用户放心（已注册、已登录、地址正确）。
3. **服务异常 → 按对应阶段处理**：未注册则按完整安装流程处理；未登录则通过 `codex mcp login wimo-gen` 完成授权。

如果不便新开会话，可尝试原会话回复一次 `$wimo-gen 继续` 等待下一轮工具刷新。成功则继续原需求；**一次后仍不可用，不再重试**，回到第 1 步确认服务状态并建议新会话。

不重复迁移、删除配置、重新登录或要求重启；不反复要求”再试一次”。

仅凭 `ALL_TOOLS` 或模型工具列表缺少 Wimo，不能认定 native runtime 返回 unknown MCP server。诊断须区分原生调用的真实错误、握手失败、认证失败和模型工具列表延迟；原生刷新／握手成功的证据与”未加载”推断冲突时，以该证据定位后续工具暴露环节。

如果原生客户端诊断明确返回 unknown MCP server／未注册（不是仅凭模型工具列表推断），且用户要求修复已有安装：

1. 使用官方配置查询入口核对同名配置、来源与包内服务。只迁移由旧安装流程写入、已启用、同名同地址的全局远程服务。不同地址、项目／插件／受管配置、自定义请求头、认证配置、工具过滤或其他未知定制，报告差异并停止迁移，不覆盖或丢弃设置。禁用状态不视为失效注册。
2. 若已有且允许使用的**当前客户端**连接支持 `config/mcpServer/reload`，使用它刷新，再验证当前会话工具。另起一个 App Server 的 reload 不能修复原桌面会话；不得猜 socket 或注入客户端。
3. 无当前客户端刷新入口时，先确认完整技能依赖已安装且客户端支持该机制。将需迁移的原配置原样备份到仅当前用户可读的本地文件，记录备份位置，不输出凭据。再次核对配置未变化，再由 Agent 使用官方 `codex mcp remove <包内服务名>` 移除这一条旧注册，保留其他配置及 OAuth 凭据；不执行 logout，不修改凭据存储。
4. 用户在原会话下一条消息明确使用 `$wimo-gen`，让原生机制重新注册、授权并加载。清理配置后不立即用 `mcp add` 写回，否则会重现问题。不能在同一轮里重复执行删除／安装循环。
5. 新链路失败时保留备份并报告具体阶段，不声称修复成功。用户要求恢复时，仅在目标配置仍未被他人修改的情况下恢复备份的那条配置，并说明恢复文件不等于当前会话已经刷新。

无失效证据、无迁移授权或无法安全备份时不删除配置。不能将这个修复过程变成每次创作的固定步骤。

## WorkBuddy 与其他客户端

- WorkBuddy：从原生连接器入口导入完整包，由客户端读取根目录配置并安装附带技能；已安装的连接器直接复用。不要将 Codex 专用依赖声明替代 WorkBuddy 的 `mcp.json`。
- WorkBuddy 当前会话没有 `creator_*` 工具时，先区分未授权、工具刷新延迟和明确的 unknown MCP server／unknown tool；未授权时停止依赖操作，认证后再重新发现工具。
- 自动 OAuth 失败时，只使用 WorkBuddy 生成的重新授权或手动授权链接。授权链接必须由客户端生成并保留 `client_id`、`redirect_uri`、`state`、`code_challenge` 与 PKCE verifier；技能不得自行拼接、复用旧链接或替换回调地址。
- WorkBuddy 未提供手动授权入口时，报告客户端 OAuth 能力缺失；不能把服务端 `/oauth/authorize` 裸地址当成可用连接链接。
- 其他 Agent：核实其官方技能安装、远程 MCP、OAuth 和运行时刷新机制，通过该客户端支持的入口完成安装。不能将 WorkBuddy JSON 或 Codex 元数据当作通用安装合同。不支持自动安装或刷新时说明确切限制和必要的用户操作。

## 授权、验收与停止条件

OAuth 由客户端发起，授权地址和认证发现来自服务端真实合同；缺失时报告错误，不猜接口。不复制旧执行器的 token、API Key 或凭据到客户端。

只有当前会话实际调用 `creator_check_token` 成功，才能报告连接完成；连接自检不创建项目、不生成、不展示项目列表或认证信息。若用户同时要求创作，自检成功后继续其任务，结果附上服务返回的“查看项目”链接。

区分“技能文件已安装”“等待下一条消息触发连接”“等待授权”“当前会话已验证”，不能以注册成功冒充可用。不默认要求退出客户端、重启或反复新建会话。工具、权限或登录缺失时停止依赖操作，不转到低层 HTTP、其他服务或本地程序。
