# 启动里程碑与首次使用引导

启动检查的目的是把用户召回 3Chat 空间并帮助完成首次配置。它记录当前空间是否曾经完成两个 onboarding 里程碑：

1. 至少成功发布过一次 3Chat Agent。
2. 至少成功连接过一次消息渠道。

这是完成后不回退的历史成就，不是当前运行状态检查。里程碑一旦完成，即使用户后来取消发布或删除 Agent、停用或断开渠道、撤销渠道授权，也仍然保持已完成。当前业务是否可执行，由实际调用的查询或发送工具自行校验。

## 哪些用户需要检查

启动检查不限于通过 OAuth 注册的新用户。用户可能早已注册 3Chat，但空间从未完成任何配置；当这个空间第一次连接到办公智能体(WorkBuddy)时，同样需要启动引导。

在以下情况调用 `get_3chat_workspace_readiness`：

- 打开插件的 onboarding 或启动配置流程；
- 当前对话首次提出 3Chat 启动或使用引导请求（例如“我如何通过 3Chat 进行客户运营？”），或者依赖 3Chat 数据或操作的请求，且尚无当前空间的成功检查结果；
- 最近一次成功检查为 `ACTION_REQUIRED`，用户在后续回合再次提出依赖 3Chat 的请求；
- 用户表示某个缺失步骤可能已经完成；
- 用户明确要求查看或刷新启动进度；
- 用户切换或重新连接了 3Chat 空间。

按照状态决定是否复用：

- 成功的 `READY` 结果可以在当前对话中复用，不得在普通客户查询、上下文查询或消息发送前重复检查。
- 展示配置入口后，`ACTION_REQUIRED` 只作为待刷新状态使用。用户在后续回合再次提出依赖 3Chat 数据或操作的请求时，应先重新检查，即使用户没有明确说已经完成配置。
- 同一个助手回合或同一条多工具业务链路中，最多执行一次启动检查。
- 用户明确表示暂不配置或跳过时，不再主动重复检查或展示引导，直到用户表示完成了某个步骤、主动要求刷新，或者重新连接空间。

重新检查后：

- 里程碑有进展时，只展示仍然缺失的步骤；
- 变为 `READY` 时，简短告知用户初始配置已经完成，然后继续处理当前请求；
- 缺失状态没有变化时，不重复完整产品介绍，只做一句简短提醒，并在可能的情况下继续处理原始请求。

这套复用规则依赖启动里程碑完成后不回退。

仅询问产品概念或功能、不使用 3Chat 数据的内容撰写，以及已经取得明确 `job_id` 的批量任务状态查询，不需要启动检查；询问如何开始使用 3Chat 开展客户运营属于启动引导请求。客户或对话查询为空，不能证明启动里程碑未完成。

## 返回状态含义

- 整体 `READY`：两个启动里程碑都至少完成过一次。
- 整体 `ACTION_REQUIRED`：一个或两个启动里程碑从未完成。
- Agent `COMPLETED`：至少成功发布过一次 Agent。
- Agent `NOT_COMPLETED`：从未记录过 Agent 发布成功。
- 渠道 `COMPLETED`：至少成功连接过一次消息渠道。
- 渠道 `NOT_COMPLETED`：从未记录过渠道连接成功。

`READY` 只表示首次配置成就已经完成，不代表 Agent 当前处于发布状态、渠道当前仍然连接或已授权、空间中一定存在业务数据，或者当前一定能够发送消息。

## 两个里程碑都未完成时

首次展示完整引导时，按以下顺序回答。可以结合用户目标调整措辞，但必须保留能力介绍、启动原因、三个操作步骤和持续优化建议。

### 1. 介绍能力与启动原因

说明 3Chat 帮助企业搭建专属 AI Agent，通过消息渠道接待客户、回答问题、理解需求，并协助推进购买、预约、留资或转人工。办公智能体(WorkBuddy)可以利用 3Chat 中的客户信息和沟通记录，帮助分析客户、准备跟进内容，并在用户确认后执行触达。

可参考以下表达说明为什么需要启动配置，并结合用户目标调整措辞：

“先让 **3Chat 搭建助手**了解你的业务，帮你生成并发布专属 Agent，再接入客户常用的消息渠道，Agent 就能开始接待客户。随着客户互动不断积累，你可以在 WorkBuddy 中了解客户需求、分析沟通情况，并准备更有针对性的跟进，让日常接待与客户运营衔接起来。下面三步就可以开始。”

对用户输出时，名称统一为 **3Chat 搭建助手**并加粗；不输出“自然衔接一下”“自然衔接到启动步骤”等写作指令，也不得据此声称未完成配置就无法使用所有查询工具。

### 2. 三步快速启动

使用有序列表依次输出下列步骤的文字说明；步骤 1、2 的说明后各紧接一个跳转组件，展示方式按 [guidance-widget.md](guidance-widget.md) 执行。步骤 3 没有工具返回的入口时只输出文字，不编造收件箱地址。

1. **创建并发布 Agent。** 展示 `BUILD_OR_PUBLISH_AGENT` 对应的入口。告诉用户与 **3Chat 搭建助手**对话，说明业务、产品、目标客户、销售流程和转人工规则，检查生成的 Agent 后完成发布。
2. **接入消息渠道。** 展示 `CONNECT_CHANNEL` 对应的入口。请用户选择客户常用的消息渠道，例如企业微信、小红书或抖音，并完成授权连接。
3. **体验真实接待。** 请用户在已经接入的渠道中发送一条消息，再到 3Chat 收件箱查看 Agent 的接待表现。

### 3. 持续优化

如果接待效果不理想，可以回到 **3Chat 搭建助手**，让它分析表现、模拟业务场景并测试回复，继续优化 Agent。

如果用户同时提出具体业务请求，先完整展示本次启动引导，再在可执行的范围内处理原始请求；不得把启动检查作为业务操作的准入条件。

## 只缺少一个里程碑时

- 只缺 Agent：仅展示创建并发布 Agent 的步骤及工具返回的 **3Chat 搭建助手**地址。
- 只缺渠道：仅展示接入消息渠道的步骤及工具返回的渠道地址。

完整启动引导、仅缺渠道的引导及后续提醒中，需要举例时均优先使用企业微信、小红书、抖音，不默认推荐 WhatsApp 等海外渠道。用户已经明确目标渠道时，使用用户指定的渠道，无需追加国内渠道名单。示例不表示当前空间已连接或一定支持这些渠道，实际可接入渠道及条件以 3Chat 渠道页面为准。

只缺一个里程碑时，不重复完整产品介绍，也不重复已经完成的步骤。

同样采用有序列表中的文字步骤加下方跳转组件，只渲染当前缺失步骤的入口；单步骤列表从 1 开始。

## Action 与 URL 规则

`data.actions[]` 中每一项都是一个 action 对象，包含 `code`、`label` 和 `url`。`BUILD_OR_PUBLISH_AGENT` 与 `CONNECT_CHANNEL` 是 `code` 字段的枚举值，不是 URL，也不是工具名。先按 `code` 选择 action，再直接使用同一个对象中的完整 `url`。不得在 Skill 中自行拼接、翻译、缩短或改写 URL。

## 检查失败

启动检查失败不代表里程碑未完成。遵循结构化错误和重试规则。问题仍无法解决时，说明当前无法验证启动进度。该工具不能替代客户查询、上下文查询或发送工具自身的实时业务校验。
