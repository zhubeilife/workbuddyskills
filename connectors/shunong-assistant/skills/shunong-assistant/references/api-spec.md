# 数字农人 CLI 调用契约

版本：0.1.2。配套 CLI：0.1.7，配套 Skill：0.1.2。

本参考定义 `sznr-cli` 的通用调用与失败处理。具体业务能力、参数、分页和分析口径由当前会话可用的业务技能及其单 API 文档维护；本连接器不另维护一张空业务能力表作为全平台能力判断。

## 能力来源与权限

业务请求先按 SKILL.md 的路由选择技能，再沿该技能参考索引读取目标 API。业务路径必须来自随业务技能发布的接口规范；没有对应规范时说明能力未支持，不从前端源码、历史接口或用户给出的地址猜测路径。

文档存在和登录成功均不代表服务端允许所有接口。Gateway 的实际方法、路径白名单与 NCP 企业 ACL 最终决定权限；收到 `WB_PATH_FORBIDDEN` 时停止该项查询，说明能力未开放或方法不匹配，不试探其他路径。

调用方遵守业务技能的读写边界。现有只读业务技能不因连接授权、用户确认或通用 POST 能力而获得写权限。

## 命令与参数

macOS/Linux 使用 `sznr-cli`，Windows 使用 `sznr-cli.cmd`。首次确认入口使用 `--version`，核对语法使用 `--help`；不把 CLI 当作具名 MCP 工具，也不调用不存在的 `whoami`、`set_current_enterprise` 或 `search`。

| 命令或参数 | 契约 |
| --- | --- |
| `--version` | 离线输出真实安装版本；不检查新版，不表示授权状态。 |
| `update-check` | 供 WorkBuddy 版本检测：npm `latest` 的稳定版更高时输出 `0.0.0` 触发受管升级，否则输出真实安装版本。查询超时 2.5 秒；离线或异常回退当前版本，退出码 `0`。不访问授权或 Gateway，不接受额外参数。 |
| `auth status` | 输出实时授权 JSON；退出码 `0` 且布尔 `loggedIn=true` 才确认已授权。 |
| `auth login` | 创建或复用授权，输出完整授权链接后退出；已有有效授权时可返回状态 JSON。用户完成授权后仍需 status 确认。 |
| `auth context` | 实时确认授权，再返回绑定企业的 `customerId` 与 `currentEnterprise`；不用于自行选择或切换企业。 |
| `auth logout` | 远端明确撤销或确认已失效后清理本地授权；失败时不能报告退出成功。 |
| `get <相对路径>` / `post <相对路径>` | 方法与路径来自业务文档；POST 也可用于只读查询，按业务影响判断。路径以单个 `/` 开头，不接受域名、片段或路径逃逸。 |
| `--query` | GET/POST 均可使用，必须为 JSON 对象；字段与必填性以单 API 文档为准。 |
| `--body` | 仅 POST 使用，必须为合法 JSON；字段与结构以单 API 文档为准。 |
| `--header` | 可重复的 `名称: 值`；仅传业务文档明确允许的 header，无声明时不传。认证、Cookie、企业身份及设备签名 header 不由调用方提供。 |
| `--debug` | 排查时输出脱敏请求/响应日志到 stderr，不改变正常 stdout 契约；不向用户展示凭证或无关业务明细。 |

企业参数只有业务文档要求时才传，并取自 `auth context` 的顶层 `customerId`，保留原始数字或字符串类型。不得以企业参数模拟或切换授权身份。

CLI 自动管理凭证、设备身份和签名，不要求模型读取私钥、token 或 Cookie。不支持文件上传、multipart、二进制下载、SSE 或其他流式响应，不跟随重定向。

## 结果解析与完整性

授权命令的状态输出为单行 JSON，例如：

```json
{"loggedIn":true,"state":"active","customerId":559}
```

`auth context` 在此基础上返回当前授权企业记录 `currentEnterprise`。授权链接是 login 的另一种输出，不能把链接或命令退出码 `0` 当作授权完成。

GET/POST 的 stdout 直接输出业务响应原文，不增加统一的 `ok/status/body` 外层。例如采用 `code/msg/data` 的接口可能返回：

```json
{"code":200,"msg":"操作成功","data":{"total":0,"list":[]}}
```

此例只说明响应形态；成功码、列表路径、分页字段及空结果判据必须读取目标 API 文档。先检查 CLI 退出码、stderr 诊断和响应中的稳定错误码，再判断业务成功；退出码 `0` 不保证正文中的业务状态成功。HTTP 非 2xx 仍可能输出正文，退出码为 `4`。

stdout 为空可能是空 HTTP 响应或根本未收到响应，不等于“没有业务记录”。只有接口业务成功且文档定义的数据集合为空，才能报告当前查询范围暂无记录。

GET/POST 业务响应不自动脱敏。按业务技能仅展示必要字段，账号等优先使用接口脱敏值，否则保留必要后四位或省略。完整性按接口总量、分页及截断规则判断；未取完分页、关联记录缺失或部分失败时披露覆盖范围，不以单页推断全量。

## 失败处理

先识别稳定错误码，再结合退出码；不要仅凭自由文本、界面连接标签或工具索引推断授权。

| 结果 | 动作 |
| --- | --- |
| `state=pending` / `WB_AUTH_PENDING` | 等待用户授权，由 WorkBuddy 默认状态检测继续确认；不重复创建授权或写轮询脚本。 |
| `state=denied` / `WB_AUTH_DENIED` | 停止授权；用户再次要求连接时才启动，不自动再次打开页面。 |
| `state=unauthenticated` / `reauth_required` | 按登录流程启动一次 login，完成后 status 确认并继续原任务。 |
| `WB_AUTH_EXPIRED`、`WB_AUTH_REVOKED`、`WB_INVALID_KEY`、`WB_TOKEN_RECOVERY_FAILED`、`WB_REAUTH_REQUIRED`、`WB_DEVICE_MISMATCH`、`WB_DEVICE_REVOKED` | 当前授权需要恢复，启动一次登录；稳定错误可能伴随退出码 `3` 或 `4`。恢复后可继续读请求，写请求先核实是否已生效，不能盲目重放。 |
| `WB_DEVICE_REQUIRED`、`WB_DEVICE_SIGNATURE_INVALID`、`WB_REQUEST_REPLAYED` | 设备签名或防重放校验失败；停止当前请求并报告具体错误，不修改 header 或盲目重试。 |
| `WB_CUSTOMER_FORBIDDEN` | 企业参数、对象归属或权限不符；只检查文档规定的参数与授权上下文，不自行换企业。用户明确要求切换时再 logout/login。 |
| `WB_PATH_FORBIDDEN` | 能力未开放或方法不符；停止该项查询并说明配置问题，不探索其他路径、不重新登录。 |
| `WB_RATE_LIMITED` | 按服务端提供的重试时间处理，不高频重试；没有重试时间时说明限流，不猜测。写操作先核实结果。 |
| 普通业务 `403` / `ENTERPRISE_LOOKUP_FAILED` | 权限或业务拒绝；解释具体原因，保留授权，不自动重新授权。企业详情查询失败不等于未登录。 |
| 退出码 `2` | 参数或配置错误；核对公开命令和接口规范，不覆盖受管 Gateway、授权地址或环境配置。 |
| 退出码 `3` | 结合状态及稳定错误码区分等待、拒绝、未登录和需要重新授权。 |
| 退出码 `4` | HTTP 请求被拒绝；按正文稳定错误码或业务信息分类，不一律当作登录失效。 |
| 退出码 `5` | 网络或超时，授权/请求结果未知；报告实际故障，保留授权，不自动重新登录或盲目重放写请求。 |
| 退出码 `6` / `INVALID_ENTERPRISE_CONTEXT` | 本地持久化、内部或协议异常；报告阶段并停止当前请求，不读取凭证排错或选择其他企业替代。 |

工具不存在、业务技能未加载、接口未支持、请求失败与成功空结果是不同情况。只有真正的授权拒绝或用户要求停止，才应用停止授权的规则；具名 MCP 工具缺失不能触发这条规则。
