# 话费补贴 / 话费报销规范（硬拦截）

> **命中「话费补贴标准审批流程」或「话费报销」时必须严格执行本文件，禁止按普通发票金额直接填单。**
> **材料不齐、岗位标准未确认、或无法拆出可报销账单金额时，禁止调用 `invoice.reim.flow.create.prepare/apply`。**

---

## 何时适用（满足任一即可）

| 判断依据 | 条件 |
|----------|------|
| 报销工作流名称 `workFlowName` | 含「话费补贴标准审批流程」或「话费报销」 |
| 事前申请名称 `requestname` / `requestnametitle` | 含「话费补贴」或「话费报销」 |
| 用户表述 | 明确说「话费报销」「话费补贴」 |

> 通讯类发票（`expenseType` 含「通讯」、销方为「中国移动 / 中国联通 / 中国电信」）若已匹配到上述流程，同样适用。

---

## 必须提供的材料

报销前必须同时具备：

1. **本人实名制当月手机账单截图**
2. **账单构成**（能区分基本套餐 / 通话流量 / 赠送套餐 / 家庭宽带等分项）

缺少任一项时：

1. **在 Step 5 之前必须暂停**
2. 明确提醒用户：「话费报销必须提供本人实名制当月手机账单截图及账单构成，否则无法继续报销。」
3. 用户补齐后再计算可报销金额
4. 用户拒绝或不提供 → **结束报销流程，禁止创建报销单**

涉及账单截图、图片或本地文件时，仍须先按 SKILL 提醒文件可能进入大模型上下文和 E10，等用户明确确认后再读取。

## 月度报销标准（上限）

| 岗位 | 月度上限 |
|------|----------|
| 各条线负责人、EBU销售及项目负责人 | 350 元 |
| 售前条线 | 200 元 |
| 销售条线 | 200 元 |
| 项目条线 | 200 元 |
| 外勤为主的客服岗位 | 100 元 |
| 外联业务为主的招聘岗位 | 100 元 |
| 外联服务为主的司机 | 100 元 |
| 专职内外服务的技术模块负责人、技术支持同仁或项目开发同仁 | 100 元 |
| 涉及外勤或支撑服务较多的其他岗位 | 100 元 |

岗位未确认时**禁止猜测**（尤其不要默认 350）。先问用户属于上表哪一类，确认后再算金额。

标准按**自然月**分别封顶：一次报销多个月份时，每个月单独套用上限，不能把多个月的额度合并。

---

## 可报销金额怎么算

1. 从账单构成中取出**当月手机账单合计**
2. **剔除不属于报销范畴的费用**（见下表），得到「可报销账单金额」
3. 与该岗位月度上限比较后支付：

| 条件 | 实报金额 |
|------|----------|
| 可报销账单金额 **低于** 报销标准 | **按实际可报销账单金额**支付 |
| 可报销账单金额 **超过** 标准上限 | **按上限标准**支付 |

公式：`实报金额 = min(可报销账单金额, 岗位月度上限)`

### 不属于报销范畴（必须剔除）

- 手机设备赠送套餐费用
- 家庭宽带套餐费用

账单里混有上述项目、但构成不清、无法拆出可报销金额时：暂停询问用户确认分项，不要把整张账单或整张发票金额直接当实报金额。

发票票面金额只作核对，**不是**话费报销的实报金额来源。发票金额可以高于实报金额；差额不得报销。

## 填单规则

| 字段 | 怎么填 |
|------|--------|
| 明细所有 `fieldType="Money"`（实报金额、报销金额、申请金额等） | 填本规范算出的**实报金额**，不要填发票原价 |
| 主表申请金额 / 人民币金额 | 各行实报金额之和 |
| 费用类型（科目） | 通讯科目 `"100502270000000010"`（`invoice.reim.row-info` 的 `subjectId` 已是通讯类时可直接用） |
| 费用说明 | 写清所属月份、可报销账单金额、岗位上限、实报金额，例如 `2026-08话费 账单280 上限200 实报200`（禁止 `*` 号） |

> 这是「金额一律填发票 `amount`」的**唯一覆盖规则**，只适用于本规范命中的话费报销。发票原始 `amount` 仍须原样保留在上下文中，不得改写发票数据本身。

向用户确认报销内容时，必须同时列出：

| 展示项 | 说明 |
|--------|------|
| 发票金额 | 票面原值，仅供核对 |
| 可报销账单金额 | 剔除赠送套餐、家庭宽带后 |
| 适用岗位标准 | 上表对应上限 |
| **实报金额** | `min(可报销账单金额, 上限)` |

## 事前申请查询：必须回溯 2~3 年

话费补贴的事前申请（「话费补贴标准审批流程」）可能在很早以前发起，审批通过后长期有效，每月按标准报销。

**默认 90 天回溯窗口不适用于话费报销。** 识别为话费报销后，`invoice.reim.requests.list` 的 `cusCreateDateStart` 必须至少往前推 **3 年**（1095 天）：

```
cusCreateDateStart = 最早发票 invoiceDate 往前推 1095 天（3 年）
cusCreateDateEnd   = 最晚发票 invoiceDate
```

示例（发票日期 2026-09-20）：

```json
{
  "pageNo": 1,
  "pageSize": 20,
  "requestname": "话费",
  "cusCreateDateStart": "2023-09-20",
  "cusCreateDateEnd": "2026-09-20"
}
```

> 如果 3 年内仍查不到，可继续问用户是否有更早的事前申请，但不要猜测或跳过。

### 匹配时间窗口同步放宽

默认匹配规则要求 `invoiceDate 在 [createTime, createTime + 90天]`。**话费报销不适用此窗口**，因为一次审批可覆盖数年的月度报销。

话费报销匹配时：
- **取消 90 天窗口限制**：只要 `invoiceDate >= createTime`（发票日期不早于事前申请日期）即可匹配
- 费用类型匹配仍然生效：`requestname` 含「话费」「通讯」即为匹配
- 金额校验仍然生效（按月度上限核算后的实报金额与事前申请预算比较）

---

## 操作步骤

1. 识别为话费补贴 / 话费报销后，**先不要创建报销单**
2. 确认本人实名制当月账单截图和账单构成；缺则暂停索要
3. 确认用户岗位对应的月度上限；未确认则暂停询问
4. 按账单构成剔除赠送套餐、家庭宽带，算出可报销账单金额
5. 按 `min(可报销账单金额, 上限)` 得到实报金额，展示给用户确认
6. 查询事前申请时使用 **3 年回溯**（`cusCreateDateStart` 往前推 1095 天），用 `requestname="话费"` 缩小范围
7. 匹配到事前申请后，用户确认，才允许进入 `invoice.reim.flow.create.prepare` → `.apply`
8. 材料不齐、岗位未确认、账单构成无法拆分、或用户拒绝 → **结束流程，禁止创建**
